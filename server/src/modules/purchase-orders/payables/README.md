# 采购应付款

## 业务边界

- 审核采购订单时，在同一事务中生成定金、尾款两条应付。零金额阶段仍保留，展示为“无需付款”。
- 销售关联采购在审核时固定销售出单人 `issuerUserId`；备货采购固定为公司账户。付款操作者不改变资金归属。
- 首版按阶段一次付清剩余金额，客户端只能提交版本、付款方式、备注与幂等键，不能指定付款金额、账户或资金比例。
- 本次迁移不回填历史已审核订单，不补扣历史实际付款。没有应付的旧单不能继续通过旧付款接口绕过新流程。

## 事务与资金

先锁采购单，再读取阶段应付和实际付款。付款、应付版本、采购状态、资金批次与审计共用一个事务。

| 操作 | 来源 | consumer | 资金类型 |
| --- | --- | --- | --- |
| 销售关联采购付款 | `PURCHASE_PAYMENT` | `PURCHASE_PAYMENT.PAY` | `PURCHASE_PAYMENT` |
| 备货付款 | `PURCHASE_PAYMENT` | `PURCHASE_PAYMENT.STOCK_PAY` | `PURCHASE_PAYMENT` |
| 作废实际付款 | `PURCHASE_PAYMENT` | `PURCHASE_PAYMENT.VOID` | 原批次类型 |

备货沿用当前已发布的分摊规则，以有效用户比例 0%、公司比例 100% 计算，只产生公司分录；不修改业务配置或任何用户账户比例。配置不兼容时拒绝付款。

实际付款使用独立 UUID 作为资金业务身份。请求幂等键按操作者隔离，并保存请求指纹；相同请求重放不重复记账。作废按原批次全额反向入账，恢复应付余额；再次付款必须使用新的请求键和版本。普通资金冲账入口不能绕过采购作废流程。

数据库延迟约束核对阶段金额、归属、实际付款与资金批次，以及作废前后的分录。不可变字段不能事后补写。历史无资金批次的付款作废仅恢复历史采购付款统计，不创建资金流水。

## 查询与金额

- `GET /purchase-order-payables` 按采购订单分页，`total` 是采购单组数，每组始终返回完整定金与尾款。
- `POST /purchase-order-payables/:id/pay` 使用 `Idempotency-Key` 和 `expectedVersion`；成功返回所在采购单分组。
- 实际采购金额、计算和接口返回统一两位。产品档案及旧参考成本、修订记录、归档图片快照保留原精度。
- 精度迁移遇到非零第三、四位时整体回滚，需先核对来源，不能静默改写历史金额。

变更入口的权限为 `purchase-orders:payment`。付款方式写入前核对 `payment.method` 的有效字典值。
