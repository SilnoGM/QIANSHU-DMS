| 类别 | 精确范围 |
| --- | --- |

| 既有业务表 | `SalesOrderPayment` 新增 origin、入账/冲正批次关联及汇率快照共 7 个字段，增加所需反向关系与约束；存量 LEGACY 标记，不补造入账 |

## 3. 依赖与执行约定

主依赖：T1 → T2 → T3 → T4 → T5 → T6 → T7 → T8。

- T3 的资金代码与 T4 的申请服务可在 T2 稳定后分别推进，但 schema/migration、共用资金服务、OpenAPI 只由一个负责人集成；不能同时生成互相覆盖的迁移和快照。

- 局部验证通过后再执行必要集成和全链路验收；检查失败先定位修复，不以失败结果进入交付。
- 在本分支按完整逻辑变更小步本地提交；精确暂存，不混入用户修改，不提交 .env、密钥、日志、生成目录或测试附件。
- 未完成整条能力前，不把分阶段提交当作可部署版本；尤其不能把阻断旧收款入口与尚未可用的新入口分开上线。
- 每项完成后记录命令、结果和提交；最终文档区分实测、未验证与阻塞项。

## 4. 实施任务

### T1 — 接口与迁移测试基线

- [x] 核对工作区/分支、适用 AGENTS、Server/Web 现行脚本；确认隔离测试库不指向业务库。
- [x] 将设计的请求、响应、expectedContext、状态转换及错误码固化为测试期望；定义申请指纹规范和重复审核/作废的相同操作判定。
- [x] 建立含历史正式收款、用户/公司账户、TWD/MYR 汇率、ORDER_SETTLEMENT 规则和凭证的隔离 fixture；全部使用合成数据。
- [x] 建立失败场景：提交不应直接生效、缺审核权限不能通过、资金写入失败必须回滚销售状态。

验收：失败测试命中现有缺失行为或约束，而非环境/凭据故障；现行资金和销售定向基线结果已记录。

### T2 — Schema、迁移、媒体引用与权限基础

- [x] 新增申请表、审核状态；扩展正式收款 7 个字段、关联、索引和唯一约束。
- [x] 明确 LEGACY 回填与新 REVIEWED 创建约束；扩展不可变守卫和事务末一致性校验，禁止新记录借 LEGACY 绕过审核。
- [x] 以追加 migration 初始化受限业务来源、三个财务权限及必要审计事件，不改已有 migration。
- [x] 新增申请媒体引用与生命周期检查；待审核、驳回、通过和受权重提均保留证据。
- [x] 验证同订单关系、申请/正式收款/批次关联一致、审核和作废形状约束、凭证数量/引用规则。

验收：隔离空库和存量 fixture 库均可迁移、重复部署无待执行项；历史收款金额及账户余额不变；伪造关联/不完整新收款被数据库拒绝。

### T3 — 换汇与资金事务内能力

- [x] 实现定点换汇：原币四位除以十二位汇率，HALF_UP 到 CNY 两位；验证零额舍入、溢出和分录守恒。
- [x] 扩展受控资金抽象端口和模块导出，复用现有入账/冲正核心；保留原独立事务调用方行为。
- [x] 审核预览与真实入账共用计算规则；规则和比例必须在资金引擎锁内比较 expectedContext，再用同一快照计算。
- [x] 业务来源、类型和 consumer 仅由服务端构造；操作者与账户归属分别记录，资金账户缺失不自动开户。
- [x] 全额冲正只读取原实际分录，支持 0%/100% 比例与负余额；封堵通用管理员冲正收款关联批次的入口。
- [x] 定义外层事务错误传播及回滚后的幂等恢复；不在失效事务内继续查询恢复。

验收：资金自身既有入账/管理员调整/其他批次冲正回归通过；规则或比例在预览后变更导致明确冲突；不同账户锁序稳定；原汇率/比例改变不影响冲正金额。

### T4 — 收款申请、金额预占与查询

- [x] 提交服务从订单冻结币种、开单人归属，验证五种类型、正额、时间、付款字典及凭证；在一个事务内激活媒体、创建申请及审计。
- [x] 实现同键同内容重放、不同内容冲突；未知结果沿原键恢复，不允许自动换键重提。
- [x] 实现待审金额汇总；订单锁内限制已确认加待审核不超应收，覆盖减价、产品修改造成总额下降及取消入口。
- [x] 实现驳回及关联重提，不改原申请内容、不丢凭证、不将技术失败自动驳回。
- [x] 实现财务分页筛选/状态计数、申请详情、订单内摘要及两条受权凭证读取路径；金额按币种分开。

验收：提交/驳回均不改变正式收款及资金；并发申请不超额；跨订单凭证访问和无关申请复用凭证被拒绝；待审记录不被媒体清理误删。

### T5 — 审核入账、作废冲正与旧入口切换

- [x] 通过服务按统一锁序重读订单/申请/凭证/汇率依赖，校验版本与可收金额。
- [x] 在同一事务内生成正式收款及凭证、资金入账、汇率快照、批次关联、申请通过、订单状态和审计。
- [x] 作废服务改用独立纠错权限、原因和 expectedOrderVersion；新收款全额冲正与作废同步，历史收款不扣资金。
- [x] 保留 COMPLETED 订单的既有限制；申请通过后的正式收款作废不改原审核结论。
- [x] 旧 POST payments 关闭直接生效能力；对未知结果/重复通过和作废恢复既有成功结果，冲突不覆盖原审核人/原因。
- [x] 逐点注入凭证、资金、订单、审计及最终约束失败，证明没有半笔业务。

验收：双审核、审核与驳回、作废与通用冲正并发均只产生允许的一次结果；审计故障回滚余额/订单；余额不足时冲正成功为负数；无绕过审核的旧写路径。

### T7 — 销售弹窗及财务工作台

- [x] 销售弹窗改为提交申请，保留原字段和单份凭证；成功提示待审核，超时恢复保留原提交快照及幂等键。

- [x] 替换销售收款占位页：待审核/已通过/已驳回、服务端分页筛选与计数、订单和归属人追溯。
- [x] 实现受权详情、凭证预览、当前汇率与预计 CNY/分账核对、通过和必填原因驳回；依赖冲突后重新读取并人工确认。
- [x] 已通过详情展示实际入账快照；作废显示原反向分录、必填原因及允许负余额说明，LEGACY 单独标识。

验收：销售→财务→订单与账户结果一致；无权限/空数据/错误/加载状态可继续操作；亮暗色、390px、键盘与焦点回归通过。
