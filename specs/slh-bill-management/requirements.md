# 顺联航账单管理 需求规格

## 1. 文档状态

- 状态：已确认
- 确认日期：2026-09-26
- 目标模块：`server/src/modules/slh-bills/`
- 目标页面：`/qs-finance/bill-reconciliation/slh-bill-management`
- 依赖规格：`specs/numbering-management`（编号派发）、`specs/system-currency-management`（汇率读取）

## 2. 目标

把顺联航（台湾专线海运货代）每月发来的 Excel 对账单**结构化接收、留痕并供查阅**，作为后续「与我方数据比对判定」的唯一外部事实来源。

本阶段只承担「接收、结构化、留痕、查阅」；比对判定属于兄弟页面 `/qs-finance/bill-reconciliation/slh-bill-reconciliation`（权限 `slh-bills:reconcile`），不在本规格范围内。

## 3. 业务边界

- 只接收顺联航出的对账单，不接收其他货代格式。
- 账单是外部单据，**只被引用，不写回我方装柜明细**。
- 表头区（标题、须知、银行收款账号）不结构化，只用于定位表头行。
- 不做付款、入账、汇率维护；不做单据导出。
- 不做「从账单自动修改我方数据」的任何路径。
- DMS 内部材积口径为 `÷28317`，账单口径为 `÷28316`，本阶段忠于账单口径，口径差留待比对阶段显式处理。

## 4. 需求与验收标准

### R1 上传与解析账单工作簿

**User Story：** 作为财务，我可以上传顺联航对账单 xlsx，系统识别出账单结构，以便我不必手工抄录。

#### Acceptance Criteria

1. 支持上传 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，单文件不超过 50 MiB。
2. 解析时按关键词定位表头行（同时含「装柜日期」「柜号」「嘜頭」的行），不依赖固定行号；表头行之前的标题、须知与银行账号内容不进入任何字段。
3. 表头行之后、含「小计」的行之前的所有非空行视为明细行。
4. 列映射按别名匹配，且同时支持繁简写法（`入倉單號`/`入仓单号`、`嘜頭`/`唛头`）。
5. 未识别的列不得被静默丢弃：其单元格原值必须进入该行的来源留痕数据。
6. 缺列或表头无法定位时，返回可读的解析失败原因，不产生半成品账单。

### R2 材积复算与计价方式推导

**User Story：** 作为财务，我希望系统自己把材积和运费算一遍，这样我能发现对方算错的行。

#### Acceptance Criteria

1. 材积按账单口径复算：`长 × 宽 × 高 ÷ 28316 × 箱数`。
2. 计价方式由单价推导：单价大于 10 记为 `VOLUME`，否则记为 `WEIGHT`；单价为空的明细行计价方式为空、运费按 0 记录且不报错。
3. 材积记录值按计价方式取值：`WEIGHT` 行四舍五入到 2 位小数，`VOLUME` 行向上取整。
4. 运费复算：`单价 × (WEIGHT 行取重量、VOLUME 行取材积记录值)`，结果四舍五入到 2 位小数。
5. 合计应付复算：`运费 + 代收手续费 + 附加费`。
6. 复算值与账单缓存值不一致的行必须逐行列出差异，但不阻断入库。

### R3 台币金额与汇率

**User Story：** 作为财务，我要知道这张账单的台币金额和它用的汇率，以便后续核对我方回款。

#### Acceptance Criteria

1. 「合计应付台币NTD」按**不折算**记录：`代收货款 − NTD 杂费合计`。
2. 账单公式自带除数时（如 `=(V58-W58)/4.8`），除数即为账单自报汇率，汇率来源记为 `EMBEDDED`。
3. 账单公式不带除数时，在同一事务内读取系统当前汇率并冻结，汇率来源记为 `SYSTEM`。
4. 公式不带除数时允许用户手填汇率覆盖，来源记为 `MANUAL`；公式自带除数时不开放手填。
5. 汇率存储精度为 `Decimal(30,12)`，与该币种汇率主数据和既有单据冻结汇率口径一致。
6. 汇率不可用时返回明确的业务错误，不静默兜底。

### R4 费用明细拆解

**User Story：** 作为财务，我想按费别看到每一笔杂费，而不是只看一个合计数。

#### Acceptance Criteria

1. 备注中的费别被拆解为费用明细行，覆盖：重货费、偏远费、卸货费、派送费、二次派送、转派、仓储费、等待费、超尺费、验机费、堆高机、最低消费、其他。
2. 费别匹配同时支持繁简与多种写法（`寄仓费`/`寄倉費`、`等待費`/`等待费`）。
3. 未识别出的费用内容进入「其他」，不丢弃原文。
4. 每条明细行的费用明细合计必须等于该行对应的聚合列（RMB 附加费或 NTD 杂费），不满足时列为差异。
5. 币种按费用所在列判定：附加费列为人民币，NTD 杂费列为新台币。

### R5 账单编号与重复导入

**User Story：** 作为财务，我需要每张账单有唯一编号，并能发现重复导入。

#### Acceptance Criteria

1. 账单编号由既有编号规则 `CTN_BILL_NO` 派发，消费域为 `SLH_BILL.CREATE`，形态为 `CBILL/<派发月>-<流水>`。
2. 编号规则缺失或未启用时返回明确业务错误，编号不由应用自行拼装。
3. 编号必须来自编号派发台账：数据库层校验编号、派发记录、规则与用途的一致性。
4. 编号中的月份是派发月，流水周期由规则的 `resetPolicy` 决定（实测为按年重置，年内上限 99 张），账单所属期间由独立字段表达，三者不互相推导。
5. 相同「账单期间 + 柜号集合」再次导入时给出重复提示，允许用户确认后继续。
6. 同一幂等键重复提交返回同一张账单。

### R6 账单查阅

**User Story：** 作为财务，我能在列表里找到账单，并看到它每一条明细。

#### Acceptance Criteria

1. 列表支持按账单期间、柜号、金额区间、关键词检索与分页。
2. 列表展示账单编号、期间、柜号数、明细行数、合计应付人民币、代收货款台币、汇率来源。
3. 详情页展示账单头汇总、账单自报值与自算值的差异、以及分页的明细行。
4. 详情可下载原始 Excel 文件。
5. 详情只能通过 `slh-bills:read` 权限访问；导入入口需要 `slh-bills:create`。

### R7 权限

**User Story：** 作为系统管理员，我能分别控制「查看账单」与「导入账单」。

#### Acceptance Criteria

1. 新增权限码 `slh-bills:create`，默认仅授予系统管理员。
2. 查看类接口要求 `slh-bills:read`；导入与取代类接口要求 `slh-bills:create`。
3. 权限目录常量、设计文档与既有 e2e 权限清单断言同步更新。

## 5. 非验收范围

- 与我方装柜明细的逐行比对、差异处置与确认锁定。
- 账单修订版差异对比。
- 付款与入账。
- 按费别的统计报表与导出。
