## 本期范围摘要

- 已建立 `ContainerBatch`、`ContainerLoadingItem`、`OceanFreightBill`、`OceanFreightBillLine`、`OceanFreightBillCharge` 五张业务表的 Schema 与迁移。
- 装柜明细关联现有货件 `PurchaseOrderPart`；一个货件可有多个包装明细，首版不可跨柜拆分。
- 海运账单可包含多个柜次的货物及追加费用；每条账单明细独立核对并计算金额。
- 货件唛头与海运唛头独立保存；同义字段统一命名、类型与单位，装柜数据和账单数据各自保留快照。
- 材积按单件长宽高除以 `28317`，再乘包装件数；整行材积向上取整后得到计费材数。
- 计算台币扣费后的人民币返款及扣除人民币费用后的净返款，允许正数、零和负数。
- **暂不接入资金引擎，不新增 `OceanFreightLineSettlement`，不改变账户余额或资金流水。** 后续另行实现“生成对账单 → 再核对对账单 → 账户入账”。

## 现有实现与方案的界线

[柜次页面](../../web/apps/qsmds-arco/src/views/workbenches/containers/index.vue)已接入列表、真实创建与独立详情，说明文案保留“统一管理海运货柜柜次和海快发出情况”。以下路由已经建立，其中柜次详情接入数据，海运账单两页仍为骨架：

| 页面 | 路径 | 侧边栏 |
| --- | --- | --- |
| 千树采运工作台 → 柜次详情 | `/qs-purchase-transport/containers/:id` | 隐藏，保持柜次管理高亮 |
| 千树财务工作台 → 账单对账 → 顺联航海运账单 | `/qs-finance/bill-reconciliation/shunlianhang-ocean-bills` | 显示 |
| 千树财务工作台 → 账单对账 → 顺联航海运账单详情 | `/qs-finance/bill-reconciliation/shunlianhang-ocean-bills/:id` | 隐藏，保持账单列表高亮 |

柜次列表及详情现使用 `container-batches:read`，新增/编辑分别检查 `create`/`update`；账单分组及两页仍为骨架，使用 `purchase-orders:payment`。基础接口见[阶段 1 实施记录](./phase-1.md)，精确计算与事务重算见[阶段 2 实施记录](./phase-2.md)，柜次及明细维护、来源文件和当前验收状态见[阶段 3 实施记录](./phase-3.md)。Excel 解析导入、账单完整维护、对账流程和海快业务尚未实现。

项目通用规范继续遵循[开发工作流](../../docs/全局文档/开发工作流.md)、[UI 设计规范](../../docs/前端文档/UI设计规范.md)、[接口契约规范](../../docs/后端文档/接口契约规范.md)及[数据库迁移规范](../../docs/后端文档/数据库迁移规范.md)。
