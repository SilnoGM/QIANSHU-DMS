# 运营海运柜次接入记录

日期：2026-09-20。范围：将已验收的 `QsOceanContainerList` 接入运营真实页面，并支持运营修改本人装柜明细的收件信息及代收款。阶段 4 海运账单与费用继续暂缓，不接入资金引擎。

## 展示与归属

- 入口：千树运营工作台 → 仓储运输 → 海运柜次，路由 `/qs-operations/warehouse-transport/ocean-containers`。
- 卡片显示柜次名称、编号、装柜日期、仓库、整柜明细数、我的明细数、总毛重与总材积；整柜概览不因销售归属改变。
- 支持按柜次名称、编号搜索，默认每页 10 个柜次；多个卡片可同时展开，每柜个人明细独立分页，每页 20 条。
- 个人归属唯一依据：装柜明细 → 货件 → 采购订单 → 销售订单 → `issuerUserId` 等于当前登录用户。管理员在运营页也遵守此规则。
- 未匹配货件、独立备货、缺少销售来源及他人销售订单的行不属于本人明细；无本人明细的柜次仍展示整柜概览，展开显示专用空状态。
- 整柜毛重或材积任一行缺失时，对应汇总显示待完善，不以部分合计代替完整合计；空柜显示零。
- 明细每行显示海运唛头、品名、货件唛头、来源、收件人、代收货款；来源显示销售订单编号、采购订单编号，并按各自读取权限打开现有订单抽屉。海运唛头与代收金额加粗，海运唛头支持复制，查看明细打开 `QsGenericDrawer`。
- 抽屉显示入仓参考、完整收件信息、包装件数、重量尺寸、材积、代收货款与备注。重量尺寸整数、材积两位，缺失代收显示占位。

## 只读接口与权限

页面与接口使用已有 `sales-orders:read`，不要求授予完整的柜次管理权限。

| 接口 | 作用 |
| --- | --- |
| `GET /api/operations/ocean-containers` | 整柜概览、整柜统计及当前登录人的个人明细计数 |
| `GET /api/operations/ocean-containers/:id/items` | 本柜个人明细分页 |
| `GET /api/operations/ocean-containers/:id/items/:itemId` | 重新校验归属后返回个人明细详情 |

- 归属在数据库查询中限制，不接受前端传入用户 ID。详情不存在、跨柜或不属于本人统一返回 404。
- DTO 使用字段白名单，不返回来源文件、来源快照、其他销售人员客户资料或管理操作字段。
- 列表与两类统计使用同一数据库快照，避免并发归属变更造成计数矛盾。个人分页与计数同样使用一致快照。
- 响应标记为 `private, no-store`；页面离开、搜索变化、登录身份变化或撤权时取消请求并清除个人缓存，迟到响应不得恢复旧内容。
- 每次打开抽屉重新请求详情。个人总数变化时清除该柜旧分页，更新计数并关闭其旧详情；总数为零直接清空，页数缩减重新请求有效页。
- 来源单号使用运营明细返回的 `salesOrderId / salesOrderNo` 与 `purchaseOrderId / purchaseOrderNo`。点击和重试先重新校验个人明细，再以新返回的订单 ID 调用原有订单详情接口；销售需要 `sales-orders:read`，采购需要 `purchase-orders:read`，无权限仅展示编号。关闭、切换、失活或撤权会取消两段读取。
- 三个接口不修改柜次、货件状态、审计记录或资金数据。

## 明细修改与发送确认

操作列增加“改信息”“改代收”。沿用本人销售归属范围，另要求 `sales-orders:update`，不能修改其他销售的明细，也不向运营开放采运管理员的全部编辑字段。

1. **编辑**：重新读取当前明细与版本；改信息只含客户姓名、客户电话、收件地址、备注；改代收只含 TWD 代收金额（非负、两位小数，空值表示未设置）。没有实际变化不能进入下一步。
2. **对比与复制**：显示修改前后，提示“请点击复制修改，发送到顺联航群”。复制文本包含柜次、海运唛头及修改内容；实际复制成功后才进入第三步。发送群消息由用户完成。
3. **确认已发送**：询问“确定已发送到顺联航群了吗？”。“未发送，取消更改”关闭弹窗，不修改数据库；“已发送，确认更改”携带 `notificationConfirmed: true` 提交修改。无需上传截图。
4. **成功与撤销**：显示成功更改，“关闭”按钮倒数 5 秒后自动关闭。关闭前可点“撤销更改”：改信息恢复原收件信息，改代收恢复原金额。撤销时停止倒计时；失败保持弹窗供用户处理，成功恢复后关闭。

- 返回编辑使原复制确认失效，产生新的修改请求标识，重新走对比与发送确认步骤。
- 新增 `ContainerLoadingItemChange` 留存修改前后、原版本、新版本、操作人和时间，与明细更新同事务保存。修改记录不可改写或删除，撤销追加一条逆向记录并关联原变更。
- 使用明细版本避免覆盖并发更新；已有账单引用的明细继续冻结。版本冲突需要重新加载和确认。
- 撤销只能由原操作者执行，只允许当前版本仍为本次修改后的版本，且同一修改只能撤销一次；后续已有更新时拒绝覆盖。5 秒是前端撤销入口展示时间，服务端以归属、权限、版本与撤销记录保护为准。
- 网络异常导致保存或撤销结果未知时，保留原始提交内容和幂等键，允许原样重试；服务端重放不能产生重复变更。
- 只修改装柜明细，不同步覆盖销售订单客户资料、不修改货件状态、不产生资金操作。数据库记录“用户确认已发送”，不能据此宣称系统验证了外部群消息。

| 新增接口 | 作用 |
| --- | --- |
| `POST /api/operations/ocean-containers/:id/items/:itemId/changes` | 检查明确发送确认及版本后保存，返回最新明细与变更 ID |
| `POST /api/operations/ocean-containers/:id/items/:itemId/changes/:changeId/undo` | 校验原操作者及版本，追加逆向记录并恢复本次修改前的字段 |
