### 费用与返款

使用 `BigInt` 定点整数和有理数运算，不经 JavaScript 浮点金额运算；统一 `ROUND_HALF_UP`，货币结果两位小数。

```text
WEIGHT = round(整行毛重 × 单价, 2)
VOLUME = round(计费材数 × 单价, 2)
FIXED  = 校验后的固定金额

有效费用 = NORMAL/SUPPLEMENT 的正金额，或 DEDUCTION 的负金额
单行返款 CNY = round((本次有效代收 TWD − 台币有效费用) / twdPerCny, 2)
单行净返款 CNY = 单行返款 CNY − 人民币有效费用
整单金额 = 对应逐条金额之和
舍入差额 = 逐条返款之和 − round((整单有效代收 − 整单台币费用) / twdPerCny, 2)
```

- 汇率方向为 `1 CNY = twdPerCny TWD`，必须大于零。费用分币种汇总，净返款允许为负。
- 计重/计材费用以数量和单价为计算依据；重算忽略旧的派生金额和数量。固定金额使用保存金额。
- 减免使用非负金额和 `DEDUCTION` 性质，不接受负输入重复反转；费用来源差异使用“有效有符号费用 − 原始来源金额”。
- API 输出固定小数格式：金额两位、毛重/尺寸三位、材积八位、汇率十二位，不输出科学计数法。
- 同一合计字段只要有一条未知，该字段合计就是 `null`，不把部分数额当完整账单合计。

### 调整行代收来源

账单行创建新增可选 `codSourceTreatment`：

| 值 | 含义 | 本次有效代收 |
| --- | --- | --- |
| `CURRENT` | 明确属于本次新增代收 | 输入金额 |
| `HISTORICAL_REFERENCE` | 调整行上的历史代收参考 | `0.00`，原金额保留 |
| `UNRESOLVED` | 含义尚未确认 | `null`，暂不能形成完整返款 |

正常行缺省按本次代收处理；调整行非零代收缺省为待确认，显式输入零可明确为本次零代收。缺失金额始终保留未知，不能通过选择来源类型将缺值变成零。正常行不能标记为历史参考或待确认。

来源判定与原金额保存在已有 `sourceData.oceanFreightCod` 服务端快照中，版本为 `1`，未新增列。响应增加 `reportedCodAmountTwd` 并返回来源类型，`codAmountTwd` 表示有效值。阶段 1 历史调整行缺少来源判断时采取保守规则，不将非零历史代收直接纳入本次返款。

## 2. 接入与事务约束

- 装柜明细创建开放 `grossWeightKg`、`lengthCm`、`widthCm`、`heightCm`、`reportedVolumeCai`，服务端计算后随明细事务保存；响应增加对应原始数据、计算值及差异。
- 账单行创建后，在同一事务重算费用、各行金额与账单总额，再返回落库后的结果。
- 重算固定按照账单、明细、费用的顺序加锁；任何计算或审计失败，整次创建与计算一起回滚。
- 包含已核对明细时拒绝重算；后续重开对账流程必须先明确解除冻结。
- 原值、来源快照不被重算覆盖；相同结果不重复增加明细版本，账单版本由外层业务命令统一维护。
- 保留基础创建请求的幂等指纹；旧请求未提供新字段时仍能重放，重放不会再派号、写审计或重复重算。
- 新计算错误统一为 422：`OCEAN_CALCULATION_INVALID`、`OCEAN_CALCULATION_OVERFLOW`。

## 3. 当前边界与后续接入

本阶段没有费用维护 API 或完整页面。纯计算层接受完整费用集合；持久化重算中，空费用集合表示“尚未录入”，保持费用和返款为 `null`。明确零费用可通过一条固定金额为零的费用表示。阶段 4 需把费用录入完整性与界面交互一起落实，不能将空集合擅自解释为免费。

费用重算已作为内部事务能力实现；本轮真实数据库测试通过合法夹具写入费用验证，未增加对外费用录入入口。后续费用、汇率、关联编辑命令须统一调用该能力并维护版本、审计和冻结规则。

页面仍为原有骨架；Excel 导入、匹配、确认/重开核对、正式对账单和账户结算继续按后续阶段推进。本阶段没有执行真实返款、确认真实账单或操作业务账户。
