# 广告账户充值需求规格

## 1. 文档状态

- 状态：需求与方案已确认，已实施（本地分支 `feat/advertising-recharge`）
- 编写日期：2026-11-02
- 关联文档：
  - [技术设计](./design.md)
  - [后端设计](./backend.md)
  - [前端设计](./frontend.md)
  - [实施任务](./tasks.md)
- 影响域：运营工作台（新增「网络与广告」分组）、财务工作台「实收实付」、资金账户与资金流水、编号、媒体、权限、审计

## 2. 背景与目标

广告投放费用由公司账户与投放人个人账户按分成比例共同承担，但当前系统没有采集广告账户充值信息的入口，财务只能在线下收款、线下分摊，资金流水缺少业务来源。

目标是提供一条完整链路：**运营提交广告账户充值申请 → 复制申请信息给财务 → 财务登记实付金额与付款截图 → 系统按 `ADVERTISING_FEE` 已发布规则把实付金额分摊到申请人个人账户与公司账户**，并保留驳回、撤回、作废冲正等纠错路径。

## 3. 范围

### 3.1 本期包含

- 运营工作台新增「网络与广告」分组：静态节点（占位页）、广告充值（真实链路）。
- 广告充值申请：新增（两步弹窗：填写 → 复制信息）、本人列表、只读详情、待付款撤回。
- 财务工作台「实收实付」新增广告充值：全部申请列表、隐藏详情页、登记付款金额（CNY）与付款截图、驳回、已付款作废并冲正。
- 资金：新增业务来源 `ADVERTISING_RECHARGE`，复用既有启用类型 `ADVERTISING_FEE`。
- 编号：`AD/YYYYMMDD-####`，按年重置。
- 权限：五条可委派权限，运营与财务按职责拆分。

### 3.2 本期不包含

- 静态节点的实际功能（仅占位）。
- 充值金额与付款金额之间的汇率换算或金额校验；付款金额由财务按实际支付手填。
- 申请单原地改金额重付（作废为终态，需重新提交申请）。
- 广告账户主数据、账户与投放人的绑定关系。
- 与广告平台 API 的对接或余额回读。

## 4. 角色与权限

| 权限码 | 含义 | 默认授予 |
|---|---|---|
| `network-nodes:read` | 查看静态节点占位页 | `operations_staff`、`system_admin` |
| `advertising-recharges:read-self` | 查看本人申请、二维码与付款结果 | `operations_staff`、`system_admin` |
| `advertising-recharges:create` | 提交申请、撤回本人申请、上传二维码 | `operations_staff`、`system_admin` |

## 5. 功能需求

### 5.1 申请字段

| 字段 | 必填 | 填写人 | 说明 |
|---|---|---|---|
| 账户类型 | 是 | 运营 | `PERSONAL`（个人户）/ `NON_PERSONAL`（非个人户） |
| 广告账户名称 | 是 | 运营 | ≤128 字符，首尾去空白 |
| 广告账户编号 | 是 | 运营 | ≤128 字符，首尾去空白 |
| 充值金额 | 是 | 运营 | >0，两位小数；币种 CNY/USD，默认 USD |
| 付款二维码 | 个人户必填 | 运营 | jpg/png/webp，≤10 MiB；非个人户不接受 |
| 备注 | 否 | 运营 | ≤500 字符，纯空白视为未填 |
| 付款金额（CNY） | 付款时必填 | 财务 | >0，两位小数 |
| 付款截图凭证 | 付款时必填 | 财务 | jpg/png/webp，≤10 MiB |
| 状态 | — | 系统 | 待付款 / 已付款 / 已驳回 / 已撤回 / 已作废 |
| 审计字段 | — | 系统 | 单号、申请人、提交时间、付款人/时间、审核人/时间、撤回/作废时间、版本号 |

### 5.2 运营侧

1. 列表固定只看本人提交的申请，支持状态页签与单号/账户名称/编号搜索。
2. 「新增申请」为两步弹窗：第一步填写信息并提交；第二步展示复制文本，点击复制后关闭。
3. 复制文本固定三行：

   ```text
   【广告户充值】
   广告账户名称：…
   广告账户编号：…
   广告账户充值链接：<财务工作台详情页绝对链接>
   ```

4. 待付款申请可撤回；撤回为终态。
5. 详情抽屉只读展示申请信息、二维码、付款结果与驳回/作废原因。

### 5.3 财务侧

1. 列表展示全部申请，支持状态页签与单号/账户名称/编号/申请人搜索。
2. 点击详情进入隐藏路由详情页（不显示在菜单），登记付款金额与付款截图后提交。
3. 付款成功即产生资金流水：个人与公司账户按申请人当时分成比例扣减。
4. 待付款申请可驳回（必填原因），不产生资金流水。
5. 已付款申请可整单作废并冲正（必填原因），申请保留原付款事实；作废为终态。

### 5.4 状态机

```text
PENDING ──付款──> PAID ──作废──> VOIDED
   │
   ├──驳回──> REJECTED
   └──撤回──> WITHDRAWN
```

所有终态不可再流转；单号、账户信息、申请金额与二维码提交后不可修改。

## 6. 验收标准

1. 运营提交后单号符合 `AD/YYYYMMDD-####`，申请为待付款且不动资金。
2. 个人户缺少二维码、非个人户携带二维码均被拒绝。
3. 财务付款 1000 CNY、申请人分成比例 30% 时：个人账户扣 300、公司账户扣 700，批次类型为 `ADVERTISING_FEE`、来源 `ADVERTISING_RECHARGE`。
4. 作废后生成反向批次，两账户余额恢复到付款前。
5. 运营列表看不到他人申请；财务列表能看到全部。
6. 驳回、撤回、作废都不允许重复执行，也不允许跨状态执行。
7. 直接 URL 不能绕过权限：运营读取码打不开财务详情，财务全量码打不开运营列表。
