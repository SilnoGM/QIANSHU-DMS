# 编号用途分类与新增页面实施任务

状态：需求、schema/API 与页面设计均已确认；本任务计划待用户确认。所有实现与功能验收项均未开始。

## 执行边界

- 目标：完成“全部编码 / 业务编码 / 唛头编码”视图、可信计数、用途分类列、双卡片用途选择与独立新增页面。
- 真相源：[需求基线](requirements.md)、[已确认设计](design.md)、现有编号模块与正式 Web 应用。
- 新增页面替代新增抽屉入口；编辑、复制、详情继续用抽屉，保留原文件。
- 允许实施已确认的 schema/API 变化并新增 migration 文件；只在隔离测试数据库应用和验证，不连接业务库执行迁移、重置或真实发号。
- 不改引擎、配置指纹、编号周期、唯一性、计数推进、幂等契约；不接入采购自动唛头。
- 使用 TDD：先记录针对目标行为的失败，再实现最小改动并回归。真实命令错误、测试失败和未验证部分如实记录。
- 只进行本地标准提交，提交前核对范围；不推送、不发布、不自动重启业务开发服务。必填用途字段需前后端成套交付，不把中间契约不匹配状态视为可交付结果。

## 任务清单

- [ ] **1. 建立实施基线与失败测试。**
  - 核对 Git 现状，保留用户并行改动；记录现有编号相关测试基线。
  - 为用途必填、非法值、创建/复制持久化、编辑拒绝用途覆盖、列表用途过滤与三项计数补失败测试。
  - 为用途列、三视图查询、用途选择入口及新增路由补 Web 失败测试。
  - 记录失败原因，区分目标缺失与既有失败，不把未执行测试标记为通过。
  - _对应需求：R1–R5；依赖：任务计划确认。_

- [ ] **2. 实现用途模型及独立迁移文件。**
  - 新增 `NumberingRulePurpose` 与非空 `NumberingRule.purpose`。
  - 迁移时现有规则全部回填 `BUSINESS`；最终不保留隐式默认用途。
  - 增加用途不可变保护与已确认组合索引，不改旧迁移、不更新其他历史字段。
  - 隔离数据库先准备历史规则、版本、已用计数和派发记录，再应用新迁移，核对历史快照不变；检查非法值、空值、修改用途被拒绝。
  - 更新必须显式声明用途的现有测试夹具，不借机改变编号测试语义。
  - _对应需求：R1；依赖：1。_

- [ ] **3. 实现 Server 管理契约与可信统计。**
  - 新增请求严格要求 `purpose`；编辑和复制请求不接受用途覆盖；复制从服务端来源规则继承用途。
  - 列表/详情及相关写操作详情响应增加 `purpose`，审计记录用途。
  - 列表增加可选用途查询和固定三项 `purposeCounts`；`ALL` 只作为前端视图/计数标识，不作为持久化用途。
  - 在现有 `RepeatableRead` 快照内，对 `keyword + status` 聚合跨页计数；列表另加用途过滤，确保选中项计数与 `total` 相等。
  - 保留预览、版本、派发记录和内部生成接口，验证两种用途仍通过同一引擎运行。
  - _对应需求：R1–R3；依赖：2。_

- [ ] **4. 同步 OpenAPI 与 Web 契约边界。**
  - 通过 `node --run contract:sync` 生成双端快照，不手工编辑快照或生成类型。
  - 更新 Web API 模块、运行时响应校验、查询及请求 builder、相关夹具。
  - 新增请求明确传用途，预览/编辑/复制 builder 不夹带用途；拒绝未知用途、缺失/非法计数与不一致总数。
  - 执行 `node --run contract:check` 和针对性测试，记录实际结果。
  - _对应需求：R1–R5；依赖：3。_

- [ ] **5. 提取现有表单的稳定复用部分。**
  - 将字段、片段编辑、字段错误、dirty 与本地校验整理为编号业务目录内的受控表单组件。
  - 继续复用现有片段编辑器、预览组件及窄请求能力；不复制两套校验逻辑，不新增全局 Store 或流程框架。
  - Drawer 壳保留关闭保护，Page 壳独立负责路由离开；保留编辑冻结、复制配置只读及 `expectedVersion` 恢复行为。
  - 先验证编辑、复制抽屉回归，再接入新增页面。
  - _对应需求：R5；依赖：4。_

- [ ] **6. 实现用途选择弹窗与独立新增页面。**
  - 基于 `QsGenericModal` 实现两张用途卡片，沿用已确认图标、文案、绿色/琥珀色区分及响应式规则。
  - 初始无选择，选定后允许继续；取消无写入，支持键盘、焦点恢复及减少动态效果。
  - 新增 `/system/basic-data/numbering/create` 隐藏菜单路由，保留编号管理菜单高亮与明确的 `read && create` 页面权限。
  - 严格处理用途缺失、非法值和数组值；合法用途只读展示，URL 用途改变时不能携带旧表单继续保存。
  - 实现左配置/右预览及窄屏上下布局；保留 Server 预览、防抖与旧响应隔离。
  - 保存仅创建 `DRAFT`，成功后轻提示并返回相应用途列表；失败保留输入，未知结果不自动重试。
  - 覆盖双击、离开/后退/刷新/页签关闭的未保存保护，不新增本地持久化草稿。
  - _对应需求：R4–R5；依赖：5。_

- [ ] **7. 接入列表视图、计数与用途列。**
  - 在页面头与表格之间接入 `QsStatusSwitchToolbar`：全部编码 / 业务编码 / 唛头编码。
  - 使用服务端三项计数；保留其他查询条件，切换用途重置页码；加载/失败不伪装为零，过期响应不覆盖新视图。
  - 在编号规则与编号结构之间加入“用途分类”普通文本列，`minWidth: 120px`，三个视图均保留。
  - 新增按钮改为用途弹窗；编辑、复制、详情仍走抽屉，详情补用途展示。
  - 新建成功刷新对应分类及计数，取消恢复原列表上下文；验证查询参数与界面同步。
  - _对应需求：R2–R5；依赖：4、6。_

- [ ] **8. 完成隔离端到端与视觉验收。**
  - 在隔离 PostgreSQL 验证迁移、管理 API、复制继承、分类计数和原内部派发回归；不在业务库创建测试规则或派号。
  - 浏览器走完两种用途的“列表 → 弹窗 → 新增页 → 草稿列表”，确认预览/取消不占号、创建不自动启用。
  - 验证权限缺失/变化、快速切换、搜索/状态/分页组合、URL 异常、离开保护及编辑/复制回归。
  - 检查桌面、窄屏、亮暗主题、键盘焦点与减少动态效果；确认不存在整页横向撑宽和截断。
  - 串行执行会生成共享产物的命令：`pnpm -C server check`、`pnpm -C web check`、`node --run contract:check`；运行隔离编号 E2E 与 `node --run ci:browser-numbering-e2e`。
  - 如环境阻塞，记录未验证项和证据，不跳过后宣称通过。
  - _对应需求：R1–R5；依赖：2–7。_

- [ ] **9. 审阅、记录与本地交付。**
  - 更新本清单完成项及验收记录，附实际命令、测试结果与已知限制。
  - 运行 `git diff --check`，检查引擎、旧迁移和不相关文件没有被改动；核对暂存范围无 `.env`、密钥、生成文件、构建物或日志。
  - 对通过必要验证的变更小步标准提交，类型用英文、描述用中文；核对最终工作区，不推送。
  - 清楚告知新 migration 文件尚未应用业务库，避免把代码完成等同于业务环境可用；实际应用继续等单独授权。
  - _对应需求：R1–R5 及交付限制；依赖：8。_

## 完成判定

只有任务 1–9 的必要验证均完成并有证据，才能称为代码实施完成。任务计划确认不等于业务数据库应用、重启、推送或发布授权。
