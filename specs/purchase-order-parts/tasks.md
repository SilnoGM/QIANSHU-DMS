# 采购预定义货件实施

## 已确认范围

- 第三步改为“预定义货物件”；保留采购备注与紧凑唛头规则摘要。
- `QsPartConfigurator` 以产品行与正整数数量配置货件，支持拆分、合并、删除退回。
- 一张采购单有多个货件，每个货件独立派发唛头；前后端逐行校验完整覆盖。
- 扩展采购创建、列表和详情契约；历史单值唛头保留，不推断历史包装数量。
- 新增货件及分配持久化结构和 migration，沿用编号引擎和供应商绑定规则。
- 不应用业务库 migration，不推送、不发布；不扩展按货件履约或提交后重新分箱。

- [x] 采购步骤接入、修改产品后分配失效处理、冻结提交快照。
- [x] 货件持久化、数量守卫、逐件派发、幂等与历史恢复。

## 实现边界

- 每单最多 1000 个货件、10000 个产品分配项；同一产品行可按正整数数量拆箱，不支持把单件产品拆成多个包装箱。
- 创建请求必传 `parts`，采用 `purchase-order.create.v4` 指纹；旧 v3 请求只允许恢复已存在的同键结果。
- 唛头、货件和采购单在同一业务事务中写入；继续沿用原采购订单编号预派发机制。
- 数据库最终校验完整分配后封存货件。提前 `SET CONSTRAINTS` 也不能在校验后追加、改写或删除货件配置；封存不改变订单版本、更新时间或业务状态。
- 仅采购创建请求体允许 1 MiB；其他 API 保留原上限，超限返回 `413 PAYLOAD_TOO_LARGE`。
- 历史订单继续展示原单值唛头，不回填货件，也不重新派发。
- 组件库入口：业务组件 → 货件配置器；页面路径 `/component-library/business/part-configurator`。

- `server check`：261 suites / 2760 tests 通过。
- `web check`：172 项 Node 脚本、49 项 TS 脚本、1179 项 API/页面逻辑测试，以及类型、ESLint、Stylelint 检查全部通过。
- `ci:server-e2e`：隔离库双次 migration deploy、迁移状态检查及全部 55 suites / 317 tests 通过；包含 1000 货件和 10000 分配项、数量守恒、派发回滚、幂等、历史恢复与封存绕过回归。
- `contract:check` 通过，Server / Web OpenAPI 一致。
- 根脚本测试 691 项通过。
- `ci:browser-auth-e2e`：5 个真实 Chrome 综合场景全部通过。采购场景验证多产品合箱、按数量分箱、删除退回、减量重配、完整覆盖拦截、逐件派号、任意唛头查询、逐号与全部复制、键盘/触控、默认折叠及私有产品图、提交结果未知时按原 key/货件快照恢复，以及审核/付款/发货/取消既有流程。
- 亮色、暗色及 `390×844` 窄屏截图已检查。货件与多唛头展示沿用现有卡片、手风琴、主题色和绿色小节标记。
- 全量 E2E 初次遇到两套既有接口测试偶发连接重置，改为套件统一监听与关闭后，连续三轮定向回归及完整服务端 E2E 通过，未添加重试或忽略失败。
- 浏览器历史夹具先用真实旧 migration 写入，再正常 deploy 新 migration；未关闭生产约束或手工改写迁移账本。
- 浏览器迭代中修正了组件库 CI 入口、旧步骤提示断言、列表必填 `view` 参数，以及固定列遮挡/窄屏重排后的滚动定位。最终保留真实命中检测、原生鼠标/触控事件与失败诊断，未用跳过断言或重复点击掩盖问题。
- 构建仍有既有 VueUse PURE 注释、较大分块及 pg 并发 query 弃用提示；未作为本次扩展范围升级依赖。
- 业务数据库 migration **尚未应用**；新旧结构不兼容，业务启用前必须先完成迁移并同步部署前后端。
