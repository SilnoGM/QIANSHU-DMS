# 采购订单接入销售订单选择弹窗需求

## 简介

新增采购订单第一步当前使用采购域私有的简易销售订单选择器。本需求将其替换为公共组件 `QsSalesOrderSelectorModal`，同时继续通过采购域接口执行查询和图片鉴权，避免要求采购操作员额外具备 `sales-orders:read` 权限。

## 需求

### 需求 1：使用公共销售订单选择弹窗

**用户故事：** 作为采购操作员，我希望通过统一的销售订单选择弹窗查找并确认来源订单，以便在采购创建流程中获得与其他业务域一致的选择体验。

#### 验收标准

1. 当用户在销售关联采购第一步点击“选择销售订单”时，系统应打开 `QsSalesOrderSelectorModal`。
2. 当用户搜索或切换分页时，系统应通过采购域来源订单接口加载候选数据。
3. 当用户选中候选订单但尚未确认时，系统不应修改采购表单当前关联订单。
4. 当用户确认选择时，系统应回填销售订单并加载该订单剩余可采购明细。
5. 当用户取消弹窗时，系统应保留采购表单原有关联订单。

### 需求 2：候选订单数据完整且可信

**用户故事：** 作为采购操作员，我希望在弹窗中看到出单人、产品、履约和付款状态，以便判断应关联的销售订单。

#### 验收标准

1. 当采购域查询销售来源订单时，系统应只返回 `orderStatus = CONFIRMED` 的订单。
2. 当接口返回候选订单时，系统应提供 `issuer`、`orderStatus`、`fulfillmentStatus`、`paymentStatus` 和 `lineSummary`。
3. 当销售产品存在当前有效主图时，系统应返回采购权限可访问的主图 URL。
4. 当销售产品是 `CUSTOM` 或没有当前有效主图时，系统应返回 `mainImage = null`。

### 需求 3：产品主图使用采购权限读取

**用户故事：** 作为只有采购权限的操作员，我希望能查看候选销售订单的产品主图，而不需要销售订单读取权限。

#### 验收标准

1. 当用户读取采购来源销售产品主图时，系统应要求 `purchase-orders:create` 权限。
2. 当图片 URL 中的销售订单、销售明细或产品媒体关系失效时，系统应返回资源不存在错误，不应泄露其他产品媒体。
3. 当图片读取成功时，系统应保留现有媒体内容服务的缓存、范围请求和 `HEAD` 行为。

### 需求 4：保留采购订单业务规则

**用户故事：** 作为采购业务负责人，我希望选择器升级不改变既有采购规则，以避免出现来源、价格或数量越界。

#### 验收标准

1. 当用户选择新的销售订单时，系统应清空旧来源明细和已同步采购明细，并重新读取剩余可采购数量。
2. 当用户同步产品时，系统应继续执行供应商匹配、`CUSTOM` 规则和剩余数量上限校验。
3. 当用户创建备货采购时，系统不应展示销售订单选择和同步入口。
4. 在最终提交确认之前，系统不应创建幂等键、派发采购订单号或写入采购订单。
