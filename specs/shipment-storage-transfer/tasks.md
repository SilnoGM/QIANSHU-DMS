## 2. 执行纪律

1. 每个任务遵循“先失败测试 → 最小实现 → 聚焦验证 → 审计 diff → 小步提交”。
2. 数据库 schema、公共 API、权限目录、审计枚举变更必须单独授权；授权按对象与范围生效。
3. 提交前检查 `git status`、`git diff --cached --name-only`、`git diff --cached --check`，不混入用户已有改动。
4. Commit Message 类型用英文、描述用中文，例如 `feat: 新增货件归属事件表`。
5. 不 push、不建 PR、不合并、不发版，除非另行授权。
6. 命令失败、测试失败如实报告，不跳过断言、不伪造通过。
7. 迁移期不改 DTO、不改前端、不新增接口。

## 7. 回滚

| 阶段 | 回滚方式 |
|---|---|
| M1 | 纯 additive；回退代码即可，表可保留；双写变成死代码 |
| M2 | 回退终止态代码；已终止数据需单独数据修复 |
| M3 | 回退释放接口与前端；已释放数据按寄仓记录回滚或保留 |
| M4 | 回退认领与资金；已记账批次需业务冲账，不删除 |
| M5 | 回退挂起与包装费前置；账单状态保留 |

## 8. 完成定义

- 所有阻塞缺口关闭或明确接受；
- 现有全部测试与 e2e 通过；
- 新功能端到端通过；
- 迁移自检与 parity 零差异；
- 文档、契约与索引同步；
- 未授权项（push、PR、发布、部署）保持未执行。
