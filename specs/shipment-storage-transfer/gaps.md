## 2. 阻塞性缺口

| ID | 缺口 | 现状与依据 | 影响 | 建议 |
|---|---|---|---|---|
| G-01 | 一条账单行拆两个收款人 | 结算模型是“一条账单行 → 一条 ACTIVE 结算 → 一个收款人”；`settlement.sales_order_id` 单值 | 寄仓费+二派费归甲、运费归乙的原始口径无法落账 | 单独立项：费用级分摊 + 新结算模式。若业务接受“同一收款人”降级，则本期可解除阻塞并在页面标注 |
| G-02 | 采购款未付清时能否释放 | 业务口径“拒收前必须付清”，但付款节奏不可控 | 未付清则成本快照缺少已付部分，转移金额不完整 | 二选一：禁止释放，或允许释放但标记“成本待清”且禁止认领；建议后者 |
| G-03 | 释放是否要求已到仓 | 现状未定义；已装柜资格本身要求已到仓 | 未到仓释放会让采购单无法 `SIGNED/COMPLETED`，且“寄仓”名不副实 | 建议要求 `warehouse_received_at` 非空 |
| G-04 | 认领后新销售单取消/改行的回收 | 销售取消门禁只检查采购单、收款、签收；认领不产生采购单 | 认领后 B 可取消，货件变孤儿；B 删除已认领销售行会破坏覆盖 | 定义“回收进池”二次寄仓，或禁止认领后取消/删除相关行 |
| G-05 | 拒收与“已签收”的边界 | 现有 `delivered_at` 是客户签收终态，不允许释放 | 客户拒收常发生在物流签收后，按现状无法进池 | 明确拒收事实记录方式与允许释放的例外规则 |
| G-06 | 历史货件目的地仓库为空 | 迁移明确“历史发货保留 NULL”，CHECK 允许 NULL；新发货触发器强制非空 | 这些货件无法走内地释放 | 上线前用只读 SQL 核对；非 0 时提供补录能力或显式阻断 |

### G-06 核对 SQL

```sql
SELECT count(*) AS shipped_without_destination
FROM purchase_order_parts
WHERE shipped_at IS NOT NULL AND destination_warehouse_value IS NULL;
```

## 3. 功能缺口（已知限制）

| ID | 缺口 | 影响 | 状态 |
|---|---|---|---|
| G-07 | 部分数量认领/拆件 | 一张货件只能整件归一个销售单；B 只要一部分时无法处理 | 已知限制，需新分配层后另立 |
| G-08 | 货件级跨单合并（N:N） | 柜次层可合并多单装柜；货件本身不能聚合多张采购单 | 不在本期 |
| G-09 | 无采购来源的货件 | 父单仍必填，不能凭空产生库存货 | 不在本期 |
| G-10 | 库存域 | 无库龄、盘点、报废、库存估值 | 不在本期 |
| G-11 | 海外仓作为一等维度 | 柜次无“到港仓”事实；寄仓位置只在快照里 | 已知限制；位置由释放时人工声明 |
| G-12 | 未认领货物的核销 | 报废/退运/销毁无去向，池余额不会自动清零 | 不在本期 |
| G-13 | 调货后改柜次收件人/COD | 原拍板第 8 条；现有 `ContainerLoadingItemChange` 只支持 RECIPIENT/COD，但未纳入本方案 | **待补进 M4** |
| G-14 | 出货信息复制与柜次唛头顶行 | 原流程第 7 步；界面与数据源未设计 | **待补进 M3/M4** |
| G-15 | 终止时部分货件已签收 | 混合场景规则未定：已签收货件不能释放，未签收货件可释放 | 待拍板 |
| G-16 | 认领后新销售单修改销售行 | `removedAt` 软删除会破坏已认领数量映射 | 待补校验 |
| G-17 | 非 TWD 的新销售单 | SLH 结算只支持台币订单 | 已知限制 |
| G-18 | 账单先于认领到达 | 已定“挂起”，但挂起时长、处理角色、超时策略未定 | 待细化 |
| G-19 | 历史已取消但货在仓 | 货件为 `CANCELLED`，装柜/签收/寄仓前置都要求 `ACTIVE` | 需单独数据修复或例外通道 |
| G-45 | 寄仓页的成本与客户信息对所有 `read` 权限角色可见 | 不做仓库隔离的直接后果 | 确认可接受，或限制 `shipment-storage:read` 的授予范围 |

## 4. 账务口径缺口

| ID | 缺口 | 说明 | 状态 |
|---|---|---|---|
| G-20 | 成本快照时点 | 已定在释放时快照；但采购金额修订若在释放前发生，快照需取最新值 | 已定，需实现校验 |
| G-21 | 成本尾差 | 多货件按 `数量 × 单价` 分摊时的尾差归属未定 | 待拍板 |
| G-22 | 公司腿跨比例 | 甲/乙比例不同时需要 2～3 张批次；资金规则引擎现有“单 user + 公司余数”模型能否表达需验证 | 待验证 |
| G-23 | 汇率 | 成本是 CNY、对账是 TWD；两跳是否涉及汇率与手续费未定义 | 待拍板；当前成本转移只在 CNY 账户内 |
| G-24 | 已收款不冲正 | 按拍板保留原收款；客户退款走外部通道，系统账务存在缺口 | 已知限制，业务接受 |
| G-25 | 包装费作废/冲正 | 包装费单无作废能力；若释放时仍待付款，只能阻断 | 待补或维持阻断 |
| G-26 | 池账户财务口径 | 能否负余额、是否提现、是否计入公司报表、是否出现在账户列表 | 待拍板 |

## 5. 数据与迁移缺口

| ID | 缺口 | 说明 |
|---|---|---|
| G-27 | 归属回填等价性 | 必须有 parity 命令逐行比对，零差异才允许继续 |
| G-28 | 已取消货件归属 | 回填为 `VOIDED`，列表仍按原归属可见，行为不变 |
| G-29 | 字典落地 | seed 只补缺失不覆盖；生产需 CLI 或后台手工，需授权 |
| G-30 | 字典停用/改名 | 快照标签保证历史可读；`RF_TZ`/`RF_LK` 值不可复用 |
| G-31 | 迁移失败关闭 | 件数、投影覆盖、最大 sequence、归属分布任一不符即整体回滚 |

## 6. 工程风险

| ID | 风险 | 缓解 |
|---|---|---|
| G-32 | 五条读取链路遗漏 | 逐条切换 + parity + 全量回归 |
| G-33 | 归属投影与事件不一致 | 触发器维护 + 自检 + parity |
| G-34 | 终止态遗漏判断点 | 按九类影响清单逐项验收 |
| G-35 | 锁序冲突 | 沿用“销售明细 → 采购单 → 销售主行”，新增锁排在货件之后 |
| G-36 | 寄仓列表性能 | 按 `location_scope`、`warehouse_value`、`status` 建索引并 EXPLAIN |
| G-37 | 契约破坏 | 迁移期零 DTO 变更；功能期只做 additive |
| G-38 | 回滚 | 迁移期纯 additive，代码可单独回退；功能期按里程碑独立发布 |

## 8. 待拍板清单

| # | 问题 | 推荐 |
|---|---|---|
| 1 | 账单行拆两个收款人是否本期做 | 本期不做，先按单收款人上线并在页面标注 |
| 2 | 未付清采购款能否释放 | 允许释放但标记“成本待清”，禁止认领 |
| 3 | 释放是否要求已到仓 | 要求 |
| 4 | 认领后新销售单取消/删除行 | 允许取消但强制回收进池；删除行加硬校验 |
| 5 | 拒收事实由谁录入、与已签收的关系 | 运营/仓管录入；拒收作为独立事实，不写 `delivered_at` |
| 6 | 终止时已签收与未签收混合 | 已签收保持完成，未签收释放；终止要求全部非签收货件已释放或已认领 |
| 7 | 成本尾差 | 尾差归最后一个货件或按公司腿吸收，需财务确认 |
| 8 | 池账户形态 | 公司账户 `purpose = SUSPENSE`，不可提现、不进个人列表 |
| 9 | 账单挂起时长与处理人 | 财务处理，超过 30 天进入异常清单 |
| 10 | 历史无目的地仓库货件 | 补录后释放，不静默放行 |
| 11 | 一次释放能否跨多张销售单/采购单勾选 | 建议允许，但批次内按来源单分组处理成本与审计；`origin_sales_order_id` 允许为空 |
