## 2. 背景与目标

客户取消或拒收后，已经采购、甚至已经发货或装柜的货件需要保留下来，转给新的销售订单：

- 情况 1：货件仍在内地仓库、尚未装柜，转移没有额外费用；
- 情况 2：货件已装柜并到达海外仓，产生寄仓费与二次派送费；
- 情况 3：客户拒收，货件携带必要信息进入寄仓，等待新订单调走。

当前模型的硬约束是：货件（`purchase_order_parts`）不直接关联销售单，业务归属只有一条不可变链路 `Part → PurchaseOrder.salesOrderId → SalesOrder`。因此货件既不能改挂销售单，也不能脱离采购单独立存在。

本需求的目标是：**在不破坏采购单、编号、唛头与物流事实的前提下，让货件的“当前业务归属”可以变更**，并在此基础上提供寄仓、认领、成本转移、对账与包装费跟随的能力。

## 3. 术语

| 术语 | 定义 |
|---|---|
| 货件 | 数据库中的 `purchase_order_parts` 一行；本文统一称“货件” |
| 来源采购单 | 创建货件时所属的采购单，永久保留，作为成本与来源凭证 |
| 当前归属 | 货件当前挂靠的销售单、寄仓池或公司；由归属事件解析 |
| 归属事件 | 追加式的归属变更记录，不可修改、不可删除 |
| 释放 | 把货件从原销售单归属转入寄仓池 |
| 寄仓记录 | 释放时生成的快照与状态记录，承载位置、成本、数量映射与认领状态 |
| 认领 | 新销售单从寄仓池取走货件，归属转为该销售单 |
| 池账户 | 承载寄仓期间成本责任的资金账户 |
| 终止态 | 销售单新增的终态，表示订单不再履约但未走取消，采购单保持可写 |
| 内地仓 | `mainland.warehouse` 字典中的仓库，装柜与到仓的物理现场 |
| 海外仓 | 新增 `overseas.warehouse` 字典中的仓库，寄仓位置 |

## 5. 已确认业务口径（2026-10-27，八条）

1. 先解除归属进入“待调货池”，不要求取消时同时指定新销售单。
2. 采购成本按新销售单出单人的 `userShareRate` 重算；已付部分通过成本转出批次回补原出单人与公司，再按新比例重记，公司腿随比例差自动变化。后续评估已明确：**不冲正原采购付款批次**，只做成本责任重分类（见 [design.md](./design.md) 6.3）。
3. 不做退款单；原收款记录保留、不对已收款事实做冲正；客户退款走另行规划的台币转账通道。
4. 情况 2 的寄仓费与二次派送费归原出单人，正常运费归新销售单。
5. 待调货期间成本由新建的池账户承接。
6. 按单个货件处理，不按整张采购单。
7. 原销售单终止后，已保留的有效收款保持原样，不派生“待退”展示。
8. 调货后唛头保留（写入后不可改），只改装柜明细的收件人/COD（走现有变更能力，提交前需确认已发群通知）。

## 6. 本次补充口径（2026-10-28）

| # | 口径 | 说明 |
|---|---|---|
| 1 | 采用“业务归属脱离”，不做物理拆父单 | 采购单保留为来源与成本凭证；归属由新增归属层表达 |
| 2 | 认领按整件货件 | 首期不支持部分数量；部分数量需要拆件与新的分配层 |
| 3 | 未装柜释放时，内地仓必须等于货件的 `destinationWarehouseValue` | 不提供内地仓选择，不做仓间调拨 |
| 4 | 已装柜但柜次尚未到港，位置算“海外仓” | 位置是业务声明，不区分在途与已入仓 |
| 5 | 允许瑞锋-台中仓 ↔ 瑞锋-林口仓之间移动 | 仅海外仓之间、仅寄仓期间；需原因与审计 |
| 6 | 内地寄仓与海外寄仓共用一个列表，通过筛选区分 | 菜单由“海外寄仓”改为“寄仓管理” |
| 7 | 不做仓库级数据权限隔离 | 有寄仓页权限即可看到内地与两个海外仓的全部记录 |
| 8 | 认领后解除物流冻结 | 未装柜可继续装柜，已装柜可继续签收；财务快照不解冻 |
| 9 | 新增字典类型 `overseas.warehouse` | 条目 `RF_TZ`＝瑞锋-台中仓、`RF_LK`＝瑞锋-林口仓 |
| 10 | 字典落地方式为 seed + CLI | seed 保证新环境一致；CLI 幂等补齐存量环境 |
| 11 | 寄仓费/二次派送费不按仓库区分费率 | 两个海外仓使用同一费率口径 |
| 12 | 海外仓只用于寄仓位置 | 不进入发货目的地、柜次装柜仓、到仓分仓等内地仓场景 |

## 7. 范围

### 7.1 本期范围

- 货件归属事件与当前归属投影。
- 现有五条读取链路切换到归属解析（行为等价迁移）。
- 销售单终止态。
- 货件释放进寄仓、寄仓记录与位置快照。
- 海外仓位置移动（台中 ↔ 林口）。
- 新销售单认领寄仓货件。
- 成本两跳转移与池账户。
- SLH 对账收款人跟随归属；认领前账单挂起。
- 包装费释放前置与释放后禁提报。
- 寄仓管理页面（单列表 + 筛选）。
- 字典 `overseas.warehouse` 的 seed 与 CLI。
- 审计、权限、幂等与并发控制。

### 7.2 非本期范围

- 物理移除货件父单（`purchase_order_id` 仍必填）。
- 部分数量认领或拆件。
- 一张货件聚合多张采购单（货件级 N:N）。
- 库存域：库龄、盘点、报废、库存估值。
- 无采购来源的货件。
- 客户退款与台币转账通道。
- 账单行拆多个收款人（寄仓费/二派费归甲、运费归乙的落账仍不完整）。
- 海外仓作为柜次到港事实或分仓维度。
- 修改货件唛头、编号、装柜事实。

## 8. 验收标准

### 8.1 迁移阶段（无用户可见变化）

1. 现有货件列表、状态计数、详情、对账预览、包装费提报可见性在迁移前后逐字段一致。
2. 现有 e2e 与前后端测试全部通过，不改既有断言。
3. OpenAPI 在迁移阶段无破坏性变更。
4. 迁移与回填具备自检，失败关闭，不伪造历史。

### 8.2 功能阶段

1. 原销售单可以终止，采购单仍可付款、可完成，不触发采购行来源不变量。
2. 释放后原销售单看不到也操作不了该货件；货件保留编号、唛头与全部物流事实。
3. 寄仓记录包含来源单、数量映射、柜次/收件人/COD、成本与比例快照。
4. 新销售单认领后，覆盖、履约、装柜、签收、对账收款人全部按新销售单解析；包装费在释放后禁止新增，已付费用进入成本快照随成本转移。
5. 成本两跳后，原出单人、公司、池、新出单人四方的最终结果与新销售单自行采购一致；池账户归零。
6. 位置移动只在海外仓之间、只在寄仓期间，且每次移动有审计。
7. 寄仓管理页可看到内地与海外全部寄仓记录，并按位置范围、仓库、状态筛选。
8. 释放与认领具备幂等、并发锁与明确错误码。
