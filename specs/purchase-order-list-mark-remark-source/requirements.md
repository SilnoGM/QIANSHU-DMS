# 采购订单列表唛头、备注与销售来源需求

## 1. 背景与目标

采购人员需要在“全部采购”和“待办采购”的共享列表中直接查看采购唛头、备注和销售来源，并快速复制需要传递的销售订单号或采购唛头。该能力应复用现有采购列表、编号排版和复制交互，不新增详情请求或数据库字段。

## 2. 设计规格

- 平台：Web，Vue 3 + Vite。
- 视觉方向：Industrial / utilitarian，延续运营工作台的高密度业务表格。
- 色彩：只使用现有主题 Token，不新增硬编码颜色。
- 字体：订单编号使用现有数据强调与等宽字体；客户名、采购唛头和备注使用正常正文。
- 布局：桌面端使用独立列；移动端在共享订单卡片中展示同一组信息。

## 3. 功能需求

### R1：采购唛头列表契约

**用户故事：** 作为采购人员，我希望采购列表直接返回采购唛头，以便无需打开详情即可识别和复制。

#### 验收标准

1. 当客户端请求采购订单列表时，系统应在每个订单项中返回可空的 shippingMarkText。
2. 当采购订单未填写唛头时，系统应返回 null。
3. 当系统扩展列表响应时，系统不得修改数据库 schema、采购唛头保存规则或详情响应语义。
4. 当 Web 渲染当前页订单时，系统不得为了取得采购唛头发起逐订单详情请求。

### R2：采购唛头与备注列

**用户故事：** 作为采购人员，我希望列表同时展示采购唛头和备注，以便快速判断订单附加要求。

#### 验收标准

1. 当桌面采购列表渲染时，系统应展示“采购唛头”和“备注”两列。
2. 当字段为空时，系统应显示 -。
3. 当字段内容超出列宽时，系统应单行截断，并允许通过 Tooltip 查看完整内容。
4. 当采购唛头非空时，系统应提供一键复制，并复制服务端返回的完整原始文本。
5. 当采购唛头为空时，系统不得提供可执行的复制操作。
6. 当移动端采购卡片渲染时，系统应展示相同的采购唛头和备注信息。

### R3：销售来源排版与复制

**用户故事：** 作为采购人员，我希望销售来源中的订单号与采购订单号具有一致的编号语义，并能直接复制。

#### 验收标准

1. 当销售关联采购存在销售订单号时，系统应在第一行使用与采购订单编号相同的数据强调与等宽字体。
2. 当销售订单号存在时，系统应提供一键复制，并复制完整订单号。
3. 当销售来源存在客户名时，系统应在第二行使用正常正文样式展示，不使用编号字体或弱化元信息样式。
4. 当订单为独立备货采购时，系统应显示“独立备货”和“不关联销售客户”，且不提供销售订单号复制。
5. 当移动端采购卡片渲染销售来源时，系统应保持订单号、客户名和复制能力的同一语义。

### R4：共享列表一致性

**用户故事：** 作为采购人员，我希望全部采购与待办采购展示一致，以免不同入口产生理解差异。

#### 验收标准

1. 当用户进入“全部采购”或“待办采购”时，系统应复用同一列表列定义和单元格实现。
2. 当新增展示能力时，系统不得改变现有筛选、分页、状态计数、处理按钮或详情抽屉行为。

## 4. 非目标

- 不修改数据库 schema、迁移或历史数据。
- 不修改采购唛头、备注或销售来源的业务规则。
- 不修改 CopyCellButton、QsGenericTable 或其他公共组件 API。
- 不调整用户未指定的既有列宽。
- 不新增第三方依赖、主题 Token 或动画。
