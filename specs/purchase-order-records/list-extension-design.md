# 采购列表记录列接入方案（已确认并实施）

## 已确认需求与范围

全部采购和待办采购共用 `purchase-orders/index.vue`。新增实际付款记录、订单凭证、变更记录三列，保留原有实际付款金额列。不改变列表筛选、分页、汇总金额、业务权限及操作按钮。

当订单没有对应记录时，列表必须显示明确空值占位，不得把“尚未加载”当作“没有记录”。当订单存在记录时，三列分别展示类型和金额、类型和数量、最近变更和次数。

## 已确认的公开 API 变更

仅扩展 `GET /api/purchase-orders` 的 `PurchaseOrderListItemDto` 响应。由于详情 DTO 继承列表 DTO，详情接口同步返回新增摘要字段。保持原字段不变，不新增路由，不修改数据库 schema。

| 新增字段 | 结构 | 口径 |
| --- | --- | --- |
| `paymentRecordSummary` | `{ count, byType: [{ paymentType, count, amount }] }` | 只统计 `voidedAt = null` 的付款；按 `DEPOSIT / BALANCE / OTHER` 固定三类返回，金额为四位小数十进制字符串，各类金额合计与 `paidAmount` 一致 |
| `documentSummary` | `{ count, byType: [{ documentType, count }] }` | 只统计 `detachedAt = null` 的凭证，分别统计采购单、付款凭证、签收单；不复制凭证或在列表返回附件正文 |
| `changeSummary` | `{ statusCount, amountCount, latest: { kind, changedAt, reason } \| null }` | 合并状态历史与金额修订；`kind` 为 `STATUS / AMOUNT`，最近项按时间及稳定键排序，无历史则 `latest = null`；旧空原因保留 `null`，由 UI 显示“未记录原因” |

所有计数字段为非负整数，付款类型金额缺项返回 `0.0000`，不使用 JavaScript 浮点数累计。当前页订单批量查询摘要，不逐行请求详情；同一响应内付款分类和已付金额必须使用同一批有效付款事实。

## UI 设计规格

- 用途：让采购经办人在列表快速查看付款构成、凭证齐备情况和最近变更，完整记录继续从已有详情抽屉查看。
- 风格：沿用工业工具型业务表格，密集但分层；不新增卡片式布局或动画。
- 色彩：沿用现有主题 token；亮色基准为品牌绿 `#00873A`、正文近黑 `#18181B`、辅助灰 `#71717A`、分隔灰 `#E4E4E7`、背景 `#FFFFFF`。实际样式不硬编码色值，暗色主题使用对应 token。
- 字体：沿用 `Noto Sans SC` 和金额/数字的 `Noto Sans Mono`，复用 `AmountDisplay`、`DateTimeDisplay` 与表格堆叠行组件。
- 布局：实际付款记录紧接实际付款金额列，建议 `minWidth: 180px`；订单凭证接订单状态列，建议 `minWidth: 170px`；变更记录接审计信息前，建议 `minWidth: 190px`。类型左对齐、金额右对齐；保持现有水平滚动及固定操作列。
- 无记录显示 `—`；有记录时付款展示三类的非零记录项及金额，凭证展示各类非零数量，变更展示总次数、最近类型与时间，完整原因使用轻量提示，不无限抬高行高。
