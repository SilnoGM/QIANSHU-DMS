# 采购单复制文案与采购单图片格式需求

## 1. 背景与目标

采购审核弹窗同时提供「复制文本」和「复制图片」两种对外传递方式：文本用于通过聊天工具发给供货方，图片用于归档和打印。两者目前对同一份采购单的描述口径不一致：

- 文本带「出货请贴货物唛头：」段标题，每个货件重复一次「（请将此货件唛头贴到包装箱 / 货物上）」，且完全不包含行备注和采购备注。
- 图片渲染产品编号（`PROD/00001`）、产品属性、每个货件的红色贴标提示，行备注为空时整行不渲染。

目标是让两个出口共用一套口径：唛头标签统一为「唛头：」，贴标提示只出现一次并归入采购备注，行备注在图片中恒定渲染（空值为 `-`），在文本中按需出现。

## 2. 范围

### 2.1 本次实施

复制文案：

- 删除「出货请贴货物唛头：」段标题。
- 唛头行标签从「此货件唛头：」改为「唛头：」。
- 删除货件块内每行的贴标提示。
- 新增行备注（有值才输出）。
- 新增采购备注段（恒定输出，内含贴标提示与可选自定义备注）。

采购单图片：

- 删除产品明细块的产品编号行与产品属性行。
- 删除货件区产品行的产品编号前缀，改为在产品名后用括号内联行备注。
- 行备注空值渲染为 `备注：-`。
- 货件块删除红色贴标提示，提示语迁入采购备注段并保持红色醒目。
- 采购备注段改为恒定渲染。
- 图片模板版本升级，旧草稿失效。

### 2.2 本次一并实施（已批准的 B 方案）

- 把同一格式做成「采购审核通过」事件（`PURCHASE_REVIEW_APPROVED`，模板键 `purchase.review.approved`）的通知模板，文案与采购单图片同发。
- 新增 5 个模板变量并放开变量长度上限，使整段文案不再被 200 字截断。
- 通知变量的供应商名统一改为字典显示名，与复制文案抬头一致。

### 2.3 不在范围

- 不修改数据库 schema、Prisma 模型和任何迁移。
- 不修改公共 HTTP 契约、OpenAPI 快照与前端生成类型。
- 不修改采购行说明的录入入口，也不改变其数据来源（销售单行说明继承或采购单录入）。
- 不修改唛头后缀规则，包括个人别名 > 默认别名 > 产品名的优先级和「名×数量」写法。
- 不修改货件块产品名取值来源（仍为采购行快照名，不使用别名）。
- 不修改复制图片的归档链路、媒体资产和通知附件合同。
- 不修改通知渠道策略的目标解析、投递重试、静默时段和失败语义。
- 不改变站内通知不支持附件的现状，附件只在小助理渠道发送。

## 3. 术语

| 术语 | 定义 |
| --- | --- |
| 复制文案 | 审核弹窗「复制文本」生成的纯文本，构建于 `purchase-order-copy.logic.ts` |
| 采购单图片 | 服务端渲染并归档的 PNG 凭证，构建于 `purchase-order-image-renderer.ts` |
| 行备注 | 采购明细行说明，即详情 DTO 行上的 `description` 字段 |
| 采购备注 | 整单备注，即详情 DTO 上的 `remark` 字段 |
| 采购提示语 | `请将上述货件唛头贴到对应的包装箱 / 货物上` |
| 别名 | 产品在唛头后缀里的展示名，优先级为个人别名 > 默认别名 > 产品名 |

## 4. 格式定义

### 4.1 复制文案

```
【PO/20260916-00016】
供应商：示例供应商
采购日期：2026-09-16

[采购产品明细]
产品名：木桌*1
金额小计：100.00*1=100.00
备注：请附带说明书

产品名：椅子*2
金额小计：30.00*2=60.00

总价：160.00
订金：30.00
尾款：130.00

货件-01：木桌+椅子
唛头：【TEST/00016/货件-01】木桌+椅子（李华-赖文寿）

货件-02：椅子
唛头：【TEST/00016/货件-02】椅子（李华-赖文寿）

采购备注：请将上述货件唛头贴到对应的包装箱 / 货物上；请按货件分别包装并附采购单。
```

分段规则：

- 顶层段落之间空一行；段落顺序为 抬头、产品明细、金额约定、货件块、采购备注。
- 产品块内固定两行，行备注非空时追加第三行；产品块之间空一行。
- 货件块内固定两行，货件块之间空一行。
- 采购备注恒定输出一段，内容为采购提示语，存在自定义备注时追加 `；` 和压平后的自定义备注。

### 4.2 采购单图片

产品明细块每行信息自上而下：

```
双动力600型撕碎机     ← 产品名（26px 加粗）
备注：-               ← 行备注，恒定一行；有值时为「备注：xxx」
```

产品编号与产品属性不再出现在图片中。表头「产品 / 规格备注」保持不变。

货件块：

```
货件-01                                        PKG/20260916-00001
唛头：【TEST/00016/货件-01】木桌+椅子（李华-赖文寿）
木桌（请附带说明书）                                           数量 1
椅子                                                           数量 1
```

货件块末尾不再出现红色贴标提示。产品行去掉编号前缀，行备注非空时以全角括号内联在产品名之后，为空时不渲染括号。

采购备注段恒定为图片最后一节：

```
采购备注
请将上述货件唛头贴到对应的包装箱 / 货物上        ← 红色加粗（#e7000b）
请按货件分别包装并附采购单。                    ← 灰色（#6b756f）
```

提示语一行恒定存在，自定义备注存在时另起一行；两者都不参与换行压平，保留原始换行。

### 4.3 口径对照

| 项 | 复制文案 | 采购单图片 |
| --- | --- | --- |
| 段标题「出货请贴货物唛头：」 | 删除 | 不适用 |
| 唛头标签 | `唛头：` | `唛头：` |
| 货件块内贴标提示 | 无 | 无 |
| 行备注·有值 | `备注：xxx` 独立一行 | `备注：xxx` 独立一行 |
| 行备注·空 | 不输出 | `备注：-` |
| 多行备注 | 以 `；` 压成一行 | 保留原始换行 |
| 产品编号 | 不出现 | 不出现 |
| 产品属性 | 不出现 | 不出现 |
| 采购备注 | 恒定一段：提示语[；自定义] | 恒定一段：提示语（红）+ 自定义（灰） |

### 4.4 备注归一化规则

复制文案使用统一压平函数，规则为：按 `\r?\n` 拆行 → 每行去首尾空白 → 行内连续空白折叠为单个半角空格 → 丢弃空行 → 用全角分号 `；` 连接。

图片货件区的内联备注使用同一规则，避免括号内出现换行导致产品名换成两三行、右侧「数量」看起来错位。图片产品明细块的 `备注：` 行保留原始换行。

判定空备注时以归一化后的结果为准，仅含空白字符视为空。

## 5. 功能需求

### R1：复制文案段落结构

**用户故事：** 作为采购人员，我希望复制出去的采购信息没有冗余标题和逐货件重复的提示，以便直接转发给供货方。

#### 验收标准

1. 当复制文案生成时，系统不应输出「出货请贴货物唛头：」这一行。
2. 当复制文案生成时，系统应在每个货件块输出「唛头：【基础唛头】后缀」，不得在行尾追加任何贴标提示。
3. 当采购单存在多个有效货件时，系统应按 `partNumber` 升序输出，货件块之间空一行。
4. 当采购单存在已取消货件时，该货件不得出现在复制文案中。
5. 当货件尚未派发唛头时，系统应输出「唛头：待派发」。

### R2：复制文案行备注

#### 验收标准

1. 当采购行有行备注时，系统应在该行「金额小计」之后输出「备注：归一化后的备注」。
2. 当采购行没有行备注时，系统不应输出任何备注行，也不应输出「备注：-」。
3. 当行备注包含换行时，系统应以 `；` 连接各非空行输出。

### R3：复制文案采购备注

#### 验收标准

1. 当复制文案生成时，系统应恒定输出采购备注段，内容以「采购备注：」开头。
2. 当采购单没有自定义备注时，该段内容仅为采购提示语。
3. 当采购单有自定义备注时，该段内容为采购提示语、全角分号、压平后的自定义备注。
4. 采购备注段应位于货件块之后，是复制文案的最后一段。

### R4：图片产品明细块

#### 验收标准

1. 当图片渲染产品明细时，系统不应渲染产品编号，也不应渲染「临时产品」占位。
2. 当图片渲染产品明细时，系统不应渲染产品属性行。
3. 当采购行没有行备注时，系统应渲染「备注：-」。
4. 当采购行有行备注时，系统应渲染「备注：xxx」，保留原始换行。
5. 备注值仅含空白字符时，系统应按空备注处理。

### R5：图片货件块与采购备注

#### 验收标准

1. 当图片渲染货件区产品行时，系统不应渲染产品编号前缀。
2. 当该产品有行备注时，系统应在产品名后以全角括号内联压平后的备注。
3. 当该产品没有行备注时，系统不应渲染空括号。
4. 当图片渲染货件块时，系统不应在唛头行后渲染贴标提示。
5. 当图片渲染时，系统应恒定渲染「采购备注」段：先渲染红色采购提示语，再在存在自定义备注时渲染灰色自定义备注。
6. 采购备注段的自定义备注应保持原始换行。

### R6：图片模板版本与草稿有效性

#### 验收标准

1. 当图片渲染规则变更后，系统应将图片模板版本从 `6` 升到 `7`。
2. 当版本升级后，升级前生成且未归档的图片草稿应失效，审核时返回 `PURCHASE_ORDER_IMAGE_STALE` 并提示重新生成。
3. 当图片已归档为采购单凭证时，该媒体资产不受版本升级影响。

### R7：容量与失败语义

#### 验收标准

1. 当采购单行数不超过 86 行时，系统应能生成单张图片。
2. 当采购单行数超过 86 行时，系统应返回 `PURCHASE_ORDER_IMAGE_TOO_LARGE`，并给出「采购单内容超过单张图片可读尺寸，请调整后重试」提示，不得产出被截断的图片。
3. 图片高度上限沿用现有 `MAX_HEIGHT`（画布坐标 12482），不提高媒体像素上限。

### R8：口径一致性

#### 验收标准

1. 唛头文本「【基础唛头】后缀」在复制文案、采购单图片、通知文本三处必须逐字一致，后缀由服务端同一函数生成。
2. 采购提示语在前端语言包与服务端常量中各存一份字面量；两侧代码不得跨依赖域引用。
3. 服务端文本构造必须有单测用例对齐前端复制文案的期望字符串。

### R9：通知变量的供应商名显示口径

**用户故事：** 作为采购人员，我希望通知里的供应商名和复制文案一致，避免把字典存储值直接发给供货方。

#### 验收标准

1. 当采购单使用字典供应商时，通知变量的 `vendorName` 应为字典显示名，与复制文案抬头一致。
2. 当采购单使用自定义供应商名时，`vendorName` 应为该自定义名称。
3. 当字典项已停用或无法解析时，`vendorName` 应回退为存储值，不得为空、不得抛错。
4. 采购审核通过、审核驳回、采购取消、采购完成四个发布点的取值口径必须一致。

## 6. 非功能需求

- 语言包改动限于 `purchase-review` 命名空间，不新增语种；该命名空间只有 `zh-cn.json`。
- 复制文案的金额继续按两位小数输出，不得因备注改动而改变现有金额格式化与占位语义。
- 语义上不改变复制行为本身（仍是读取已加载详情、一次剪贴板写入、失败提示）。
- 根治理的供应商残留白名单依赖 `purchase-review/zh-cn.json` 仍命中既有占位符；修改语言包时不得移除该占位符，也不得新增白名单条目之外的命中文件。

## 7. 验收清单

1. 复制文案完整示例与 4.1 逐字一致。
2. 采购单图片人工出图，核对 `备注：-`、无编号、无属性、货件块无提示语、采购备注红灰两行。
3. 多行备注在文案中压平为一行，在图片明细块保留换行，在图片货件区内联时被压平。
4. 86 行通过、87 行报 `PURCHASE_ORDER_IMAGE_TOO_LARGE`。
5. 版本升级后旧草稿审核被拦为 `PURCHASE_ORDER_IMAGE_STALE`。
6. 前端定向测试、服务端图片单测、根治理测试全部通过。
7. 审核通过后通知变量完整落库，多行文案未被变量长度上限截断。
8. 小助理收到文本与图片两条消息，文本换行和空行显示正确。
9. 字典供应商的通知供应商名为字典显示名，自定义供应商名保持原样。

## 8. 通知模板方案（B 方案，已批准）

### 8.1 结论

「采购审核通过」事件（`PURCHASE_REVIEW_APPROVED`，模板键 `purchase.review.approved`）已存在，但现有 8 个变量不足以表达本节定义的格式。要做成完整文案与采购单图片同发，需要新增变量并放开变量长度上限。

### 8.2 新增变量

| 变量 | 内容 | 备注 |
| --- | --- | --- |
| `productLines` | 产品块，每块 2-3 行，块间空行 | 与复制文案逐字一致 |
| `partMarks` | 货件块「货件-0N：名+名」与「唛头：【…】…」，块间空行 | 不含贴标提示 |
| `depositAmount` | 约定订金，两位小数 | 敏感变量 |
| `balanceAmount` | 约定尾款，两位小数 | 敏感变量 |
| `orderRemark` | `采购备注：提示语[；自定义]`，前置两个换行 | 恒定非空，不标记敏感 |

### 8.3 模板正文

```
【{{orderNo}}】
供应商：{{vendorName}}
采购日期：{{orderDate}}

[采购产品明细]
{{productLines}}

总价：{{totalAmount}}
订金：{{depositAmount}}
尾款：{{balanceAmount}}

{{partMarks}}{{orderRemark}}
```

`orderRemark` 自带前置空行，空值场景已不存在，因此无需求助模板条件表达。

### 8.4 硬上限

变量长度上限共有四处硬约束，必须同时放开，否则管理端存不进大值或发布时被静默截断：

| # | 位置 | 现值 | 目标值 |
| --- | --- | --- | --- |
| 1 | `MAX_NOTIFICATION_VARIABLE_LENGTH` | 200 | 1500 |
| 2 | 发布存储前的变量截断（跟随上一条常量） | 200 | 1500 |
| 3 | 模板变量 DTO 的 `maxLength` 上限 | 200 | 1500 |
| 4 | 管理端模板变量长度校验与提示文案 | 1–200 | 1–1500 |

`MAX_NOTIFICATION_TEMPLATE_LENGTH` 保持 2000 不变；超大单据会在正文末尾截断，属于已知边界。

### 8.5 图片附件

审核事务中归档的采购单凭证已作为来源 `purchase.orderImage` 传给通知服务，代码侧无需改动。要真正发出，需要在小助理渠道模板开启附件策略，并让渠道策略允许敏感内容，否则整张图片会被拦截且金额变量被脱敏。

### 8.6 已确认的决策

1. `vendorName` 改用字典显示名，口径见 8.7；这会改变既有模板中字典供应商的渲染文本，属于预期修正。
2. 变量长度上限取 1500。
3. `orderRemark` 不标记为敏感变量；`depositAmount`、`balanceAmount` 与 `totalAmount` 一致标记为敏感。
4. `MAX_NOTIFICATION_TEMPLATE_LENGTH` 暂不提高；小助理单条文本上限留待真机验证后再评估。

### 8.7 供应商名取值口径

`vendorName` 当前在四个发布点（审核通过、审核驳回、采购取消、采购完成）都取「自定义名称 ?? 字典存储值 ?? `—`」。改为：

1. 自定义供应商名：直接使用该名称。
2. 字典供应商：在发布事务内用字典查询服务解析采购供应商字典，取 `label` 作为显示名；字典项已停用或无法解析时回退为存储值。
3. 字典 code 常量目前在采购查询服务内是私有的，实施时改为导出复用，不新增第二份字面量。
4. 每次发布只多一次字典查询，且仅在存在字典值时发生。

## 9. 未决风险

1. 删除产品编号与产品属性后，同名产品或仅属性不同的产品在图片上无法区分。
2. 采购提示语在前端语言包、服务端渲染常量和通知变量构造三处各存一份字面量，存在口径漂移风险，只能靠服务端单测对齐前端期望字符串。
3. 图片版本升级会让在途待审核草稿全部失效，需要采购人员重新生成。
4. `vendorName` 改为字典显示名会改变既有通知模板的渲染文本。属于预期修正，但发布说明需要标注，避免运营误判为消息内容异常。
5. 通知发布在采购审核事务内执行。文本构造抛异常会回滚审核，因此构造器必须全字段兜底；`purchase-order-mutation.service.spec.ts` 的详情 fixture 目前只有订单 ID，正好可用于验证兜底行为。
