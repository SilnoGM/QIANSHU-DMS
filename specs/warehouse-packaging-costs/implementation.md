# 打木架费用提报与付款

## 业务范围

- 运营入口：千树运营工作台 → 仓储运输 → 到仓货件 → 已到仓 → 打木架。
- 财务入口：千树财务工作台 → 实收实付 → 打木架付款。
- 提报保存后进入待付款队列；财务查看固定的人民币提报金额，确认后记录已付款、付款人和付款时间。
- 首版记录付款确认事实；没有银行转账、资金账户流水、部分付款、修改金额或撤销付款流程。

## 提报规则

提报对象必须是已经入仓、有效且有关联销售订单的货件。归属人是关联销售订单的出单人。服务端读取货件、采购订单、销售订单及归属人，固定来源与人员身份，并保存单号和包装类型名称快照；人员名称沿用系统中的当前显示名称。客户端不能指定归属人或覆盖来源。

| 字段 | 规则 |
| --- | --- |
| 包装类型 | 使用 `warehouse.packaging_type` 的有效字典值；记录对应名称快照 |
| 包装厂商 | `CHENGXIN`（沙井·诚信木箱）或 `OTHER`（其他）；选择其他无需填写名称 |
| 金额 | 固定 `CNY`，大于零，输入最多两位小数；接口使用十进制字符串 |
| 包装完成截图 | 必填且一张，JPEG / PNG / WebP，最多 10 MiB |
| 报价截图 | 必填且一张，JPEG / PNG / WebP，最多 10 MiB |
| 备注 | 选填，最多 500 字 |

两张截图使用现有媒体资产存储，上传后在提报事务中建立正式引用。正式引用参与媒体保留约束，截图通过受权限保护的业务地址读取。关闭未提交弹窗留下的临时资产继续由现有媒体生命周期处理。

每次独立提报使用一个 UUID 幂等键。相同请求的网络重试返回原记录；同一键不能用于不同内容。同一货件允许独立的多次费用提报，不以货件编号强行合并。

## 付款规则

状态只有 `PENDING_PAYMENT`（待付款）和 `PAID`（已付款）。金额在提报后固定，付款确认只接收预期版本。服务端在事务内复核权限、记录状态和版本，保证并发付款只有一次成功，已付款记录不能被重复付款。

页面默认展示待付款，可切换已付款并查看付款人和时间。搜索和分页在服务端执行，状态计数由同一筛选范围计算。金额、人员、时间及截图分别沿用 `AmountDisplay`、`QsPersonDisplay`、`DateTimeDisplay` 和 `ImageGroup`。

## 权限与接口

三个权限默认仅授予 `system_admin`，允许通过现有角色权限维护分配给普通角色。界面隐藏仅改善体验，服务端是授权边界。

| 权限 | 用途 |
| --- | --- |
| `packaging-costs:create` | 上传截图、提交打木架费用 |
| `packaging-costs:read` | 财务列表、记录详情和截图读取 |
| `packaging-costs:pay` | 确认付款 |

接口前缀为 `/api/packaging-cost-requests`。

| 方法与相对地址 | 用途 |
| --- | --- |
| `GET /shipment-context/:shipmentId` | 以提报权限读取货件、单号、销售出单人和是否可提报，不要求读取整张销售订单 |
| `POST /images` | 临时上传一张截图，multipart 字段顺序为 `mediaType=IMAGE`、`file` |
| `POST /` | 保存提报，必须携带 `Idempotency-Key` |
| `GET /` | 按状态、关键词分页查询及返回状态计数 |
| `GET /:id` | 读取提报及付款状态 |
| `POST /:id/pay` | 按 `expectedVersion` 确认固定金额付款 |
| `GET /:id/images/:kind` | 私有截图内容，`kind` 为 `PACKAGING` 或 `QUOTATION` |
| `HEAD /:id/images/:kind` | 私有截图响应头 |

请求与响应的准确字段、错误码及权限组合以 Controller、DTO 和生成的 OpenAPI 为准。
