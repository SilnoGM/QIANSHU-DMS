# 通用订单产品明细编辑与产品选择器需求规格

## 1. 文档状态

- 状态：Phase 1-Phase 4 已完成，自动化、真实浏览器与用户手动验收已通过
- 业务口径确认日期：2026-08-23
- Phase 1 确认日期：2026-08-23
- Phase 2 确认日期：2026-08-23
- Phase 3 确认日期：2026-08-23
- 适用应用：`web/apps/qsmds-arco`
- 首个接入页面：`/operations/sales-orders/create`
- 关联基线：`specs/sales-order-domain/requirements.md`
- 目标组件：`QsProductSelector`、`QsOrderProductLineEditor`

## 2. 背景与目标

现有新增销售订单页已经支持数据库产品和仅用于本订单的临时产品，但数据库产品仍在明细行内搜索，难以同时浏览主图、按供应商筛选、批量选择并识别已存在的订单明细；明细表也将销售语义与表格结构耦合，不利于后续采购订单复用。

本需求建立两个职责分离的 Web 业务组件：

- `QsProductSelector`：搜索、筛选和批量选择全部有效数据库产品，并按订单币种返回可空标准价；调用方已有数据库产品投影为右侧已选清单，会话可产生新增、累计加量或删除变更。
- `QsOrderProductLineEditor`：以业务中立的订单产品明细编辑器承载数据库产品、临时产品、数量、成交单价、行小计、备注、删除和汇总，并由销售订单调用方注入销售语义。

首期只接入新增销售订单的“产品与销售”步骤。采购订单接入、采购领域模型和采购校验不属于本期；通用组件不得因首个调用方是销售订单而写死销售领域名称或权限。

## 3. 用户故事

### 3.1 销售人员

作为销售人员，我希望在固定订单币种下按产品名称、编号和供应商浏览数据库产品，查看主图并批量选择，以便快速建立准确的订单明细。

### 3.2 订单录入人员

作为订单录入人员，我希望系统识别已经存在于明细表中的产品，并让我选择是否增加原行数量，避免同一数据库产品形成重复明细行。

### 3.3 业务组件维护者

作为业务组件维护者，我希望产品明细编辑器使用业务中立的名称和契约，由销售或采购调用方提供字段标题与领域映射，以免复制表格、空态、金额和交互逻辑。

## 4. 已确认业务决策

1. 产品选择弹窗左侧分为搜索筛选、产品列表和统计三部分，右侧同步显示明细表中的数据库产品及本次会话新增产品。
2. 供应商筛选默认“全部供应商”，可切换至具体供应商。
3. 产品卡片左侧显示主图，右侧显示加大加粗的产品名称和次级产品编号。
4. 左侧底部“产品总数”表示当前关键词和供应商条件下全部有效产品的匹配总数，订单币种不参与产品资格筛选。
5. 产品列表采用滚动加载下一页，筛选和分页变化不得丢失本次选择状态。
6. 产品选择弹窗必须读取打开时产品明细表中的数据库产品及数量。
7. 已存在或本次已选择的数据库产品不得新增重复行；用户每次确认“增加数量”后累计数量 `+1`，不得形成重复明细行。
8. 新增、加量和删除变更只在产品选择器最终确认时原子写入明细；取消或关闭弹窗必须回滚本次会话，保持明细不变。
9. 产品明细默认是空表格，顶部提供“添加数据库产品”和“添加临时产品”两个入口。
10. 通用明细编辑组件命名为 `QsOrderProductLineEditor`，不得命名为销售订单专用组件。
11. 临时产品编号固定显示“仅本订单”，首版不支持临时产品主图。
12. 产品名称和备注均不换行；溢出时省略，Hover 或键盘聚焦 Tooltip 显示完整内容。
13. 销售订单继续执行一单一币种、数量正整数、成交总价等式和服务端重新计算等既有硬校验。
14. 产品选择不限制币种或当前币种标准价；缺少当前币种标准价时显示“暂无”，本单售价默认 `0.00` 并要求用户填写，不得套用任何标准价。

## 5. 术语与状态口径

### 5.1 数据库产品

由产品域持久化、具有稳定 `productId` 和产品编号的产品。销售订单可以选择全部 `ACTIVE` 数据库产品，是否具有当前订单币种标准价不影响候选资格。

### 5.2 临时产品

只存在于当前订单明细中的自定义产品，不写入产品域。临时产品没有数据库 `productId`、产品编号、主图或标准价。

### 5.3 已有明细快照

产品选择弹窗每次打开时，从 `QsOrderProductLineEditor` 读取的当前数据库产品明细集合。至少包含稳定产品 ID、明细行身份和当前数量；临时产品不参与数据库产品重复判断。

### 5.4 选择会话变更

- `ADD`：把尚不存在于明细中的数据库产品按会话累计数量新增为一行。
- `INCREMENT`：把已存在数据库产品的原明细行数量增加会话累计的正整数增量。
- `REMOVE`：从明细中删除已存在的数据库产品；临时产品不进入选择器同步范围。

右侧清单是应用上述变更后的数据库产品明细投影，不是操作日志。变更只属于当前弹窗会话；取消或关闭时必须清空，重新打开时重新读取最新明细。

### 5.5 产品总数

产品总数是 Server 在 `ACTIVE`、关键词和供应商组合条件下返回的匹配记录总数，不是当前已加载卡片数，也不是已选择数；订单币种不改变该总数。

## 6. 设计规格

### 6.1 Purpose Statement

界面用于高密度订单录入场景，在一个弹窗内完成产品发现、重复识别和批量选择，并在明细编辑器中保持价格、数量和汇总关系清晰。视觉优先保证业务信息密度、状态可辨识和键盘可操作性，不建立与现有 qianshu-dms 脱节的新视觉系统。

### 6.2 Aesthetic Direction

采用 `Industrial/utilitarian`：明确边界、稳定对齐、克制装饰，以主图和状态反馈辅助识别，不使用营销式大卡片、装饰性渐变或 Emoji。

### 6.3 Color Palette

- 页面与弱背景：`#F6F7F8`
- 内容背景：`#FFFFFF`
- 主要文字：`#1D2129`
- 主操作及选中强调：`#00B42A`
- 错误及危险操作：`#F53F3F`

实现必须优先使用项目现有亮色/暗色主题 Token，不得把上述 Hex 作为绕过主题系统的局部硬编码。

### 6.4 Typography

沿用项目现有 `Noto Sans SC`、`Noto Sans TC`；金额和数量使用项目既有数据排版能力与等宽数字，不额外引入字体。

### 6.5 Layout Strategy

- 产品选择弹窗在桌面端采用左宽右窄的非对称分栏；左侧结果区是主任务面，右侧已选清单是核对与同步操作面。
- 左侧内部采用顶部固定检索、中部独立滚动、底部固定统计的纵向结构。
- 明细编辑器使用高密度语义化表格和表格区域横向滚动，不让宽表导致页面级横向溢出。
- 窄屏时产品选择器改为单列顺序布局，先检索与结果、后已选清单；功能和状态不得减少。

## 7. 功能需求与验收标准

### R1 - 组件分层与复用边界

**User Story：** 作为组件维护者，我希望产品选择与明细编辑职责清晰，并为后续订单域复用保留稳定边界。

#### Acceptance Criteria

1. 当正式应用需要选择数据库产品时，Web 应提供名为 `QsProductSelector` 的业务组件。
2. 当正式应用需要编辑订单产品明细时，Web 应提供名为 `QsOrderProductLineEditor` 的业务组件。
3. 当组件组织到项目中时，系统应将两个组件放入 `components/business` 并由调用方显式导入。
4. 当销售订单接入明细编辑器时，调用方应提供销售字段标题、订单币种、金额目录、已有明细、错误状态和领域 DTO 映射，不得要求通用组件直接读取销售订单页面 Store 或路由。
5. 当未来采购订单复用明细编辑器时，组件应允许调用方替换参考单价、成交单价和汇总标题；本期不得实现采购订单页面、采购接口或采购领域校验。
6. 当组件处理产品与明细时，组件不得派发订单编号、持久化订单、修改产品主数据或替代调用方的最终领域校验。

### R2 - 销售订单固定币种与产品展示资格

**User Story：** 作为销售人员，我希望订单保持单一币种，但产品选择不受币种标准价限制，同时避免误用另一币种价格。

#### Acceptance Criteria

1. 当销售订单打开产品选择器时，调用方应把进入新增页前已固定的 `TWD` 或 `MYR` 币种传入选择器。
2. 当订单币种为 `TWD` 时，产品选择器应返回全部 `ACTIVE` 产品；具有 TWD 标准价时只返回 TWD 标准价，否则返回 `null`，不得展示或套用 MYR 标准价。
3. 当订单币种为 `MYR` 时，产品选择器应返回全部 `ACTIVE` 产品；具有 MYR 标准价时只返回 MYR 标准价，否则返回 `null`，不得展示或套用 TWD 标准价。
4. 当产品选择器打开时，界面不得提供订单币种切换入口。
5. 当产品在选择后、订单保存前失去 `ACTIVE` 状态或不存在时，服务端保存硬校验应拒绝该产品；仅缺少对应币种标准价不得拒绝保存。
6. 当产品缺少当前订单币种标准价时，明细标准价应显示“暂无”，本单售价应以 `0.00` 初始化并由用户手填；正式保存时标准价快照为 `null`。
7. 当产品查询用于新增销售订单时，系统应使用 `sales-orders:create` 的授权边界，不得额外要求录单用户具有产品管理权限。

### R3 - 产品选择弹窗信息架构

**User Story：** 作为销售人员，我希望在一个结构稳定的弹窗中完成筛选、浏览和核对待添加产品。

#### Acceptance Criteria

1. 当用户点击“添加数据库产品”时，系统应打开包含 `QsProductSelector` 的产品选择弹窗。
2. 当桌面端弹窗打开时，弹窗左侧应为产品检索区，右侧应为已选择及待增量产品清单，且左侧宽于右侧。
3. 当左侧检索区渲染时，其顶部应显示关键词搜索框和供应商下拉选择器，中部应显示产品卡片列表，底部应显示产品总数。
4. 当供应商下拉首次渲染时，系统应默认选择“全部供应商”，且不得提交具体 `supplierValue` 条件。
5. 当明细中没有数据库产品且本次会话也未新增产品时，右侧应显示明确空态，不得复用产品查询空态。
6. 当弹窗处于打开状态时，调用方明细不得在背景中被直接编辑。

### R4 - 产品搜索、供应商筛选与分页

**User Story：** 作为销售人员，我希望按名称、编号和供应商组合筛选，并能连续浏览大量产品。

#### Acceptance Criteria

1. 当用户输入产品关键词时，产品选择器应按产品名称或产品编号执行不区分大小写的包含匹配。
2. 当用户输入关键词时，组件应在短暂防抖后发起最终查询；当用户按 Enter 时，应立即提交当前关键词查询。
3. 当用户选择具体供应商时，产品选择器应使用该供应商的稳定字典 `value` 精确筛选，不得用 Label 或 UUID 查询。
4. 当关键词和供应商同时存在时，系统应按 `ACTIVE`、关键词和供应商的 AND 关系查询；订单币种只决定返回哪一币种的可空标准价。
5. 当用户切换关键词或供应商时，产品列表应回到第一页、清除旧结果所有权并加载新结果。
6. 当旧查询在新查询之后返回时，组件不得用旧结果、旧总数或旧错误覆盖当前状态。
7. 当用户滚动到结果区底部且仍有下一页时，组件应加载下一页并追加结果，不得清空已经加载的当前查询结果。
8. 当下一页正在加载时，组件不得重复请求同一页。
9. 当筛选条件或分页变化时，当前弹窗会话中的已选投影与变更状态应保留。
10. 当当前条件可信加载完成时，左侧底部应显示 Server 返回的匹配总数，而不得使用当前已加载卡片长度代替。
11. 当产品所属供应商是可读取的历史停用值时，供应商筛选应遵守既有产品读取筛选语义并清晰标识历史状态，不得静默把稳定值映射到其他供应商。

### R5 - 产品卡片展示与选择状态

**User Story：** 作为销售人员，我希望通过主图、名称和编号快速识别产品，并明确知道产品是否已在明细中。

#### Acceptance Criteria

1. 当产品卡片渲染时，卡片左侧应显示产品主图，右侧上方应显示加大加粗的产品名称，右侧下方应显示产品编号。
2. 当产品没有可用主图或主图加载失败时，卡片应显示稳定占位图，不得显示损坏图片图标或空 URL。
3. 当产品尚未存在于明细且尚未加入本次已选清单时，卡片应显示可选择的普通状态。
4. 当产品已经加入待新增清单时，卡片应显示明确选中状态，且不得只依靠颜色表达。
5. 当产品已存在于明细表时，卡片应显示“已在明细中”和当前数量，不得伪装为普通未选产品。
6. 当同一产品在滚动分页结果中意外重复出现时，组件应按稳定 `productId` 合并交互身份，不得产生两个独立选择状态。
7. 当用户仅使用键盘时，应能聚焦产品卡片、识别其状态并触发与指针点击相同的选择行为。

### R6 - 读取已有明细与重复产品处理

**User Story：** 作为订单录入人员，我希望选择器读取当前明细并把重复选择转换为数量增加，而不是创建重复行。

#### Acceptance Criteria

1. 当产品选择弹窗每次打开时，`QsOrderProductLineEditor` 应向选择器提供当时最新的数据库产品明细及数量快照。
2. 当选择器建立已有产品索引时，系统应按稳定 `productId` 判断重复，不得按产品名称、编号或数组位置判断。
3. 当已有明细包含临时产品时，选择器应忽略该临时产品的重复判断，因为临时产品没有数据库 `productId`。
4. 当用户选择已存在于明细的数据库产品时，系统应弹出确认提示“产品已存在，是否增加数量？”。
5. 当用户取消重复产品确认时，系统不得新增会话变更或修改投影数量。
6. 当用户确认重复产品时，系统应把该产品的会话数量累计 `+1`，不得新增重复明细行。
7. 当用户在一次会话中多次选择同一已选产品并确认时，每次确认均应累计 `+1`，右侧立即显示确认后的预期数量。
8. 当右侧展示已选产品时，应显示产品身份、来源状态和应用会话变更后的数量。
9. 当用户从右侧移除产品时，系统应同步恢复左侧卡片状态；若产品来自已有明细，最终确认后应从明细表删除该产品。
10. 当被移除的已有产品在左侧再次选中时，系统应撤销删除并恢复已选状态；再次选择后仍可继续确认增加数量。
11. 当弹窗关闭后再次打开时，选择器应重新读取最新明细，不得沿用上次弹窗会话的已有明细索引或会话变更。

### R7 - 已选清单同步与原子确认

**User Story：** 作为销售人员，我希望在选择器中核对最终数据库产品清单，再一次性同步到明细。

#### Acceptance Criteria

1. 当选择器打开时，右侧应先显示当前明细表中的全部数据库产品及数量，临时产品不显示。
2. 当用户选择尚不存在的数据库产品时，系统应把该产品加入右侧清单；再次选择时先询问是否增加数量，不创建重复项。
3. 当右侧清单包含原明细和本次新增产品时，系统应分别显示“已有明细”与“新增”来源状态。
4. 当用户移除右侧任一产品时，系统应同步恢复左侧卡片状态，并在会话中登记对应取消新增或删除已有产品语义。
5. 当会话相对打开时明细没有新增、加量或删除差异时，“确认添加”按钮应不可提交。
6. 当用户点击“确认添加”时，系统应一次性把所有 `ADD`、`INCREMENT` 和 `REMOVE` 变更交给明细编辑器应用。
7. 当明细编辑器应用 `ADD` 变更时，每个数据库产品应只新增一行；本单售价统一以 `0.00` 初始化，不得复制标准价，并使用会话累计数量。
8. 当明细编辑器应用 `INCREMENT` 变更时，应按累计正整数增量更新目标原行，并保持本单售价和备注不变。
9. 当明细编辑器应用 `REMOVE` 变更时，应只删除对应数据库产品行，不影响临时产品或其他明细。
10. 当任一变更无法对应可信产品或可信原明细行时，系统应拒绝整批确认并保留可恢复错误，不得部分应用其余变更。
11. 当全部变更成功应用时，系统应关闭产品选择弹窗并清空当前弹窗会话状态。
12. 当用户点击取消、关闭按钮或按 Escape 关闭弹窗时，系统应丢弃全部会话变更，明细表保持打开弹窗前的状态。

### R8 - 明细编辑器入口与空态

**User Story：** 作为订单录入人员，我希望明确选择数据库产品或直接创建临时产品，并从空表开始录入。

#### Acceptance Criteria

1. 当 `QsOrderProductLineEditor` 首次渲染且调用方没有明细时，组件应显示空表格及稳定空态，不得自动插入空白行。
2. 当组件顶部操作区渲染时，应按“添加数据库产品”“添加临时产品”提供两个独立按钮。
3. 当用户点击“添加数据库产品”时，组件应打开产品选择弹窗，不得在明细行内显示数据库产品搜索框或搜索按钮。
4. 当用户点击“添加临时产品”时，组件应直接在表格尾部新增一行临时产品，不得打开产品选择弹窗或写入产品域。
5. 当明细数量达到销售订单既有上限时，两个新增入口应停止继续添加并提供明确原因。
6. 当订单正在提交或调用方禁用编辑时，新增、编辑、删除和打开选择器操作均应禁用。

### R9 - 明细表列、字段行为与删除

**User Story：** 作为订单录入人员，我希望一行对应一个产品，并在同一表格中完成成交信息录入。

#### Acceptance Criteria

1. 当明细表渲染时，应按“产品来源、产品编号、产品名称、产品主图、标准价、本单售价、产品数量、本单售价小计、备注、删除操作”顺序显示列。
2. 当行来源为数据库产品时，产品来源、编号、名称、主图和标准价应只读；本单售价、数量和备注应可编辑。
3. 当行来源为临时产品时，产品来源应固定显示“临时产品”，产品编号应固定显示“仅本订单”，产品名称、本单售价、数量和备注应可编辑。
4. 当行来源为临时产品时，产品主图和标准价列应显示 `—`，不得提供临时主图上传或伪造标准价。
5. 当数据库产品没有可用主图或主图加载失败时，主图列应显示稳定占位状态。
6. 当产品行已经建立时，组件不得允许在行内把数据库产品与临时产品相互切换来源。
7. 当用户输入本单售价时，组件应只接受当前调用方币种下的非负有效金额，最多两位小数；新建数据库产品行和临时产品行均默认 `0.00`。
8. 当用户输入产品数量时，组件应只接受正整数。
9. 当用户编辑备注时，组件应使用单行文本输入并遵守既有订单明细说明长度上限。
10. 当用户点击行尾删除图标时，组件应删除该行并立即重新计算汇总；删除未保存行不得产生产品域或订单域写请求。
11. 当删除操作以图标呈现时，应使用项目现有 Lucide/FaIcon，并为图标按钮提供包含行序和产品名称的可访问名称。

### R10 - 行小计、标准价汇总与本单售价汇总

**User Story：** 作为销售人员，我希望同时比较标准价格价值和本单实际成交价值，并保持最终金额校验可信。

#### Acceptance Criteria

1. 当数据库产品行的数量变化时，系统应按“当前币种标准单价 × 数量”更新该行标准价贡献。
2. 当任一产品行的本单售价或数量变化时，系统应按“本单售价 × 数量”更新该行本单售价小计。
3. 当明细表底部渲染时，应显示“标准价汇总”和“本单售价汇总”。
4. 当计算标准价汇总时，系统应累加所有数据库产品的“标准单价 × 数量”；临时产品不参与标准价汇总。
5. 当没有数据库产品时，标准价汇总应以订单币种显示零值，而不得伪造临时产品标准价。
6. 当数据库产品缺少当前币种标准价时，该行不得计入标准价汇总，并应在汇总区域提示未计入的产品数量。
7. 当计算本单售价汇总时，系统应累加数据库产品和临时产品全部有效行的“本单售价 × 数量”。
8. 当展示行小计和两项汇总时，系统应统一使用调用方固定币种，并使用项目既有金额格式化组件。
9. 当 Web 计算展示金额时，应使用现有十进制安全逻辑，不得依赖 JavaScript 二进制浮点数作为最终结果。
10. 当销售订单进入下一步时，既有“手填销售总价 = 本单售价汇总”和“定金 + 尾款 = 销售总价”硬拦截应继续执行。
11. 当正式提交销售订单时，Server 应继续重新计算明细小计和金额等式，不信任组件汇总结果。

### R11 - 表格宽度、单行溢出与 Tooltip

**User Story：** 作为订单录入人员，我希望表格列稳定可读，并能查看较长产品名称和备注的完整内容。

#### Acceptance Criteria

1. 当桌面表格宽度超过可用内容区时，横向滚动应限制在明细表区域，不得造成页面级横向溢出。
2. 当定义列宽时，每列应提供与其控件和常规业务内容匹配的固定宽度或最小宽度，不得把输入框压缩到不可操作。
3. 当产品名称超过其列宽时，单元格应保持单行、显示省略号，并在 Hover 或键盘聚焦时通过 Tooltip 显示完整名称。
4. 当备注内容超过其列宽时，备注区域应保持单行，并在 Hover 或键盘聚焦时通过 Tooltip 显示完整备注。
5. 当备注处于编辑状态时，输入控件应保持单行；用户还应能通过横向文本滚动或选择文本访问完整值。
6. 当 Tooltip 显示完整内容时，Tooltip 不得修改原值、截断复制内容或成为触屏用户读取已输入值的唯一方式。
7. 当金额、数量、产品编号或来源列渲染时，应保持单行并使用稳定对齐，避免行高因内容变化而跳动。

### R12 - 加载、错误、空态与会话恢复

**User Story：** 作为销售人员，我希望在查询延迟或失败时清楚知道当前状态，并能安全重试而不丢失选择。

#### Acceptance Criteria

1. 当产品首屏正在加载时，产品列表区应显示加载状态，同时保留顶部检索和右侧已选清单的稳定布局。
2. 当当前筛选条件没有匹配产品时，产品列表区应显示“没有符合条件的产品”空态，底部产品总数应为 `0`。
3. 当产品查询失败时，组件应显示安全错误文本和重试入口，不得把失败显示为无产品。
4. 当下一页加载失败时，组件应保留已加载结果、产品总数和已选清单，并允许只重试失败页。
5. 当供应商目录加载失败时，组件应保持关键词产品查询可用并提供供应商筛选重试，不得把失败伪装成“全部供应商”已可信加载。
6. 当用户重试产品或供应商加载时，组件不得清除已有明细快照、已选投影或当前会话变更。
7. 当身份、权限或调用方币种在弹窗会话期间失效时，组件应失败关闭提交能力并清除不再可信的候选数据。

### R13 - 响应式、主题与无障碍

**User Story：** 作为使用不同视口或辅助技术的录入人员，我希望完整操作产品选择和明细编辑流程。

#### Acceptance Criteria

1. 当桌面视口足以容纳分栏时，产品选择弹窗应使用左宽右窄布局，并分别保持结果区和已选区清晰边界；弹窗使用局部最大宽度容纳长产品名称。
2. 当视口不足以容纳双栏时，弹窗应切换为单列顺序布局，且检索、结果、统计、已选清单和确认操作均不得消失。
3. 当窄屏展示产品明细时，组件应保留语义化表格和表格内横向滚动，不得静默隐藏业务列。
4. 当界面处于暗色主题时，卡片选中、已有明细、错误、空态、表格边界和 Tooltip 应保持可读对比度。
5. 当用户仅使用键盘时，应能打开和关闭弹窗、操作搜索与供应商筛选、滚动或加载结果、选择产品、处理重复确认、移除已选项、确认添加并编辑明细。
6. 当弹窗打开时，焦点应进入弹窗并受约束；关闭后焦点应回到“添加数据库产品”按钮。
7. 当 Tooltip 用于完整内容时，触发元素应可聚焦并关联正确的可访问描述。
8. 当产品主图渲染时，应提供与产品名称一致或等价的替代文本；装饰性占位图应避免重复朗读。
9. 当用户启用 Reduced Motion 时，组件应停止非必要动画，但不得移除加载和状态反馈。
10. 当界面展示图标时，应使用项目现有 Lucide/FaIcon，不得使用 Emoji。

### R14 - 权限、安全、数据边界与交付门禁

**User Story：** 作为系统维护者，我希望组件扩展不突破销售订单权限、产品域和规格确认边界。

#### Acceptance Criteria

1. 当产品选择器请求销售订单候选产品时，Server 应校验 `sales-orders:create`，不得因组件复用而放宽为匿名读取。
2. 当候选产品响应返回时，只应包含完成产品识别、筛选、当前币种标准价和主图展示所需的最小字段，不得返回采购成本或另一币种售价。
3. 当搜索关键词、供应商筛选或分页状态变化时，这些查询状态不得写入销售订单创建 DTO、持久化 Store、URL、日志或审计事件。
4. 当组件显示产品主图时，应继续使用既有受保护媒体访问边界，不得把本地文件路径、存储密钥或私有对象地址暴露给浏览器。
5. 当本期需求实施时，不得新增采购订单 Schema、API、权限、导航或页面，不得修改订单发号时机。
6. 当本期需求实施时，除非 Phase 2 技术方案证明现有契约无法满足并再次获得确认，否则不得新增数据库 Schema 或 migration。
7. 当 OpenAPI 契约确需扩展时，应从 Server DTO 和 decorators 修改并通过既有契约生成流程同步 Web 类型，不得手工编辑生成产物。
8. 当进入正式实施时，应先建立覆盖筛选、分页状态、重复产品数量增加、原子确认、空表、金额汇总和 Tooltip 的必要聚焦测试，再进行最小实现。
9. 当进行浏览器验收时，应通过真实交互验证固定币种筛选、供应商筛选、跨页选择、重复产品确认、取消无副作用和写入明细，不得只以源码或单元测试代替。
10. 当 Phase 1 文档尚未获得用户确认时，不得创建技术设计、任务清单或实施代码。

## 8. 首期范围

### 8.1 本期包含

- 新增 `QsProductSelector` 业务组件。
- 新增 `QsOrderProductLineEditor` 通用订单产品明细编辑器。
- 将新增销售订单“产品与销售”步骤接入两个组件。
- 产品关键词搜索、供应商筛选、滚动分页、产品总数和主图卡片。
- 已有明细读取、重复产品累计加量、右侧已选清单、删除同步和原子确认。
- 数据库产品与临时产品表格、行小计、标准价汇总和本单售价汇总。
- 单行省略、Tooltip、横向滚动、主题、响应式与键盘交互。
- 为实现上述契约所必需的最小销售订单候选产品查询契约扩展。

### 8.2 本期不包含

- 采购订单页面、采购单据模型、采购价格规则或采购权限。
- 临时产品写入产品主数据、临时产品编号或临时产品主图上传。
- 在明细行内搜索或切换数据库产品。
- 允许同一数据库产品形成多条销售订单明细。
- 同时显示、换算或套用 TWD 与 MYR 标准价。
- 产品新增、编辑、上下架、供应商维护或媒体维护。
- 改变销售订单金额等式、发号时机、客户、凭证或状态模型。
- 改变组件边界以外的采购订单、产品主数据或销售订单核心业务规则。
