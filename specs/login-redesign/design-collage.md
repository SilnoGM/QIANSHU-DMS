> 状态：已实施（2026-10-19）；第四版已接入 `/login`，旧登录页与旧表单保留未改。<br>
> 日期：2026-10-19。<br>
> 原型：[`prototype-collage.html`](./prototype-collage.html)。<br>
> 参考：用户提供的「千树数据管理系统 - 登录原型 v3」HTML。<br>

## 1. 方向

这一版基于用户提供的 HTML，保留它的核心构图和氛围：

- 薄荷绿渐变全屏背景 + 左下角淡圆弧。
- 顶部品牌栏：左上 Logo + 产品名，右上系统信息胶囊。
- 主区 7:5 左右布局：左侧是一组「微缩业务 UI 拼贴」，右侧是悬浮登录卡。
- 拼贴包含：竖向业务图标栏、中央模拟系统窗口（产品流转与资金同频 / 业务协同与财务一体 + 四个业务卖点）、右上「已入库」小卡、左下数据可视化卡、右下「已核算」小卡、虚线 + 加号 + 鼠标指针。
- 登录卡使用大圆角、柔和绿色阴影、填充式输入、绿色主按钮和「忘记密码？」轻提示；卡内不再放 Logo。

这一版与前三版的差异：

| 维度 | 分栏版 | 居中档案版 | 悬浮画布版 | 业务拼贴版 |
| --- | --- | --- | --- | --- |
| 主体 | 左右贴边 | 单列文档 | 两块悬浮卡 | 左微缩 UI 拼贴 + 右悬浮登录卡 |
| 背景 | 绿色渐变 + 点阵圆环 | 白底网格 + 文字水印 | 全屏浅/深绿画布 + 等高线 | 薄荷绿渐变 + 左下圆弧 |
| 品牌 | Slogan 面板 | 文档头 | 业务链路卡 | 模拟系统窗口 + 四个卖点 |
| 卡片 | 12px 白色卡 | 无卡 | 24px 双卡 | 24px 登录卡 + 多个装饰小卡 |
| 输入 | 44px 描边 | 48px 下划线 | 48px 填充 | 48px 填充、12px 圆角 |
| 按钮 | 绿色 6px | 黑/白 6px | 绿色胶囊 | 绿色 12px + 阴影 |
| 气质 | 企业门户 | 技术档案 | 沉浸式画布 | 产品介绍 / 概念拼贴 |

## 2. 对参考稿的取舍

参考稿里有几项内容与当前登录任务约束冲突或需要工程化调整，本版按以下方式处理：

| 参考稿 | 本版处理 |
| --- | --- |
| Tailwind CDN、Google Fonts | 改为项目现有纯 CSS + 本地 Noto Sans SC / Mono；不新增 UI 库、不请求外部字体 |
| 自定义 Q 形树 Logo | 改为项目真实 Logo `web/apps/qsmds-arco/src/assets/images/logo.svg`，顶部品牌与拼贴窗口使用同一图片；登录卡顶部 Logo 已移除 |
| 右上「系统状态：正在运行 v0.8.4」 | 接入真实 `GET /api/health`：200 且 `status=ok` 显示「系统运行正常」，503/网络异常显示「系统运行异常」，首次请求期间显示「系统状态检测中」；每 30 秒刷新，不弹全局错误 Toast |
| 记住账号 / 忘记密码 | 记住账号**不实现**；忘记密码新增为**仅提示动作**：点击后轻提示「请联系管理员重置！」，不发起重置接口、不跳转页面 |
| placeholder-only 输入 | 增加可见 label 与必填标识，保留参考稿的填充式外观 |
| 按钮“登 录” | 沿用当前统一文案「登录系统」 |
| 顶部/右侧大段装饰文案 | 拼贴保留，但整体 `aria-hidden`，不参与屏幕阅读器 |
| 浮动动画 | 保留轻微 5px / 8–10s 漂浮；`prefers-reduced-motion` 下关闭 |

### 3.2 响应式

- `< 1200px`：隐藏左侧拼贴，登录卡居中；薄荷绿画布、顶部品牌栏、底部版权保留。这个断点高于框架的 1024px，是因为拼贴是绝对布局，需要更宽的空间。
- `< 640px`：顶部品牌栏缩为 46px 直接展示的 Logo + 20px 产品名 + 10px `QIANSHU DMS` 副标；状态胶囊显示短文案「正常/异常/检测中 · v0.8.4」；登录卡内边距 28px、圆角 20px。
- 390×780 实测：卡片 `358×448px`，距页面顶部 206–654px，页脚 718–778px；无横向溢出，登录按钮在首屏内。
- 拼贴的浮动动画在窄屏不加载（拼贴隐藏）；登录卡本身静止。

## 5. 交互与反馈

行为与前三版一致：

- 账号、密码只校验必填；登录页不校验 8–20 密码长度；密码保留 20 字符上限。
- blur 校验当前字段；submit 校验全部并聚焦首个错误；字段错误随输入恢复。
- 账号空「请输入账号」；密码空「请输入密码」；401 展示「账号或密码错误」（服务端错误码不变）。
- 429/503/网络错误放在登录卡全局 callout；结果未知提供「检查登录状态」和检查中状态。
- 提交时按钮、输入框、密码可见性按钮禁用；按钮「登录中…」+ spinner；`aria-busy`；loading 防重复。
- 密码可见性常显，带 `aria-label`/`aria-pressed`；清空后复位。
- 真实 `<form>` 回车提交；密码可见性按钮 `type="button"`。
- 「忘记密码？」是 `type="button"`，只显示轻提示「请联系管理员重置！」，不提交表单、不跳转、不调用重置接口；提示 2.6s 自动消失。
- 记住账号不实现；卡内不再显示「仅限内部授权人员使用」。

## 8. 适用判断

- 希望登录页更像产品介绍页、有明确的「业务全景」氛围：业务拼贴版最合适。
- 希望品牌感强但更沉浸、少装饰：悬浮画布版。
- 希望稳重、企业门户：分栏版。
- 希望技术文档感、最低装饰：居中档案版。

## 9. 实施后的剩余事项

1. 共享 `FaInput` 密码可见性按钮仍未修复：内置眼睛只在有值时出现，且没有 accessible name、清空后 `type` 可能保持 text。当前实现沿用内置行为，未改共享组件。
2. 「忘记密码？」使用现有 `QsToast`，实际显示在顶部居中，不是原型里的底部胶囊；如果必须完全复刻底部位置，需要单独评估提示层改动。
3. 左侧拼贴文案与 12–18px 漂浮动效可按实际业务口径继续微调；不影响登录逻辑。

## 11. 健康检查与启动页说明

### 健康检查

- 这版**已经接入真实健康检查**，不是静态标签：登录页进入时请求 `GET /api/health`，之后每 30 秒刷新。
- 200 且响应 `status === 'ok'` → `系统运行正常`；503 或网络失败 → `系统运行异常`；首次请求返回前 → `系统状态检测中`。
- 健康检查失败不会弹全局 Toast，也不会阻塞登录；它只是右上角状态提示。
- 当前 `/api/health` 由 NestJS Terminus + `DatabaseHealthIndicator` 实现，检查的是 **API 与数据库健康状态**，不是所有下游依赖的完整体检。
- 桌面显示完整「系统运行正常/异常 · v0.8.4」；窄屏显示短文案「正常/异常/检测中 · v0.8.4」，完整文案保留在 `aria-label`。

### 登录后启动页

- 登录成功由全局 `useAppStartup().run()` 接管：先展示 `AppStartupSplash`，同时立即执行 `router.push(redirect)`。
- 最短停留随机 `1500–2000ms`；如果路由/工作台实际加载更久，启动页继续保留，不会提前撤场；完成后 180ms 淡出。
- 启动页复用现有「正在准备工作台」的视觉语言：真实 Logo、产品名、版本、进度条、条纹背景和版权；不是新的独立路由。
- 通过 `createStartupMinimumDuration` 随机函数和 `run` 的「导航 + 最短时长」等待逻辑测试；真实账号登录成功路径仍需浏览器认证套件/人工回归。
