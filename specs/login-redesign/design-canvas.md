> 状态：第三方案原型，待选择；与分栏版、居中档案版并存。<br>
> 日期：2026-10-19。<br>
> 原型：[`prototype-canvas.html`](./prototype-canvas.html)。<br>
> 对照方案：[`design.md`](./design.md) / [`prototype.html`](./prototype.html)；[`design-centered.md`](./design-centered.md) / [`prototype-centered.html`](./prototype-centered.html)。<br>
> 第四版「业务拼贴版」：[`design-collage.md`](./design-collage.md) / [`prototype-collage.html`](./prototype-collage.html)。

## 1. 方向

这一版是 **全屏画布 + 左右双栏悬浮式布局**：

- 整个视口铺满浅绿/深绿画布，叠加平滑等高线纹理和边缘渐暗。
- 内容不是贴边的左右分栏，而是两块 **悬浮卡片**：左侧深绿品牌/业务链路卡，右侧白色登录卡；两卡之间、卡片与视口四边都留有画布可见的间距。
- 卡片使用 24px 圆角、较大投影和独立表面；视觉上像浮在画布上，而不是把页面切成两半。
- 左侧卡片用一条四步业务链路（销售订单 → 采购执行 → 装柜出运 → 账单与资金）承担品牌与业务说明，替代 Slogan 大字段。
- 右侧表单使用 **填充式输入框**（浅灰底、12px 圆角）和 **胶囊主按钮**，与分栏版的描边输入/6px 按钮、居中档案版的下划线输入/黑按钮区分。
- 页脚版本与版权放在两张卡片之外的画布底部，跨两卡对齐。

目标：比前两版更有空间感、场景感和品牌包围感，同时保持登录任务清晰。

## 2. 与另外两版的差异

| 维度 | 分栏版 | 居中档案版 | 悬浮画布版 |
| --- | --- | --- | --- |
| 结构 | 左品牌栏 + 右表单区，贴边 | 单列文档 | 全屏画布 + 左/右两块悬浮卡 |
| 背景 | 绿色实色/渐变 + 点阵圆环 | 白底细网格 + 文字描边水印 | 浅绿/深绿画布 + 平滑等高线 |
| 品牌表达 | Slogan + 业务范围 | 文档头 + 产品名 | 业务链路时间线 |
| 卡片 | 仅右侧白色卡 | 无卡 | 左右两块 24px 圆角卡，均有阴影 |
| 输入 | 44px 描边框 | 48px 下划线 | 48px 填充底、12px 圆角 |
| 主按钮 | 绿色、6px 圆角 | 黑/白、6px 圆角 | 绿色胶囊（999px） |
| 版本/版权 | 左侧底部 + 右侧底部 | 文档尾两行 | 两卡之外的画布页脚 |
| 气质 | 企业门户 | 技术档案 | 沉浸式品牌画布 |

## 3. 布局与信息组织

### 3.1 桌面

```text
┌──────────────────────────────────────────────────────────────────┐
│  画布：浅绿渐变 + 平滑等高线 + 边缘渐暗                            │
│                                                                  │
│   ┌────────────────────────┐   ┌────────────────────────────┐    │
│   │ 深绿品牌卡 504×600     │   │ 白色登录卡 504×600         │    │
│   │ [Logo] 千树数据管理系统 │   │ ACCOUNT ACCESS   DMS / 01  │    │
│   │                        │   │ 欢迎登录                   │    │
│   │ ■ BUSINESS FLOW        │   │ 使用管理员分配...           │    │
│   │ 业务全链路              │   │                            │    │
│   │ 从订单到资金...         │   │ 账号 *                     │    │
│   │ 01 销售订单             │   │ [填充输入]                 │    │
│   │ 02 采购执行             │   │ 密码 *                     │    │
│   │ 03 装柜出运             │   │ [填充输入]          [眼睛] │    │
│   │ 04 账单与资金           │   │ [       登录系统       → ] │    │
│   │ AUTHORIZED INTERNAL...  │   │                            │    │
│   └────────────────────────┘   └────────────────────────────┘    │
│                                                                  │
│   内部业务数据工作台 · v0.8.4版        Copyright © ...             │
└──────────────────────────────────────────────────────────────────┘
```

- 画布全屏（`min-height: 100%`），内容层 `max-width: 1040px`，两列等宽，间距 32px。
- 两卡 `min-height: 600px`，由网格 `align-items: stretch` 拉齐；左卡内容上下分布，右卡表单垂直居中。
- 1440×900 实测：画布 `1440×846`，悬浮网格 `1040×600`，两卡各 `504×600`，表单内容约 408px，按钮 `406×48`，页脚 `1040×17`，页面无横向溢出。
- 1025×900 实测：网格 945px，两卡各约 457px，按钮约 361px，仍无横向溢出；到 1024px 以下改为上下堆叠。
- 画布页脚位于两卡下方 20px，左侧版本、右侧版权，使用与卡片同一 1040px 网格。

### 3.2 窄屏（< 1024px）

- 两卡改为同列堆叠，仍保持「悬浮卡片」而不是贴边：
  - 品牌卡压缩到约 112px：Logo + 产品名 + 一行「从业务发生，到资金落账。」；
  - 隐藏业务链路、品牌文案和 `AUTHORIZED...`；
  - 登录卡保留 20px 圆角，内边距 28px。
- 390×780 实测：品牌卡 112px，登录卡 `y=156–600`，按钮 `y=523–571`，画布页脚 `y=616–668`，页面无横向溢出；登录按钮在首屏内。
- 断点使用 `container` 查询以支持 390px 设备框预览；实际实现可用 `max-width: 1023px` 媒体查询，与框架移动模式对齐。

## 5. 信息组织

- **品牌与业务说明**全部放在左卡，右卡只做登录；避免品牌信息与表单互相争抢。
- 左卡用业务链路代替 Slogan：销售订单 → 采购执行 → 装柜出运 → 账单与资金。每一步都有 1 行业务事实说明，需要与业务口径核对后再落地。
- 右卡用 `ACCOUNT ACCESS / DMS / 01` 的 mono 眉题建立技术感；标题「欢迎登录」保持任务明确。
- 版本与版权离开卡片，放在画布页脚；两卡之间没有版权或版本噪声。
- 卡片外只有画布；画布等高线负责空间层次，卡片负责内容层次。

## 6. 交互与反馈

行为与前两版保持一致：

- 账号、密码只校验必填；登录页不展示密码长度规则；密码输入保留 20 字符上限。
- blur 校验当前字段；submit 校验全部并聚焦第一个错误；字段出错后随输入恢复。
- 账号空「请输入账号」；密码空「请输入密码」；401 展示为「账号或密码错误」（服务端错误码不变）。
- 429/503/网络错误使用右卡全局 callout；结果未知时提供「检查登录状态」并显示检查中状态。
- 提交时按钮、输入框、密码可见性按钮同时禁用；按钮「登录中…」+ spinner；`form[aria-busy=true]`；保留 loading 防重复。
- 密码可见性常显、带 `aria-label`/`aria-pressed`；清空后复位。
- 真实 `<form>` 回车提交；密码可见性按钮 `type="button"`。
- 左卡业务链路是静态信息，不参与交互。

## 9. 适用判断

- 想要 **最强的品牌包围感和空间感**、登录页可以承担“进入工作台”的仪式感：选悬浮画布版。
- 想要品牌展示但更克制、表单更突出：分栏版更稳。
- 想要内部工具、技术文档感、最低装饰：居中档案版更合适。
- 悬浮画布版的成本主要在业务链路文案核对、画布等高线与卡片响应式；交互仍可复用现有登录逻辑。

## 10. 待确认

1. 是否采用悬浮画布版，还是保留分栏版/居中档案版。
2. 左卡业务链路的四步与说明是否符合实际业务口径。
3. 是否接受 24px 圆角卡片 + 胶囊绿色按钮这套更“产品化”的组件语言。
4. 画布等高线在亮色/暗色的强度是否合适；是否需要更弱或更明显。
5. 窄屏把品牌卡压缩成 112px 浮层、隐藏业务链路，是否可以接受。
6. 共享 `FaInput` 的密码可见性修复是否随实现一起做。
