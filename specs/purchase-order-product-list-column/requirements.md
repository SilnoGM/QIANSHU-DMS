# 采购订单列表产品列需求

## 1. 背景与目标

采购人员需要在“全部采购”和“待办采购”的共享列表中直接识别订单产品，而无需逐单打开详情。产品列复用销售订单列表已经验证的 `ImageGroup + QsGoodTooltipContent` 组合，保证销售与采购域的视觉和交互语义一致。

## 2. 设计规格

- 平台：Web，Vue 3 + Vite。
- 视觉方向：Industrial / utilitarian，延续当前运营工作台的高密度业务表格。
- 色彩：只使用现有主题 Token，不新增硬编码颜色。
- 字体：沿用 `Noto Sans SC`，数据文本沿用 `Noto Sans Mono`。
- 布局：在采购订单列表中新增紧凑“产品”列，桌面表格与移动卡片复用同一组产品预览数据。

## 3. 功能需求

### R1：采购列表产品摘要契约

**用户故事：** 作为采购人员，我希望列表一次性返回当前页订单的产品摘要，以便快速识别产品且不产生逐行详情请求。

#### 验收标准

1. 当客户端请求采购订单列表时，系统应在每个订单项中返回 `lineSummary`。
2. 当系统生成 `lineSummary` 时，系统应返回明细数量、产品总数量和完整 `previews` 列表。
3. 当系统生成单条 preview 时，系统应返回稳定的 `lineId`、采购明细中的产品名称快照和可空的当前产品主图。
4. 当采购明细为 `CUSTOM` 或当前目录产品无可用主图时，系统应返回 `mainImage: null`。
5. 当系统查询当前页列表时，系统应通过列表查询一次性取得产品摘要所需数据，不得由 Web 对每行追加详情请求。

### R2：采购订单产品主图读取授权

**用户故事：** 作为拥有采购订单读取权限的用户，我希望能够查看列表中采购产品的主图。

#### 验收标准

1. 当用户读取采购列表主图时，系统应要求 `purchase-orders:read` 权限。
2. 当主图请求到达时，系统应重新校验采购订单、采购明细、目录产品和媒体之间的有效关系。
3. 当关系无效、媒体不是当前可用主图或明细为临时产品时，系统应返回稳定的未找到错误。
4. 系统不得复用只面向采购创建场景的产品候选主图授权路径。

### R3：产品列视觉与交互

**用户故事：** 作为采购人员，我希望采购列表产品列与销售列表一致，以便使用相同操作习惯查看产品。

#### 验收标准

1. 当采购列表在桌面端渲染时，系统应新增标题为“产品”的列，并使用与销售列表相同的 `160px` 最小列宽。
2. 当订单存在可用产品主图时，系统应使用 `ImageGroup` 渲染，配置为 `max-count=3`、`size=40`、`radius=md`。
3. 当可用产品主图超过三个显示位置时，系统应沿用 `ImageGroup` 的折叠行为，不在图片组之外渲染额外主图。
4. 当用户悬停或键盘聚焦单张产品图时，系统应使用 `QsGoodTooltipContent` 展示对应产品名称与图片序号。
5. 当订单不存在可用产品主图时，系统应展示 `ImageGroup` 的标准空态。
6. 当采购列表在移动端渲染时，系统应在现有采购卡片中展示同一产品图片组，不新增独立卡片或横向滚动容器。
7. 当用户进入“全部采购”或“待办采购”时，系统应复用同一产品列实现与同一服务端列表契约。

## 4. 非目标

- 不修改数据库 schema。
- 不修改产品档案或产品媒体关系。
- 不改变销售订单列表现有产品列。
- 不新增第三方依赖、视觉主题或动画。
- 不在采购列表展示价格、数量或产品文字清单；文字信息只进入产品 Tooltip。
