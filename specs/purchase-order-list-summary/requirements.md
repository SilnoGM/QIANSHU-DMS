# 采购订单列表汇总行需求

## 1. 背景与目标

采购人员需要在“全部采购”和“待办采购”列表中直接掌握当前筛选结果的订单规模、采购金额、付款约定和实际付款情况。采购汇总行应复用销售订单列表已经验证的汇总矩阵结构，但使用采购领域语义和固定币种 `CNY`。

## 2. 设计规格

- 平台：Web，Vue 3 + Vite。
- 视觉方向：Industrial / utilitarian，延续运营工作台的高密度业务表格。
- 色彩：只使用现有主题 Token，不新增硬编码颜色。
- 字体：沿用项目现有正文样式，金额使用既有数据字体。
- 布局：桌面端使用横向汇总矩阵，移动端使用两列定义列表；不改变采购列表列宽。

## 3. 功能需求

### R1：全量筛选汇总契约

**用户故事：** 作为采购人员，我希望汇总数据覆盖当前筛选命中的全部订单，以便不受分页影响地判断采购资金情况。

#### 验收标准

1. 当客户端请求采购订单列表时，采购订单系统应在分页响应中返回当前查询条件对应的金额汇总。
2. 当查询包含搜索词、日期、供应商、采购类型、订单状态、履约状态、付款状态或待办任务时，采购订单系统应使用与列表完全相同的服务端谓词计算汇总。
3. 当匹配结果跨越多个分页时，采购订单系统应汇总全部匹配订单，而不是只汇总当前页。
4. 当匹配结果为空时，采购订单系统应返回空汇总集合和订单总数 `0`。
5. 当计算已付款金额时，采购订单系统应只计入未作废付款记录。

### R2：采购金额汇总口径

**用户故事：** 作为采购人员，我希望同时看到采购定价、本单采购总价和付款拆分，以便核对采购成本与资金执行。

#### 验收标准

1. 当存在匹配订单时，采购订单系统应返回固定币种 `CNY` 和订单数量。
2. 当计算“采购定价总计”时，采购订单系统应累加每条采购明细的 `referencePurchaseUnitPriceAmount × quantity`。
3. 当计算“本单采购总价”时，采购订单系统应累加订单的 `purchaseTotalAmount`。
4. 当计算付款约定时，采购订单系统应分别累加 `depositDueAmount` 与 `balanceDueAmount`。
5. 当计算实际付款时，采购订单系统应返回已付总额，并以“本单采购总价减已付总额”计算待付总额。
6. 所有金额应保持四位定点小数字符串，不通过 JavaScript 浮点数计算。

### R3：采购列表汇总展示

**用户故事：** 作为同时使用销售与采购列表的用户，我希望两个页面的汇总结构一致，以便使用相同阅读习惯。

#### 验收标准

1. 当桌面端渲染采购列表时，系统应在表格底部展示“筛选结果”和金额汇总矩阵。
2. 汇总矩阵应依次展示“采购价”“付款约定”“付款”三组，每组两个采购语义字段。
3. 当移动端渲染采购列表时，系统应以两列定义列表展示同一组汇总数据。
4. 当列表筛选、搜索、日期范围、状态视图或待办任务改变时，系统应随列表响应更新汇总。
5. “全部采购”和“待办采购”应复用同一汇总实现。

## 4. 非目标

- 不修改数据库 schema 或 migration。
- 不改变采购订单状态、付款状态或待办任务规则。
- 不改变采购列表已有列宽、操作和分页。
- 不新增第三方依赖或新的视觉主题。
