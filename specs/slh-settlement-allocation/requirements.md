# SLH 结算分摊 需求

## 1. 背景

顺联航账单的一行来自某张采购单，但货件可能已通过寄仓调货归属到另一张销售订单。此前对账结算把整行金额都记到**采购单的原销售订单**出单人，寄仓后的二派费、寄仓费无法扣到原订单，正常运费也无法只由当前订单承担。

本需求把「结算头」与「费用分摊明细」拆开：结算金额仍按账单金额计算，但每一笔费用可以归到：

- 甲：原销售订单（采购单挂靠的销售单）；
- 乙：当前销售订单（货件当前归属）；
- 公司：公司资金账户。

## 2. 已确认口径

| 项 | 口径 |
| --- | --- |
| 默认归甲 | `REDELIVERY`（二派费）、`TRANSFER_DELIVERY`（转派费）、`STORAGE`（寄仓费） |
| 默认归乙 | 正常运费、COD、金流费、COD 手续费，以及其余费用类型 |
| 港口费 | 新增 `PORT_FEE`，默认归乙 |
| COD | 固定归乙，不随手动目标切换 |
| 金流费 | 按乙销售订单的约定总额计算，每个当前销售订单只入一次 |
| 手动改目标 | 只允许甲 / 乙 / 公司；目标与默认不同时必须填写原因 |
| 甲已终止/取消 | 允许扣费；资金层要求甲出单人存在资金账户 |
| 费用明细缺失/对不上 | 阻断结算，不猜测分摊 |
| 甲 = 乙 | 甲的费用并入乙，不重复生成目标 |

## 3. 阻断与失败

- 备注费用合计不等于附加费（CNY）或 NTD 杂费（TWD）时，返回 `SLH_RECON_ALLOCATION_BREAKDOWN_MISMATCH`，不写结算。
- 手动改目标未填原因：`SLH_RECON_ALLOCATION_REASON_REQUIRED`。
- COD 改到甲或公司：`SLH_RECON_ALLOCATION_COD_TARGET_INVALID`。
- 覆盖项 key 不存在或重复：`SLH_RECON_ALLOCATION_OVERRIDE_INVALID`。
- 甲出单人没有资金账户：完成批次时返回 `SLH_RECON_SETTLEMENT_ORIGIN_ACCOUNT_MISSING`。

## 4. 验收

1. 默认分摊下，二派费/转派费/寄仓费只出现在甲，其余费用与 COD 出现在乙。
2. 财务可把任一项改到公司，公司目标只动公司账户，且不参与出单人比例拆分。
3. 结算记录保留逐项快照与当时的目标合计，历史记录仍可查。
4. 金流费不重复入账：同一当前销售订单跨多行、跨批次只入一次。
5. 代收货款只回填到乙，甲的订单状态不被结算改变。
6. 费用明细与账单两个杂费列对不上时，界面与接口都拒绝结算。
7. 没有分摊快照的历史结算按旧口径（单据上的 `salesOrderId` 单笔入账）继续可完成。
