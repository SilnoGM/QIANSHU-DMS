# 采购审核

## 已确认业务边界

- 新提交的销售关联采购、备货采购：`PENDING_REVIEW + ORDERED`。v5 的采购订单号在提交时派发，基础唛头及货件唛头在审核通过时生成；历史 v3/v4 原编号保持不变，详见 [审核派发规则](../purchase-order-parts/review-shipping-marks.md)。
- 独立审核动作将订单原子推进为 `CONFIRMED + PREPARING`，页面显示在待发货视图。
- 审核中可取消；不能付款、发货或到仓，通用状态接口不可替代审核。
- 有效采购（含审核中）均占用来源销售产品数量，防止重复采购及删除、减量至预占数量以下。
- 销售履约覆盖只统计已审核的 `CONFIRMED/COMPLETED` 采购。审核、取消与销售产品变更使用相同口径重算；全部销售产品已审核覆盖才进入备货中。
- 历史采购单状态保持原样；本次不增加驳回、撤回或多级审核。

## API 与权限

`POST /api/purchase-orders/:purchaseOrderId/review`

请求：`{ expectedVersion: number, reason?: string }`。响应复用采购详情。

权限 `purchase-orders:review` 独立于更新权限；默认仅系统管理员持有，可在角色配置中授权。服务端重读订单状态及版本；过期版本、重复审核返回 `409 PURCHASE_ORDER_STATE_CHANGED`。同一事务写入订单与履约两条历史、审核人、原因和审计，并重算销售进度。前端提交失败不自动重试，重查最新详情后由用户再次确认。

## 页面

- 待办视图：采购审核中 / 待发货 / 待入仓 / 待付款，保留待发货为默认视图。
- 全部视图：全部采购 / 采购审核中 / 已确认 / 已完成 / 已取消。
- 所有视图均显示后端计数；审核中不重复计入可付款或可发货视图。
- 待办审核中显示查看、审核；全部采购的审核中订单显示查看、审核、取消，各自遵循权限。
- 点击审核先读取最新详情并二次确认，成功后轻提示并刷新列表与计数。

### 既有接口差异

浏览器回归发现既有工厂发货 POST 实际返回 `201`，而 OpenAPI 标注为 `200`。本次不调整该接口响应，销售浏览器场景按真实返回值校验，并继续核对采购发货事实与销售 `LAND_TRANSIT` 状态。
