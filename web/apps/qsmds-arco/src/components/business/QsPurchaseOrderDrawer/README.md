# QsPurchaseOrderDrawer

采购订单正式详情抽屉，参照 `QsSalesOrderDrawer` 的视觉与交互，不复用创建页的 `QsPurchaseOrderDesc`，也不修改销售组件。

## 展示结构

- 顶部：采购图标、订单编号、CNY 标签、采购日期和关闭按钮。
- 订单详情信息：基础信息与三维状态、供应商与销售来源、采购产品与真实采购价/数量/行小计、采购总价/定金/尾款/已付/未付、采购唛头和备注、实际付款记录（展开查看对应付款凭证）、订单凭证（采购单与签收单）。
- 订单变更记录：聚合接口已持久化的 `statusHistory` 与 `amountRevisions`，按时间倒序，金额以变更前后对照展示；不编造历史，空原因标注“未记录原因”。
- 底部：紧凑打印按钮，仅显示后续版本推出的轻提示。

## 数据与职责

- 父页面保留请求、取消、权限和写入生命周期；组件通过 `canAttachDocument` 控制凭证归档入口，派发 `attachDocument` 事件。实际付款记录仅供查看，不提供前往采购付款、作废付款、下载或解除关联入口。
- 每次打开读取最新详情；产品主图从详情 `lineSummary.previews` 按采购行 ID 匹配，不依赖旧列表快照。
- 采购货件按 `parts.partNumber` 内部顺序排序，标题“货件-01”不是正式货件编号；默认收起且每次换单重置。`parts.shippingMarkText` 是独立已存字段，可为空，前端不根据基础唛头和序号重算。展开后按 `purchaseOrderLineId` 关联原产品快照和主图，仅显示本货件分配数量，不重复计金额。
- 新单提交后，订单和货件唛头都为空；待审核时显示“待审核生成”且无复制入口。审核通过后全单派发一个基础唛头：单件货件码等于基础码，多件码为 `基础唛头/货件-01` 等，序号最少两位但不截断。基础码在备注区域显示，已有货件码可独立复制。
- 历史订单基础码及旧版独立货件码原样显示、复制，不改号，不由旧货件码推断基础码；历史 `parts` 为空时不推断分件。
- 采购可无凭证付款；付款凭证按 `paymentId` 关联，仅在对应付款记录内展示，保留图片预览。无凭证时显示“本次付款未关联凭证”；已作废付款及已解除关联付款凭证保留历史信息，已解除凭证不加载媒体。有效采购单与签收单单独展示，不重复收纳付款凭证。
- `purchase-order-document-modal.vue` 负责独立凭证上传归档，每单最多一张有效采购单、签收单可多张。`POST /api/purchase-orders/:purchaseOrderId/documents` 不改变履约或付款状态，需 `purchase-orders:document` 权限；关闭、换单、退出登录会取消请求并释放预览资源。
- 状态、金额及记录数量均直接使用服务端字段，不做本地财务重算。
- 付款与订单凭证均默认折叠，各自最多展开一条；展开隐藏小图、收起恢复，180ms 透明度与 FLIP 位移动画支持减少动态效果。
- 使用主题 token、单一正文滚动容器、键盘 Tabs、关闭焦点恢复；窄屏改为单列，不影响销售抽屉。
