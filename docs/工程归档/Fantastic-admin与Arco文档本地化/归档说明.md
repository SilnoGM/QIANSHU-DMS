## 1. 归档范围

本任务将 Fantastic-admin 官方指南、Fantastic-admin 内置组件和 Arco Design Vue 组件库重写为千树 DMS 本地中文开发手册。手册以 Fantastic-admin 专业版 `6.3.0`、Arco Design Vue `2.58.0`、本地专业版源码和正式应用实际接入为真相源，采用“一个总入口、三个知识域、按职责分册”的分层多册结构。

归档范围包括 21 份正式手册 Markdown、根文档索引、`web/scripts/frontend-handbook.test.mjs` 治理测试、两份 `fa-page-optimizer` 技术文档路径修正、本任务设计与实施计划、本归档说明、工程归档索引，以及根治理测试 `scripts/root-governance.test.mjs`。任务没有修改业务代码、公共 API、数据结构、数据库 schema、依赖或真实 `.env`。

## 6. 关联证据

以下实施偏差和失败处理记录用于解释最终验收证据为什么与初始命令存在差异：

1. **宽泛 `rg` 策略扫描被替换。** 原计划中两条否定式 `rg` 命令分别误报 10 行 Vue 合法 `{{ ... }}` 插值与安全空值 `const password = ref('')`，因此未被虚假记录为通过。最终使用 `findArcoDocPolicyViolations()` 的 fence-aware 扫描和变异测试：允许合法 Vue 插值、空值和 `<TOKEN>`，但拒绝 TODO/TBD、大写占位、`<PLACEHOLDER>`、虚构 `/api` endpoint、Bearer、quoted/unquoted Cookie 和真实敏感赋值。
2. **Markdown 链接验证从正则升级为结构化扫描。** 实施中发现单一正则会漏掉未闭合链接，也会截断目标中的平衡括号。最终扫描器忽略 fenced/inline code，支持转义与嵌套括号，并对 `[label](target` 这类未闭合语法给出显式诊断，属于原验收意图的加固。
3. **导航分册文件名以实际产物为准。** 初始设计和计划使用“导航及其他组件.md”，最终产物为语义更一致的“导航与其他组件.md”。归档时已回写设计树和计划文件映射。
4. **`fa-page-optimizer` 真实路径修正纳入范围。** Commit `4ce1f8d81feff033f1e8df582120c0976f3ebd90` 根据手册真相源同步修正 `web/skills/fa-page-optimizer/SKILL.md` 与 `references/components-catalog.md` 中 basic/pro README 路径。它们是技术文档导航契约，不是业务代码扩张；归档时已补入计划文件映射。
5. **检查失败按根因修正。** Task 8 首次 ESLint 只报告 Node `fs` import 顺序，调整后重跑通过。仓库没有可用的 Prettier 命令，任务没有为文档引入新依赖；最终格式门槛为 ESLint、Markdown 结构契约与 `git diff --check`。
6. **根治理验证改用无依赖入口并严格串行。** 首次误在仓库根执行 `pnpm run test:root`，pnpm 生成了禁止存在的根 `pnpm-lock.yaml` 和 `node_modules/`，造成 5 项边界失败与 3 项预期的新归档 RED。新生成物经内容核对后清理；新归档契约补齐后，使用 `node --test scripts/root-governance.test.mjs` 直接执行。根治理与 Web pnpm 命令不再并发，最终串行验证 `46/46` 通过，根 workspace、lockfile 与 `node_modules/` 全部不存在。
