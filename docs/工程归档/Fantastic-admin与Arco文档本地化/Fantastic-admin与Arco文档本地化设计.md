# Fantastic-admin 与 Arco 文档本地化设计

## 1. 文档定位

本文记录“Fantastic-admin 与 Arco 文档本地化”任务已经确认的目标、信息架构、内容模型、真相源优先级、完整性口径、维护规则和验收边界，是后续实施计划与正式手册编写的设计真相源。

| 项目 | 内容 |
| --- | --- |
| 文档状态 | 设计已确认，待实施 |
| 确认日期 | 2026-07-15 |
| 适用产品 | 千树 DMS Web |
| 正式应用 | `web/apps/qsmds-arco` |
| Fantastic-admin 基线 | 专业版 `6.3.0` |
| Arco Design Vue 基线 | `@arco-design/web-vue@2.58.0` |
| 内容方案 | 完整手册型、分层多册 |
| 实施计划 | 本设计审阅通过后单独编写 |

本任务不是把三个网站逐页复制到仓库，而是将 Fantastic-admin 官方指南、Fantastic-admin 内置组件和 Arco Design Vue 组件库的完整知识目录，按照千树 DMS 的依赖版本、专业版源码和日常开发路径，重写为可检索、可执行、可维护的本地中文手册。

## 2. 背景与问题

千树 DMS 的正式前端应用基于 Fantastic-admin 专业版开发，并使用 Arco Design Vue 作为业务 UI 组件库。当前仓库已经明确了 Web 工作区边界、正式应用、接口接入和构建命令，但尚未形成覆盖框架能力、内置组件和 Arco 组件的本地开发手册。

仅依赖在线文档存在以下问题：

1. Fantastic-admin 官网同时面向基础版、专业版及不同 UI 组件库，不能直接表达千树 DMS 的真实组合。
2. 官网内容随上游版本更新，当前网页说明可能与仓库内专业版 `6.3.0` 源码存在差异。
3. Fantastic-admin 内置组件与 Arco Design Vue 存在能力重叠，缺少项目级选型规则会导致同类交互混用。
4. 在线组件文档适合查阅单个 API，但无法说明组件在千树 DMS 中如何接入、从哪里导入、是否已经启用及应放在哪个目录。
5. 当前 `web/packages/components/src/index.ts` 暴露的组件集合与官网导航并非完全一致，若只抄官网目录会遗漏本仓库真实可用能力。
6. 新成员需要在多个站点、源码目录和项目规范之间来回跳转，缺少一条从项目入口到具体组件的稳定阅读路径。

## 3. 目标

本任务必须同时达到以下目标：

1. 完整覆盖当前 Fantastic-admin 指南的指引、AI 技能、入门、应用配置、高级和其他栏目。
2. 完整覆盖 Fantastic-admin 专业版 `6.3.0` 在本仓库实际导出的基础版及专业版组件。
3. 完整覆盖 Arco Design Vue `2.58.0` 的组件分类和组件目录。
4. 为每个主题提供用途、适用场景、关键 API、最小示例、项目路径、选型规则和官方来源。
5. 明确 Fantastic-admin 框架能力、Fantastic-admin 内置组件、Arco Design Vue 组件与千树 DMS 业务组件的职责边界。
6. 使用本地源码校正官网与当前版本之间的差异，不把上游最新网页状态误写成当前项目事实。
7. 建立单一总入口、分册导航、交叉链接、来源链接和版本基线，支持后续按版本增量维护。
8. 将正式手册纳入 `docs/文档索引.md`，成为当前有效前端指导文档的一部分。

## 4. 非目标

本任务不包含以下事项：

- 不修改 Fantastic-admin、Arco Design Vue、正式应用或共享包的代码。
- 不新增、升级或删除依赖。
- 不修改公共 API、数据结构、数据库 schema 或 OpenAPI 契约。
- 不把在线文档全文、演示站源码或大段受版权保护的内容复制进仓库。
- 不为每个官网页面创建一份一比一镜像文件。
- 不承诺本地手册可以替代所有上游 API 明细；低频参数和版本新增项仍通过固定的官方来源链接追溯。
- 不记录专业版许可证、购买信息、凭据或任何不应进入 Git 的内容。
- 不把 `web/examples/*` 描述为正式业务应用，也不修改参考应用。
- 不引入文档站点、Markdown 生成器、爬虫运行时或第三方依赖。

## 5. 真相源与冲突处理

### 5.1 真相源优先级

同一事实出现冲突时，按以下优先级处理：

1. **本仓库锁定版本与正式应用代码**：确认依赖版本、启用方式、目录、导出名称和千树 DMS 当前行为。
2. **本仓库 Fantastic-admin 专业版源码**：确认专业版实际拥有的框架能力、组件实现、Props、Emits、Slots、Composables 和类型。
3. **对应版本的官方文档或官方源码**：解释上游设计意图和公开 API。
4. **当前在线官方文档**：补充目录、示例、迁移说明和最新能力，但必须标注与本地版本的差异。

本地手册不得用官网最新状态覆盖仓库事实。例如官网组件导航与 `web/packages/components/src/index.ts` 不一致时，组件是否“当前可用”以本地导出为准，官网页面只作为说明来源。

### 5.2 固定版本基线

本次整理固定到以下基线：

- `web/package.json`：Fantastic-admin 专业版 `6.3.0`。
- `web/pnpm-lock.yaml`：`@arco-design/web-vue@2.58.0`。
- `web/apps/qsmds-arco`：千树 DMS 唯一正式业务应用。
- 整理日期：`2026-07-15`。

每份正式手册都必须在开头声明适用版本和最后核对日期。官网后续变化不自动改变手册结论；升级依赖时才触发版本复核。

### 5.3 官方来源

主要官方入口如下：

- Fantastic-admin 指南：<https://fantastic-admin.hurui.me/guide/intro.html>
- Fantastic-admin 内置组件：<https://fantastic-admin.hurui.me/components/>
- Arco Design Vue：<https://arco.design/vue/docs/start>

具体章节必须链接到对应主题或组件页，不只链接站点首页。能够读取官方 Markdown 页面时优先使用其 Markdown 内容进行整理，最终仍以改写和项目化解释为主。

## 6. 信息架构

正式手册位于 `docs/前端文档/前端开发手册/`，采用“一个总入口、三个知识域、按职责分册”的结构：

~~~text
docs/前端文档/前端开发手册/
├── README.md
├── Fantastic-admin/
│   ├── README.md
│   ├── 指引与开发准备.md
│   ├── AI技能.md
│   ├── 工程基础.md
│   ├── 服务端交互与登录.md
│   ├── 路由导航与状态管理.md
│   ├── 应用配置.md
│   ├── 权限保活与国际化.md
│   └── 高级能力构建与升级.md
├── Fantastic-admin内置组件/
│   ├── README.md
│   ├── 选型与使用规则.md
│   ├── 基础版组件.md
│   └── 专业版组件.md
└── Arco-Design-Vue/
    ├── README.md
    ├── 接入基础与全局配置.md
    ├── 通用与布局组件.md
    ├── 数据录入组件.md
    ├── 数据展示组件.md
    ├── 反馈组件.md
    └── 导航及其他组件.md
~~~

目录名和文档名整体使用中文；框架名、组件名、包名、API、Props、Events、Slots、命令和路径保留英文。

### 6.1 总入口

根 `README.md` 是前端开发手册的唯一入口，负责：

- 声明版本基线和真相源。
- 提供按任务阅读路径，例如“新增页面”“配置路由”“实现权限”“选择表单组件”“构建部署”。
- 展示三类能力的职责边界和优先级。
- 链接全部分册并提供组件名称索引。
- 说明如何发现官网与本地版本差异、如何提交后续更新。

三个知识域的 `README.md` 只维护各自范围、阅读顺序和完整目录，避免根入口膨胀为正文。

### 6.2 Fantastic-admin 指南分册

指南分册按开发任务重组官网栏目，但必须通过覆盖矩阵证明没有遗漏：

- 指引、选择理由、更新日志和术语。
- AI 技能的定位、适用场景和安全边界。
- 准备工作、启动、代码规范、环境变量、资源、图标、构建与预览。
- 服务端交互、登录、路由、导航菜单、全局状态。
- 应用、主题、导航菜单、顶栏、标签栏、工具栏、页面配置。
- 权限、页面保活、国际化、内置 API、预留插槽、快捷键、私有 Storage、开发者工具、自定义字体、首屏 Loading、UI 组件库、Composition API 和 JSX。
- 框架更新、常见问题以及从 v5 迁移；迁移内容作为参考，不暗示当前项目仍待迁移。

每项配置必须同时给出上游含义和千树 DMS 的真实配置入口。示例优先引用 `web/apps/qsmds-arco/src/settings.ts`、路由、Store、Slots、Locales、UI Provider 和 Vite 配置等现有路径。

### 6.3 Fantastic-admin 内置组件分册

内置组件按本仓库 `web/packages/components/src/index.ts` 的公开导出建立完整清单。官网基础版/专业版分类仅作为参考，本地实际导出决定最终归类和可用状态。

组件正文统一包含：

1. 组件名称、功能和版本归属。
2. 当前本地源码路径和导出名称。
3. 适用场景与不适用场景。
4. 关键 Props、Events、Slots、Expose、Composables 和类型。
5. 一个能够表达核心用法的 Vue 最小示例。
6. 样式定制入口，包括 `class`、`contentClass` 或 UnoCSS 能力。
7. 与 Arco 同类组件的选择建议。
8. 官方页面、本地 `README.md` 或源码链接依据。

专业版是千树 DMS 的正式能力，不使用“可跳过”措辞。基础版与专业版分册只是按源码层级导航，不表达能力优先级。

### 6.4 Arco Design Vue 分册

Arco 分册完整覆盖 `@arco-design/web-vue@2.58.0` 的组件目录，并按官方语义分为通用、布局、数据录入、数据展示、反馈、导航及其他能力。每个组件至少记录：

1. 组件名称和解决的问题。
2. 在千树 DMS 中的全局接入状态和最小模板用法。
3. 最常用的 Props、Events、Slots 和方法。
4. 一个项目风格的最小示例。
5. 与 Fantastic-admin 内置组件的重叠关系。
6. 常见误用、可访问性、响应式或性能注意事项。
7. 对应 `2.58.0` 官方组件页。

API 明细采用“高频 API 本地化 + 完整 API 官方直链”的方式。这样既实现组件目录的完整覆盖，又避免复制大段易过时的属性表。

## 7. 组件选型规则

千树 DMS 的默认选型顺序不是简单的“内置组件优先”或“Arco 优先”，而是按职责决定：

| 场景 | 默认选择 | 原因 |
| --- | --- | --- |
| Fantastic-admin 框架壳、导航、页面容器及框架内部交互 | Fantastic-admin 内置组件 | 与框架主题、布局和内部实现一致 |
| 标准业务表单、数据展示、反馈和企业后台交互 | Arco Design Vue | API 完整、业务组件丰富、属于正式应用 UI 基座 |
| 专业版特有的可视化、动画、日期能力或框架封装 | Fantastic-admin 专业版组件 | 仓库已拥有且提供统一封装 |
| 千树 DMS 领域交互 | `apps/qsmds-arco/src/components/` 下的业务组件 | 领域语义不进入通用共享包 |
| 至少两个真实调用方且接口稳定的无业务能力 | 评估进入 `web/packages/*` | 遵循现有共享边界和 YAGNI |

同一页面可按职责组合两套组件，但不得为了视觉差异随意混用同类基础控件。存在同名或同类组件时，手册必须给出明确对照表。

## 8. 内容写作规范

### 8.1 统一章节模板

框架主题采用以下模板：

1. 功能定位。
2. 当前项目状态。
3. 配置或使用步骤。
4. 关键配置项或 API。
5. 项目示例。
6. 约束与常见问题。
7. 相关本地文档。
8. 官方来源。

组件条目采用以下模板：

1. 一句话用途。
2. 项目可用状态与源码位置。
3. 最小示例。
4. 高频 API。
5. 选型与注意事项。
6. 官方来源。

### 8.2 示例规则

- 示例必须适配 Vue 3、TypeScript 和当前项目接入方式。
- 用户可见文案使用中文，技术标识使用英文。
- 不伪造项目不存在的业务 API、路由、Store 或权限字段。
- 需要业务数据时使用语义明确的静态示例，不引入 fake service。
- 示例优先展示推荐路径，不保留不必要的旧版兼容写法。
- 引用现有源码时只截取理解所需的最小片段，并给出真实路径。

### 8.3 来源与改写规则

- 每个分册维护“官方来源”章节，组件条目保留直接链接。
- 不连续复制官网段落；所有说明都以项目语境重新组织。
- 无法从官方文档确认的行为必须回到本地源码验证，并标记为“本地源码结论”。
- 推断性内容必须明确标注为项目建议，不能冒充上游官方要求。
- 官网与本地版本不一致时建立“版本差异”提示，而不是静默取舍。

## 9. 完整性控制

“完整手册型”定义为目录和开发知识完整，不定义为官网全文镜像。验收时使用三份覆盖清单：

1. **Fantastic-admin 指南覆盖矩阵**：官网导航的每个栏目都映射到一个本地章节。
2. **内置组件覆盖矩阵**：`web/packages/components/src/index.ts` 的每个公开组件、Composable 和主要公开类型都映射到一个本地条目。
3. **Arco 组件覆盖矩阵**：`@arco-design/web-vue@2.58.0` 官方组件目录的每个组件都映射到一个本地条目。

覆盖矩阵记录：上游名称、本地分册、章节锚点、本地状态、来源 URL、最后核对日期。任何未覆盖项必须有明确原因，不能以“后续补充”或 `TODO` 结束任务。

## 10. 维护机制

以下变化触发手册复核：

- `web/package.json.version` 所代表的 Fantastic-admin 上游基座版本变化。
- `@arco-design/web-vue` 锁定版本变化。
- `web/packages/components/src/index.ts` 增删或重命名公开导出。
- 正式应用的 UI Provider、自动导入、主题、路由、权限或 settings 入口变化。
- 官网出现影响当前版本判断的修正说明。

维护时只更新受影响分册和覆盖矩阵，不重新镜像全部网站。版本升级前后的差异必须进入变更记录；旧版本内容若不再适用，应更新而不是在正式手册中长期堆叠兼容说明。

## 11. 验证设计

### 11.1 结构验证

- `docs/文档索引.md` 必须链接到前端开发手册总入口。
- 总入口必须链接到全部知识域和分册。
- 所有相对 Markdown 链接必须指向真实文件或标题锚点。
- 不允许空文档、占位章节、`TODO` 或 `TBD`。

### 11.2 内容验证

- 比较 Fantastic-admin 官网目录与指南覆盖矩阵。
- 比较 `web/packages/components/src/index.ts` 与内置组件覆盖矩阵。
- 比较 Arco `2.58.0` 组件目录与 Arco 覆盖矩阵。
- 抽查每个分册至少一个示例与当前 TypeScript/Vue 接入方式一致。
- 检查基础版与专业版标记、版本号、正式应用路径及包名是否准确。
- 检查每个组件条目是否包含直接来源链接，而不是只给首页。

### 11.3 仓库验证

实施结束时至少执行：

~~~bash
git diff --check
rg -n 'TODO|TBD|待补充|后续补充' docs/前端文档/前端开发手册
rg -n 'Fantastic-admin|@arco-design/web-vue|web/apps/qsmds-arco' docs/前端文档/前端开发手册
git status --short
~~~

若仓库已有 Markdown 格式化或文档链接检查入口，实施计划应补充并执行对应命令。任何失败必须如实报告。

## 12. 实施与提交边界

后续实施按小步提交完成，至少拆分为：

1. 文档骨架、总入口与覆盖矩阵。
2. Fantastic-admin 指南分册。
3. Fantastic-admin 内置组件分册。
4. Arco Design Vue 分册。
5. 交叉选型、索引、完整性与格式收口。
6. 任务归档说明和工程归档索引更新。

每次提交只包含本任务文档，不包含 `.env`、构建产物、日志、依赖目录或无关用户改动。Commit Message 类型使用英文、描述使用中文。

## 13. 验收标准

本任务只有在以下条件全部满足后才能声称完成：

1. 分层多册目录全部落地，根索引和分册导航可用。
2. Fantastic-admin 指南官网栏目覆盖率为 100%。
3. 本地 Fantastic-admin 专业版公开组件覆盖率为 100%。

6. 专业版能力作为正式主线描述，没有被降级为可选附录。
7. 官网、本地源码和项目规范之间的差异均有明确说明。
8. 文档不含大段官网复制内容、敏感信息、虚构业务契约或占位文本。
9. 全部验证命令通过，最终 Git 暂存范围经过核对。
10. 文档变更按既定小步提交进入根 Git 仓库。
