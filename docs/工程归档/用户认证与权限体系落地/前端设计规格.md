# 用户认证与权限体系前端设计规格

> [!IMPORTANT]
> 本文记录用户认证与权限体系 Web 落地时采用的界面规格，归档后仅用于历史追溯。当前认证要求以[用户认证与权限体系设计](../../全局文档/用户认证与权限体系设计.md)为准，发布边界以[发布与版本管理](../../全局文档/发布与版本管理.md)为准；实施结果与未完成门禁见[归档说明](./归档说明.md)。

## 1. 设计目标

本规格只约束《用户认证与权限体系设计》的 Web 落地，不重做现有产品视觉。界面继续使用项目已有的 Vue、Fantastic Admin 与 Arco Design 组件、主题变量、间距和交互反馈，优先保证认证流程清晰、后台管理操作完整，以及桌面和窄屏都能完成关键任务。

设计真相源为 [`docs/全局文档/用户认证与权限体系设计.md`](../../全局文档/用户认证与权限体系设计.md)。本规格与其冲突时，以全局设计文档为准。

## 2. 视觉与布局

- 登录页保留当前品牌背景、Logo、标题和卡片结构，只保留用户名、密码与登录按钮。
- 业务页面继续使用现有后台 Shell、页面标题、`Card`、`Table`、`Form`、`Modal`、`Drawer`、`Tag`、`Alert` 和 Toast，不新增第二套视觉语言。
- 状态颜色使用 Arco 语义色：成功、警告、错误和中性色不自行硬编码；用户状态、系统角色和 `systemOnly` 权限以 `Tag` 展示。
- 页面主要操作位于标题区右侧；行级低风险操作直接展示，高风险或低频操作放入“更多”菜单，并使用明确的确认弹窗。
- 表单标签、错误提示和成功提示使用中文；API、权限码、角色 code 等技术标识保留英文并使用等宽或可复制文本样式。

## 3. 应用根认证状态

根认证层只渲染一种主状态，避免身份恢复期间闪现错误页面：

| `authState` | 根界面 |
| --- | --- |
| `loading` | 全屏品牌加载态 |
| `anonymous` | 登录页 |
| `authenticated` | 业务 Shell |
| `password_change_required` | 不挂载业务 Shell，只显示不可关闭的强制改密 Modal 与简洁背景 |
| `logging_out` | 保留当前画面并阻止重复退出，显示局部提交态 |
| `unavailable` | 简洁故障态，保留已知身份但不展示陈旧业务数据，仅提供“重新检查身份” |

应用启动必须先完成共享 `/api/auth/me`，再决定展示登录页、强制改密弹窗或业务系统。认证状态不得从 `localStorage`、`sessionStorage` 或旧 Pinia 持久化数据恢复。

## 4. 登录页

登录表单从上到下为：用户名、密码、登录按钮。提交中禁用重复提交；`Enter` 可提交；用户名和密码错误统一提示，不暴露账号是否存在。

删除或停止展示注册、忘记密码、二维码、演示账号、Remember Me、多账号切换和锁屏入口。Network 或 `5xx` 导致结果未知时清空密码，显示原错误和“检查登录状态”操作，不自动重提密码请求。

## 5. 共享改密弹窗

只实现一个 `ChangePasswordModal`，通过 `mode='normal' | 'forced'` 切换字段与关闭行为，不创建改密页面或改密路由。

普通模式：

- 从用户菜单打开，字段为当前密码、新密码、确认密码。
- 可通过取消、关闭按钮、`Esc` 或遮罩关闭；提交期间不可关闭。
- 成功后关闭弹窗，保留当前有权限的业务路由。

强制模式：

- `authState='password_change_required'` 时由应用根层自动打开。
- 字段只有新密码、确认密码；底部操作为“修改密码”和“退出登录”。
- 不显示关闭按钮，禁用 `Esc` 与遮罩关闭；只有改密成功、退出或 Session 确定失效可结束。
- 不渲染菜单、标签页或业务内容，防止看到未授权的旧页面。

两种模式的密码字段都只存在于组件局部状态；关闭、成功或结果未知后立即清空。

## 6. 用户管理

### 6.1 列表与详情

- 筛选项：用户名、状态；操作：查询、重置、新建用户。
- 桌面使用分页表格，列为用户名、显示名称、状态、角色、是否需改密、最近登录、创建时间和操作。
- 窄屏使用纵向卡片，首行突出用户名与状态，次要字段折叠展示，操作进入底部 Drawer 或“更多”菜单，不要求横向滚动桌面表格。
- 用户创建成功但没有角色时，使用警告提示“用户已创建，当前无业务权限”，并提供分配角色入口。

### 6.2 用户操作

- 新建用户：用户名、显示名称、密码、确认密码、下次登录必须改密（默认勾选）。
- 编辑用户：只编辑显示名称，不提供用户名修改。
- 启用、禁用：使用确认弹窗并展示目标用户名；服务端保护最后一个有效 `system_admin`。
- 分配角色：多选角色，提交替换完整集合；明确空集合表示移除全部角色。
- 设置密码：只读用户名、新密码、确认密码、下次登录必须改密（默认勾选）；不要求管理员当前密码，不显示临时密码。

## 7. 角色、权限和审计

- 角色页：分页或完整列表、创建普通角色、编辑名称/描述、分配权限；内置 `system_admin` 只读并显示“系统角色”。
- 权限分配按资源分组展示权限码与说明；`systemOnly` 显示标签，普通角色不可勾选。
- 权限目录页只读，按 code 排序，展示 code、说明和 `systemOnly`。
- 审计页只提供页码和每页数量；固定展示时间、事件、结果、操作者 ID、目标类型/ID、请求 ID 和标量 metadata，不增加设计外筛选或敏感来源信息。

## 8. 权限与错误反馈

- 菜单、路由、按钮按当前 `AuthContext.permissions` 控制，但服务端 `403` 始终为最终判定。
- 当前身份没有页面权限时显示稳定的 403 空状态，不进入重定向循环。
- 确定性字段错误贴近表单字段展示；冲突、权限和系统错误使用页面或 Modal 内 Alert，并保留可供核查的 `requestId`。
- 创建用户和密码重置的 Network/`5xx` 结果未知时不自动重放：创建后刷新并按用户名核查；密码重置提示管理员重新明确设置一次最终密码。

## 9. 响应式与可访问性验收

- `>= 1024px` 使用标准后台表格和 Modal；`< 768px` 的关键列表改为卡片，复杂编辑改用全宽 Drawer 或全屏 Modal。
- 主要交互可用键盘完成；Dialog 有明确标题，表单控件有 label，错误不只依赖颜色表达。
- 触控操作目标不小于现有 Arco 默认控件高度；窄屏底部操作不被安全区遮挡。
- 提交、加载、空数据、无权限、不可用和结果未知均有稳定可理解的状态，不以空白页面代替。

## 10. 非目标

- 不实现 Remember Me、设备管理、多账号、锁屏 Token 切换、注册、找回密码、MFA、二次认证或独立改密页。
- 不新增复杂动画、数据看板、批量用户操作、角色层级、权限搜索引擎或设计系统抽象。
- 不把密码、Cookie、Session ID、权限集合或认证状态写入浏览器持久化 Storage。
