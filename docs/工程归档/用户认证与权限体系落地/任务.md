# 用户认证与权限体系落地任务

## 1. 文档用途

本文是《用户认证与权限体系设计》的实施跟踪清单，不重新定义产品需求。设计、实现和验收发生冲突时，以 [`docs/全局文档/用户认证与权限体系设计.md`](../../全局文档/用户认证与权限体系设计.md) 为真相源，并在继续编码前先修正文档或实现偏差。

任务状态约定：

- `[ ]` 未开始或尚未通过验收。
- `[x]` 已实现并通过该任务列出的验证。
- 每完成一个可独立验证的功能切片，更新本清单并使用 `type: 中文描述` 格式提交。

## 2. 已确认实施边界

- Git 分支：`feat/user-auth-rbac`。
- Session：单一 `AuthSession`，空闲过期 48 小时、绝对过期 30 天、5 分钟 touch 窗口。
- 状态存储：只使用 PostgreSQL，不引入 Redis。
- 登录凭证：只使用 `HttpOnly` Cookie，不使用 JWT、`Token` Header 或 `RememberCredential`。
- 强制改密：使用全局弹窗，不新增独立改密页。
- 管理员密码操作：直接输入新密码并选择 `mustChangePassword`，不使用临时密码和二次认证。
- 首期不实现设备级 Session 管理、细粒度数据范围、外部身份源和多因素认证。
- 根目录只承担无依赖编排；`server/` 与 `web/` 分别维护依赖和 lockfile。
- 本轮不推送、不部署；删除文件前另行列出准确路径并取得确认。
