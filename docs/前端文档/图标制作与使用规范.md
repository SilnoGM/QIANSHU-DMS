# 图标制作与使用规范

千树 DMS 的顶部与侧边导航使用树木造型的品牌 SVG 图标：树冠、树干和枝条共同构成业务对象，沿用 LOGO 的绿棕配色与黑色手绘轮廓。项目统一通过 `FaIcon` 显示图标，当前资产和调用示例在组件库 `/component-library/basic/icons` 展示。

本规范适用于正式应用 `web/apps/qsmds-arco`。图标源码与清单为当前真相源，历史样稿和场景效果图用于追溯视觉方向。

## 1. 品牌图标与通用图标

| 类型 | 用途 | 选择规则 |
| --- | --- | --- |
| 品牌图标 `qs-*` | 工作台、业务模块、管理菜单、组件库导航 | 先复用清单中相同语义的图标；同一个业务入口在不同工作台保持同名 |
| 通用图标 `i-lucide:*` 等 | 搜索、刷新、关闭、展开、编辑、删除、状态反馈等工具操作 | 沿用所在组件的图标体系与主题色，不为每个操作改画树木图案 |
| 原 LOGO | 品牌身份、登录页和应用标识 | 保留原始资产，不用某枚菜单图标代替 LOGO |

品牌图标是有实色面的业务轮廓，不采用纯线性图标，也不在通用图标角落统一贴一片叶子。缩小时首先保留可识别的外轮廓，木纹、叶脉和纸面标记只是辅助。

## 2. 视觉与文件标准

| 项目 | 标准 |
| --- | --- |
| 格式与命名 | 原生 SVG；小写英文短横线命名，以 `qs-` 开头；文件名与图标 `name` 相同 |
| 视口 | `viewBox="0 0 64 64"`，不绑定某一个显示像素尺寸 |
| 安全区域 | 全套源图形的外层统一使用 `transform="translate(4 4) scale(.875)"`，收进 `4–60` 安全区域；连同描边保留边距，突出枝条不触碰画布边缘 |
| 树绿 | `#2FA127`，用于树冠、叶片和绿色业务主体 |
| 木棕 | `#8E6439`，用于树干、枝条、木质容器或框架 |
| 纸色 | `#FFF9E9`，仅用于需要留白的单据、纸页等内容面 |
| 墨色 | `#11170F`，用于近黑色外轮廓和少量内部标记 |
| 描边 | 缩进变换前，外轮廓基准 `2.8`、内纹基准 `2.0` 设计单位；圆端点、圆转角，随源图形整体缩放 |
| 内部细节 | 木纹等装饰控制在 1–2 笔；勾、箭头、货币或数据标记保持粗简，不绘制小号文字 |
| 透明背景 | 不放白底矩形，不嵌入 PNG、JPEG 或整张效果图；纸色业务主体不等于画布背景 |
| 文件内容 | 保留路径与必要分组；不携带脚本、事件处理、外链、字体、滤镜阴影或编辑器冗余元数据 |

顶部与侧边菜单中的 `qs-*` 品牌图标默认显示 `24px`，沿用原菜单行高；原有通用菜单图标维持 `20px`。品牌图标推荐使用 `24px`，最小对照尺寸 `20px` 只适合有文字陪衬的简化符号。组件库默认 `24px`，提供 `20 / 24 / 32px` 对照；以真实菜单显示为验收基准，不能凭大图中的木纹细节判定小尺寸可读性。

六枚风格基准如下，其余图标沿用相同笔触和色面关系，但按业务意义形成不同轮廓：

| 业务含义 | 图标名 | 核心造型 |
| --- | --- | --- |
| 运营工作台 | `qs-workbench-operations` | 树木构成显示器与支架 |
| 财务工作台 | `qs-workbench-finance` | 树干构成钱包，树冠与财务对象结合 |
| 系统管理 | `qs-system` | 树木构成齿轮轮廓 |
| 销售订单 | `qs-sales-orders` | 树木与卷轴订单结合 |
| 采购审核 | `qs-purchase-review` | 树木采购篮与确认勾结合 |
| 资金账户流水 | `qs-fund-transactions` | 枝条形成双向流动箭头 |

## 3. 状态、主题与可访问性

- **默认、悬停和选中**：品牌图标保留固定填色。菜单文字、背景和交互反馈继续采用现有主题，不为选中态复制一套改白色或改绿色的 SVG。`text-*` 不会重染这些显式填色。
- **亮色与暗色**：同一 SVG 同时用于两种主题。必须检查树绿、木棕和近黑描边在真实菜单背景上的分界；不能仅看白底设计稿认定暗色可用。
- **禁用**：由按钮或菜单的现有禁用契约控制交互及视觉。图标不单独接管点击，不以换图标代替 `disabled` 或对应语义。
- **有文字的菜单和按钮**：图标作为装饰，避免重复播报。`FaIcon` 的本地 SVG 分支已设置 `aria-hidden="true"`，调用方仍须提供清晰可见的文字。
- **仅图标按钮**：可访问名称放在真实按钮上，键盘焦点和点击区域由按钮承担；Tooltip 仅补充说明。状态不能只靠颜色或图形表达。

## 4. 源码、清单与构建链

下列路径均以仓库根为起点：

| 真相源 | 职责 |
| --- | --- |
| [原 LOGO](../../web/apps/qsmds-arco/src/assets/images/logo.svg) | 品牌风格与身份原图 |
| [SVG 资产目录](../../web/apps/qsmds-arco/src/assets/icons/) | `qs-*.svg` 品牌源文件，以及既有本地图标 |
| [品牌语义清单](../../web/apps/qsmds-arco/src/icons/brand-icons.json) | 人工维护品牌图标名称、中文含义、分类和用途 |

| [项目图标扫描脚本](../../web/scripts/generate-icon-inventory.mjs) | 根据源码更新项目图标使用清单，支持只读漂移检查 |
| [扫描生成的清单](../../web/apps/qsmds-arco/src/icons/project-icon-inventory.generated.json) | 为示例页提供品牌、本地与通用图标索引；不手工修改 |
| [Vite 插件](../../web/apps/qsmds-arco/vite/plugins.ts) | 将 `src/assets/icons/*.svg` 合并到 SVG spritemap |
| [FaIcon](../../web/packages/components/src/basic/icon/index.vue) | 根据 `name` 的格式选择本地 SVG、UnoCSS、Iconify 或图片分支 |
| [图标示例页](../../web/apps/qsmds-arco/src/views/component_library/basic/icons.vue) | 检索、预览和复制当前清单内的图标用法 |

`name="qs-purchase-review"` 对应 `qs-purchase-review.svg`，`FaIcon` 内部使用 `__spritemap#sprite-qs-purchase-review`。调用方不手写精灵 URL，不添加 `.svg`、目录前缀或 `i-`。

本地 SVG 在构建时打包，不依赖运行时访问远程图标服务。项目清单中 `source: 'iconify'` 的完整名称由 `web/uno.config.ts` 加入 UnoCSS `safelist`，支持示例库按清单动态渲染。任意字符串拼接和后端返回的动态图标名不自动进入清单，也不自动获得同样的离线保障。

## 5. 在页面和路由中使用

正式应用已配置 `FaIcon` 自动解析，无需为品牌图标新增包装组件。

```vue
<template>
  <span class="inline-flex items-center gap-2">
    <FaIcon name="qs-purchase-review" class="size-6 shrink-0" aria-hidden="true" />
    采购审核
  </span>
</template>
```

普通工具按钮继续使用通用图标：

```vue
<template>
  <FaButton variant="outline" size="icon" aria-label="刷新">
    <FaIcon name="i-lucide:refresh-cw" class="size-4" aria-hidden="true" />
  </FaButton>
</template>
```

在已有路由的 `meta` 中指定品牌图标，其余路由路径、权限和行为保持该页面的实际定义：

```ts
meta: {
  title: '采购审核',
  icon: 'qs-purchase-review',
}
```

工作台顶部入口同样使用其 `meta.icon`。框架支持普通态与选中态的双值图标，但当前品牌图标使用单个字符串即可；选中感由菜单本身表达。

需要从本地清单选择图标时，从 `@/icons` 导入 `projectIcons`。字段 `name` 用于渲染，`label`、`category`、`usages` 用于显示和检索，`source` 区分 `brand`、`local`、`iconify`。该清单不承载权限判断或路由跳转逻辑。

## 6. 新增或调整一枚图标

1. 在图标示例页搜索业务含义和英文名称，先确认是否已有可复用项。不同页面表达同一对象时共用图标。
2. 用一句话确定主要轮廓，例如“枝条弯成采购篮，树冠成为篮内主体”；先检查轮廓，再添加最多必要的内部标记。
3. 以现有同类 SVG 为尺寸、描边和配色基准，在 `src/assets/icons/` 新增或调整源文件。保持原生矢量、透明画布和安全边距。
4. 同步 `src/icons/brand-icons.json` 的名称、中文含义、分类和用途，再在实际调用点填写相同 `name`。重命名时同步核对所有引用。
5. 更新扫描清单并运行只读检查，确认没有漏图、未知名称或过期引用。
6. 在图标示例页及真实导航检查默认、选中、亮色、暗色和 `24px` 表现，并用 `20 / 32px` 复核缩放；再完成必要的定向检查与构建。

在仓库根执行清单更新与检查：

```bash
node web/scripts/generate-icon-inventory.mjs
node web/scripts/generate-icon-inventory.mjs --check
```

`--check` 用于发现生成清单与当前源码不一致，不写文件。扫描清单有变更时，应检查差异并与对应源码一起维护，不把它当成手工图标注册表。

扫描前会校验品牌名唯一性、`qs-*` 命名、清单与 SVG 的对应关系，以及正式注册导航是否引用已登记的品牌图标。静态扫描范围是正式应用 `src/` 和共享包的 `src/`，跳过 `_examples`、生成目录、`.example.` 文件、类型声明与清单自身；通用图标记录完整 `i-*:*` 字符串及其出现的源码位置。运行时拼接的名称不会自动进入清单，源码位置也不等于该图标在运行时一定可见。

SVG 校验同时要求平铺目录、统一视口和限定色板，仅接受几何图形及必要分组、说明标签，拒绝脚本、图片、外部引用、内联样式、事件属性和 XML 实体等内容。该检查约束文件格式；手绘风格、留白和缩小后的可读性仍须通过实际预览判断。

正式应用已有 `svgo` 脚本会批量优化图标目录。使用前先核对影响范围，使用后检查填色、描边、视口和视觉结果；优化通过不等于图标可读性通过。`generate:icons` 管理 Iconify 离线集合，与 `qs-*` SVG 制作、项目使用清单扫描是三件不同的事。

## 7. 图标示例库的使用

入口为“组件库 → 基础组件 → 图标示例库”，地址 `/component-library/basic/icons`。它复用组件库现有环境开关：开发环境注册，非开发构建需 `VITE_ENABLE_COMPONENT_LIBRARY=true`；生产环境默认不注册组件库入口。

页面用于：

- 按中文含义、英文图标名、分类和使用位置搜索项目图标。
- 区分品牌图标与现有通用图标，以默认 `24px` 预览，切换 `20 / 32px` 检查缩放外观。
- 在默认和选中背景下对照轮廓；预览背景读取当前侧边菜单主题变量，随应用切换亮色与暗色主题。
- 选择图标后查看名称、分类、用途与代码，复制 `FaIcon` 用法；复制失败时按页面反馈处理。

桌面在右侧展示所选图标详情；窄屏选择图标后通过 `QsGenericDrawer` 展示详情与复制入口，关闭后恢复焦点。

清单反映项目已登记或静态识别的图标，不是整个 Iconify 图标市场。新增源码引用后重新运行扫描，避免示例页内容滞后。

## 8. 验收与交付

验收先看实际显示，再看工程完整性：

- **视觉**：全套像同一套树木品牌图标；业务轮廓有区别；真实 `24px` 导航下无断笔、裁边、糊成一团或细节噪声，菜单行高保持一致。`20px` 对照仅用于检查简化轮廓，必须配合可读文字。
- **状态**：顶部、侧边和折叠菜单均可识别；默认、悬停、选中、亮色与暗色表现合理；品牌图标不被父级文字颜色误染。
- **交互**：菜单文字、权限和跳转正常；图标示例页搜索、分类、尺寸切换、选择和复制可用；窄屏可浏览，键盘焦点可见。
- **资产**：源文件为原生 SVG，透明背景；资产名、品牌清单、生成清单与调用一致；构建产物正确包含 spritemap，浏览器无缺失图标。
- **事实**：记录实际执行的验证和结果。只完成静态检查时不写“浏览器验收通过”；历史样稿不能替代本次真实项目验证。

仓库根的常用检查：

```bash
node web/scripts/generate-icon-inventory.mjs --check
node --test web/scripts/icon-inventory.test.mjs
pnpm -C web exec tsx --test scripts/icon-css.test.ts
pnpm -C web exec tsx --test \
  apps/qsmds-arco/test/api/component-library-routes.test.ts \
  apps/qsmds-arco/test/views/icon-library.logic.test.ts
pnpm -C web exec node --test scripts/frontend-handbook.test.mjs
pnpm -C web typecheck
pnpm -C web build
git diff --check
```

根据本次变更补充图标清单和示例页的定向测试；上述命令是检查入口，不代表文档发布时它们已经运行通过。

AI 生成的六枚样稿、菜单版 PNG 和场景效果图只负责确定构图与画风。正式项目使用可编辑、可缩放的 SVG 源资产，不嵌入历史 PNG，不通过白底抠图制造生产透明资源，也不把生成效果图描述为真实项目截图。
