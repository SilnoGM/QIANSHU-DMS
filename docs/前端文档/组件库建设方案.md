| 项目 | 说明 |
| --- | --- |
| 状态 | 方案已确认，阶段三 A 已完成，阶段三 B 暂缓，阶段四已启动 |
| 适用范围 | `web/apps/qsmds-arco` |

| 正式应用 | 千树 DMS Web |

## 1. 建设目的

组件库用于集中展示、调试和验收千树 DMS 自定义组件及页面组合方式，并为正式业务页面提供可复用的实现资产。

组件库不是另一套 Arco Design Vue 或 Fantastic-admin 文档站，也不是独立于正式应用长期演进的产品。组件实现应位于正式应用的组件目录中，组件库页面只是这些正式组件的一个内部消费者。组件完成后，正式业务页面直接引用组件源码，不引用组件库页面、示例数据或调试状态。

建设目标如下：

1. 为自定义基础组件提供可重复检查的状态和交互示例。
2. 为带有千树 DMS 领域语义的业务组件提供隔离调试入口。
3. 为列表页、详情页和表单页等常用页面结构提供组合参考。
4. 让组件在进入正式业务页面前完成类型、交互、响应式和视觉验收。
5. 保持组件实现、示例代码和正式业务页面之间的单向依赖。

## 2. 非目标

首期不处理以下事项：

- 不复制 Arco Design Vue 或 Fantastic-admin 已有的完整组件示例。
- 不建设 Storybook、Histoire 或独立组件文档站。
- 不新增公共 API、请求响应结构、数据库 schema 或权限数据。
- 不把仅有一个调用方的千树 DMS 组件提前抽取到 `web/packages/*`。
- 不让组件库示例页承担正式业务流程、真实数据维护或生产运维职责。
- 不用一个长期分叉的 Git 分支作为组件源码真相源。

当组件数量、独立文档需求或跨应用复用规模明显增长后，再依据真实成本评估是否引入独立组件工作台。本阶段遵循 YAGNI，复用正式应用已有的布局、主题、路由和响应式环境。

## 3. 当前工程基础

正式应用已经具备建设组件库所需的基础设施：

- `web/apps/qsmds-arco/src/settings.ts` 使用 `menu.mode = "head"`，页面采用顶部主导航和侧边次导航。
- `web/apps/qsmds-arco/src/router/routes.ts` 的 `asyncRoutes` 负责主导航分组。
- `web/apps/qsmds-arco/src/store/modules/app/route.ts` 支持 `meta.singleMenu`，可以把一级叶子路由包装进正式应用 Layout。
- `web/apps/qsmds-arco/src/store/modules/app/menu.ts` 根据已生成路由构造并过滤主导航和次导航。
- `web/packages/components` 已提供 Fantastic-admin 通用组件和上游示例，千树 DMS 组件库无需重复维护这些内容。

原 `ui_example` 只展示部分 Arco Design Vue 控件，没有接入当前 `asyncRoutes`，也不承担千树 DMS 自定义组件的正式职责。方案文档建立后，该旧示例已从正式应用源码中移除。

## 4. 信息架构

组件库采用一个主导航、三个分类入口和按组件拆分的叶子路由：

```text
组件库
├── 基础组件
│   ├── 金额显示    /component-library/basic/amount-display
│   ├── 金额输入    /component-library/basic/money-input
│   ├── 日期显示    /component-library/basic/date-time-display
│   ├── 轻提示      /component-library/basic/toast
│   └── 图片组      /component-library/basic/image-group
├── 业务组件
│   ├── 通用表格    /component-library/business/generic-table
│   ├── 通用抽屉    /component-library/business/generic-drawer
│   ├── 通用模态框  /component-library/business/generic-modal
│   ├── 产品提示    /component-library/business/good-tooltip
│   ├── 地区选择器  /component-library/business/region-selector
│   └── 字典选择器  /component-library/business/dictionary-select
└── 页面模板        /component-library/page-templates
```

三个分类的职责边界如下：

| 分类 | 主要内容 | 正式业务使用方式 | 禁止内容 |
| --- | --- | --- | --- |
| 基础组件 | 状态展示、通用筛选、金额输入与展示、空状态等低业务耦合组件 | 正式页面直接导入组件 | 单纯复制上游组件、页面专属业务流程 |
| 业务组件 | 用户选择、权限摘要、仓库选择等带领域语义的可复用交互 | 通过稳定的 `props`、`emits`、slots 和领域类型使用 | 示例 fixture、调试开关、写死的 API 地址 |
| 页面模板 | 列表页、详情页、表单页等页面组合参考 | 复用其中已抽出的组件和布局模式 | 将整个示例路由页面作为公共组件依赖 |

基础组件和业务组件只负责分类，不再聚合多个组件示例。每个可验收组件使用一个独立叶子路由和页面，确保菜单定位、直接刷新、标签页、面包屑及浏览器验收都对应唯一组件。页面模板当前只有分类骨架，继续保留单一叶子路由；出现真实模板资产后再按同一原则拆分。

## 5. 代码与目录边界

推荐目录如下：

```text
web/apps/qsmds-arco/src/
├── components/
│   ├── base/                       # 正式基础组件
│   └── business/                   # 正式业务组件
├── views/
│   └── component_library/
│       ├── basic/                  # 基础组件展示与调试
│       ├── business/               # 业务组件展示与调试
│       ├── page_templates/         # 页面模板展示
│       └── shared/                 # 仅供展示页面复用的工作台能力
└── router/
    └── modules/
        └── component.library.ts
```

目录使用以下依赖方向：

```text
正式业务页面 ───────→ 正式组件
组件库示例页 ───────→ 正式组件
组件库示例页 ───────→ 示例 fixture / 调试壳
正式组件      ──X──→ 组件库示例页
正式组件      ──X──→ 示例 fixture / 调试状态
正式业务页面  ──X──→ 组件库示例页
```

千树 DMS 自定义组件首期保留在 `apps/qsmds-arco/src/components/`。只有已经存在至少两个真实调用方、职责和接口稳定、没有业务语义并且能清晰测试的能力，才可以按《应用边界规范》评估是否抽取到 `web/packages/*`。

正式业务页面应显式导入新的嵌套组件。当前自动组件扫描只覆盖 `src/components/*/index.vue`，首期不扩大为深层全局注册，以便通过 import 明确依赖并避免组件名称冲突。

## 6. 组件设计约束

### 6.1 基础组件

- 使用英文组件名、文件名、`props`、`emits`、slots 和类型名。
- 用户可见文案默认使用中文，并允许调用方通过属性或 slots 覆盖。
- 不读取业务 Store，不调用业务 API，不了解具体权限码。
- 通过 `props` 接收数据，通过 `emits` 输出交互意图。
- 状态、尺寸、禁用、加载、空值和异常展示应有明确行为。

### 6.2 业务组件

- 可以依赖稳定的领域类型和业务 composable，但不能依赖组件库示例目录。
- 数据查询和写操作优先由正式页面或领域 composable 负责，组件不直接绑定示例请求。
- 如果组件必须自行加载数据，应提供明确的加载、失败、重试、取消和身份切换行为。
- 权限隐藏只属于体验层；涉及敏感业务操作时，Server 仍是最终授权边界。
- 不在日志、示例状态或错误展示中输出 token、Cookie、密码、连接字符串或完整敏感请求体。

### 6.3 页面模板

- 页面模板用于验证布局和组合方式，不定义新的公共 API 或领域数据结构。
- 模板中的列表、表单和详情数据使用不敏感的本地 fixture。
- 模板出现稳定重复结构后，先提取组件，再由模板和正式页面共同消费。
- 模板不是复制粘贴的永久真相源；实际业务页面仍需依据真实业务契约实现。

## 7. 示例与调试规范

每个进入组件库的组件至少应展示与其风险匹配的场景：

- 默认状态。
- 空值或无数据状态。
- 加载、禁用和只读状态。
- 错误或边界输入。
- 主要交互事件及其当前结果。
- 浅色和深色主题下的关键视觉状态。
- 桌面宽屏和窄屏布局；数据密集页面在窄屏优先使用卡片或 Drawer，而不是强制横向滚动桌面表格。

示例数据和交互状态放在 `views/component_library/` 内，不反向进入正式组件。默认示例不得调用会修改真实业务数据的 API；确需联调写接口时，必须单独说明目标环境、账号权限、数据影响和恢复方式，并获得对应授权。

组件库不是自动化测试的替代品。示例页负责人工观察和交互调试，自动化测试负责稳定验证接口、状态转换和关键回归。

## 8. 路由与菜单设计

组件库路由集中定义在 `router/modules/component.library.ts`，再由 `router/routes.ts` 放入标题为“组件库”的独立主导航分组。

基础组件和业务组件是使用正式 Layout 的分类父路由，并显式重定向到首个组件；组件叶子使用相对 path 作为可见叶子路由，完整清单以 `router/modules/component.library.ts` 为准（下表仅保留阶段设计时的示例）：

| 类型 | 标题 | path | route name |
| --- | --- | --- | --- |
| 分类父路由 | 基础组件 | `/component-library/basic` | `componentLibraryBasic` |
| 组件叶子 | 金额显示 | `amount-display` | `componentLibraryAmountDisplay` |
| 组件叶子 | 金额输入 | `money-input` | `componentLibraryMoneyInput` |
| 组件叶子 | 日期显示 | `date-time-display` | `componentLibraryDateTimeDisplay` |
| 组件叶子 | 轻提示 | `toast` | `componentLibraryQsToast` |
| 组件叶子 | 图片组 | `image-group` | `componentLibraryImageGroup` |
| 分类父路由 | 业务组件 | `/component-library/business` | `componentLibraryBusiness` |
| 组件叶子 | 通用表格 | `generic-table` | `componentLibraryGenericTable` |
| 组件叶子 | 通用抽屉 | `generic-drawer` | `componentLibraryGenericDrawer` |
| 组件叶子 | 通用模态框 | `generic-modal` | `componentLibraryGenericModal` |
| 组件叶子 | 产品提示 | `good-tooltip` | `componentLibraryQsGoodTooltip` |
| 组件叶子 | 地区选择器 | `region-selector` | `componentLibraryQsRegionSelector` |
| 组件叶子 | 字典选择器 | `dictionary-select` | `componentLibraryQsDictionarySelect` |
| 单一叶子 | 页面模板 | `/component-library/page-templates` | `componentLibraryPageTemplates` |

路由实现必须满足：

- 不放入 `constantRoutes` 或 `systemRoutes`。
- route name 全局唯一。
- 页面通过动态 import 加载。
- 分类父路由不得设置 `singleMenu`，否则 route Store 会用包装后的隐藏页面覆盖真实 children。
- 组件子路由使用相对 path，不设置 `menu: false`；父路径使用命名 redirect 保持旧地址可用。
- 主导航、三个分类和组件叶子具有清晰、稳定的中文标题及合适图标。
- 组件库关闭时不注册对应路由，不能只通过 CSS 隐藏菜单。
- 新增组件时同步验证父路由跳转、菜单展开、面包屑和独立标签页行为。

## 9. 环境与权限策略

组件库定位为内部开发能力，生产环境默认关闭。建议使用公开的构建变量 `VITE_ENABLE_COMPONENT_LIBRARY` 控制是否注册路由：

| 环境 | 默认策略 |
| --- | --- |
| development | 开启，供本地开发调试 |
| test / preview | 通过 `VITE_ENABLE_COMPONENT_LIBRARY=true` 显式开启 |
| production | 默认关闭，不注册路由 |

只允许提交 `.env.*.example` 和对应的环境类型声明，不提交真实 `.env`。所有 `VITE_` 变量都会进入浏览器产物，不得包含密钥或敏感配置。

首期不新增权限码。若未来需要在生产环境向特定账号开放，必须单独确认后再设计 `component-library:read` 等权限、服务端权限目录和授权数据。前端 `meta.auth` 只能收敛菜单和页面体验，不能替代服务端授权。

## 10. 开发与验收流程

组件库基础设施、新组件和复杂交互按 TDD 实施：

1. 先编写路由契约、纯逻辑或关键交互的失败测试，确认 RED 原因与需求一致。
2. 完成满足测试的最小实现。
3. 将组件接入组件库示例页，验证主要状态和响应式行为。
4. 运行定向测试、Web 完整检查和正式构建。
5. 启动正式应用，在真实浏览器中验证菜单、页面、主题和窄屏行为。
6. 核对暂存范围后提交，不提交真实 `.env`、生成目录、构建产物或日志。

基础设施实施后的最低验证命令为：

```bash
pnpm -C web test:api
pnpm -C web typecheck
pnpm -C web lint
pnpm -C web build
```

需要查看实际效果时运行：

```bash
pnpm -C web dev
```

浏览器验收至少包括：

- 登录后出现“组件库”主导航。
- 次导航按顺序显示“基础组件”“业务组件”“页面模板”，并在分类下展示对应组件。
- 金额显示、金额输入、日期显示、轻提示、图片组、通用表格、通用抽屉、通用模态框、产品提示、地区选择器和字典选择器 11 个组件 URL 可以直接进入并在刷新后恢复。
- `/component-library/basic` 重定向到金额显示，`/component-library/business` 重定向到通用表格。
- 每个组件页面只挂载一个顶层 Showcase，页面模板入口行为保持不变。
- 生产关闭条件下菜单和路由都不存在。
- 页面在浅色、深色、桌面和窄屏条件下没有明显布局问题。
- 正式业务页面能够直接导入组件，且没有引用组件库示例目录。

## 11. Git 策略

`feat/component-library` 只用于建立首期组件库基础设施，是短期功能分支，不作为长期组件开发分支。

首期按以下小步提交：

1. 组件库建设方案文档。
2. 删除旧 `ui_example`。
3. 路由契约测试。
4. 组件库导航和三个分类骨架。
5. 第一个真实组件、示例和测试。
6. 按组件拆分独立叶子路由。

完成验证后将分支合入主干。以后新增组件使用与需求对应的短期功能分支，并在同一变更中维护正式组件、组件库示例和自动化测试，避免组件库与正式业务长期漂移。

Commit Message 使用英文 type 和中文描述，例如：

```text
docs: 添加组件库建设方案
refactor: 移除旧 UI 示例页面
test: 添加组件库路由契约
feat: 添加组件库导航骨架
```

`push`、创建 PR、合并、Tag 和发布仍需依据当次明确授权执行。

阶段四首个增量资产为 `DateTimeDisplay`。组件接收 `value: string | number | Date | null`，提供 `format?: "date" | "datetime" | "time"` 与 `timeZone?: string`；默认使用 `datetime` 和 `Asia/Shanghai`，输出固定数字宽度的 24 小时制日期时间。示例覆盖上海、台北、吉隆坡与纽约四个 IANA 时区，并展示日期、日期时间、时间、Unix 毫秒时间戳和空值状态。

阶段四同时新增 `MoneyInput` 金额输入基础组件。组件以 `FaInput` 为内核，对外金额使用 `string | null`，币种通过独立的 `v-model:currency` 保存并默认使用 `CNY`；右侧下拉仅切换 `CNY`、`TWD`、`MYR`、`USD`，不会改写金额或执行隐式汇率换算。组件严格拒绝空字符串、币种符号、千分位、科学计数法、非规范前导零和超精度小数；合法值失焦后按 `precision` 补齐。`decimal.js` 只用于精确比较、规范化和同币种 `sumMoneyValues` 列汇总，组件与 API 不暴露 `Decimal` 实例。金额展示继续复用 `AmountDisplay`；精确表格汇总通过现有 `summaryValues` 注入，不改变 `QsGenericTable` 公共列协议。

阶段四新增 `QsToast` 作为项目级轻提示基础组件。组件通过 `useFaToast().custom()` 复用全局队列、计时、堆叠、悬停暂停、移动端手势和安全区能力，只接管中性浮层、局部状态色、图标、操作与关闭视觉；`useQsToast()` 对外提供 `show`、五种语义状态、`promise` 和 `dismiss`。调用方不能注入任意样式、图标或 Vue 组件，也不能传入底层 id。由于当前 `vue-sonner@2.0.9` 不会为同 id 的 custom toast 重置时长，Promise 完成后先关闭永久 loading，再创建结果提示，以保证成功或失败提示能够按默认时长消失。

字符串输入只接受带显式 `Z` 或 UTC offset 的 ISO 8601 日期时间，拒绝无时区字符串和非法日历值；`number` 始终解释为 Unix 毫秒，不推测秒级时间戳。空值、无效日期或非法 IANA 时区统一显示 `—`。组件使用浏览器原生 `Intl.DateTimeFormat`，没有新增日期依赖，也不读取业务 API、Store 或 fixture。

依据本次明确范围，`DateTimeDisplay` 先完成组件库展示与调试闭环，不要求在真实业务页面中使用；后续由实际 OpenAPI 时间字段和业务时区规则驱动正式复用。

阶段四新增 `QsGenericDrawer` 作为任务型业务容器。第一版提供右侧和底部两种方向、`sm` 至 `xl` 四档右侧尺寸、Loading 骨架、Error Alert、Submitting 锁定、声明式 Footer、四类关闭原因与异步关闭守卫。组件继续以 `FaDrawer` 为内核，不引入 Arco Drawer，也不内置表单、权限、请求或固定业务动作。

`QsGenericDrawer` 同时修复了 `FaDrawer` 使用自定义 Header 时隐藏标题为空的问题，确保抽屉仍具有真实可访问名称。当前只完成组件库展示与测试闭环，不要求迁移已有业务页面；命令式服务、嵌套抽屉栈、拖拽和桌面全屏仍不属于第一版。

阶段四同时新增 `QsGenericModal` 作为聚焦式业务任务容器。第一版提供 `sm` 至 `xl` 四档响应式尺寸、Loading 骨架、Error Alert、Submitting 锁定、声明式 Footer、四类关闭原因与异步关闭守卫。组件以加固后的 `FaModal` 为内核，不引入 Arco Modal，也不内置表单、权限、请求或固定业务动作。

为满足业务模态框前置契约，`FaModal` 已改为真正的 Reka 模态语义，并统一单一 Overlay、背景滚动锁、焦点范围和关闭焦点恢复；自定义 Header 继续使用隐藏的真实标题与说明。当前只完成组件库展示与测试闭环，不要求迁移已有业务页面；命令式服务、嵌套模态框栈、拖拽和最大化仍不属于 `QsGenericModal` 第一版。

阶段四新增 `ImageGroup` 作为无业务语义的图片组基础组件。组件使用原生缩略图和 `useFaImagePreview()`，默认通过逐图 `FaTooltip` 展示对应图片与序号；调用方负责把产品、SKU 或附件字段映射为 `ImageGroupItem[]`。组件覆盖受控尺寸、圆角、重叠、`+N` 溢出、失败占位、方向键导航和窄屏卡片组合，不读取 API、Store 或领域 DTO。

阶段四同时新增 `QsGoodTooltip` 作为产品信息提示业务组件。完整包装器以 `FaTooltip` 为内核，`QsGoodTooltipContent` 只固定左侧方形图片和右侧只读信息区域，两者都不接收完整 SPU / SKU 对象。每张图片对应不同产品时，调用方通过 `ImageGroup` 的逐项 `tooltip` 插槽按稳定 `item.key` 渲染 `QsGoodTooltipContent`；整个图片组对应同一产品时，可以使用外层 `QsGoodTooltip` 并传入 `:tooltip="false"`。`ImageGroup` 始终不依赖业务组件，也不增加产品字段或 `tooltipType`。

阶段四新增 `QsReconciliationLineSwitcher` 作为对账域的明细行切换业务组件。折叠条带按 `visibleSideCount` 贴边铺满真实项（默认每侧 3 项，不补空槽位，因此首尾处选中项会移动到条带两端），选中项放大并显示绿色文字 / 边框 / 浅绿底，每块底部有按状态着色的横条；展开形态左对齐换行展示全部行。组件受控（`v-model` 持有选中行 id），不读 API、Store 与路由；状态取值与语义色由 `items.status` 与 `statusTones` 给出，未登记的状态回落中性灰，组件内不出现任何状态字面量。上一条 / 下一条到首尾禁用而不循环，窄容器下条带横向滚动并把选中项对齐视口正中，空数组与单项各有明确空态与禁用。
