# 前端接口接入规范

本文记录 `web/apps/qsmds-arco/` 当前已经实施的 OpenAPI types-only、Axios response、错误、重试和 fake route 规则。Web 与 Server 是独立依赖域；类型生成不等于跨目录源码依赖。

## 1. 快照与类型生成

### 1.1 真相源与文件边界

- `server/openapi/openapi.json` 是 Server 生成快照。
- `web/openapi/openapi.json` 是 Web 自包含快照，也是 Web 独立移植后的生成输入。
- 两份 snapshot 必须字节一致，只能从仓库根运行 `contract:sync` 更新；Web 不直接读取 Server 源码或依赖目录。
- `apps/qsmds-arco/src/api/generated/` 是 ignored 生成目录，必须精确只包含一个非空 regular `types.gen.ts`，不得手工修改或提交。

### 1.2 生成命令与 lifecycle

```bash
pnpm -C web api:generate
```

`api:generate` 只读 `web/openapi/openapi.json`，以 `@hey-api/openapi-ts` 的 types-only 配置重建 generated directory，不生成运行时 Client。输出路径经过 real directory、symlink 和边界检查；安全 override 失败时只清理 wrapper 取得所有权的临时输出。默认输出使用 `clean: true`，默认生成失败不承诺恢复旧目录；需要跨端事务式发布与回滚时必须使用根 `contract:sync`。

正式 app 的 `lint`、`typecheck`、`build`、`build:test`，以及 Web 根的 `test:api` 都通过 lifecycle 先执行生成。因此删除 ignored generated directory 后直接运行这些入口仍可工作。

跨端更新与检查使用：

```bash
node --run contract:sync
node --run contract:check
```

## 2. 成功响应

Axios Client 的成功路径保留完整 `AxiosResponse<T>`，不在 interceptor 中自动解包 `response.data`。这样调用方可以读取 HTTP status、Header 和业务 DTO，类型声明与运行时保持一致。

health 的成功 DTO 直接取自 generated alias `HealthGetResponses[200]`，不在 Web 手写重复结构。

health module 直接复用生成类型：

```ts
export type HealthResponse = HealthGetResponses[200]

export function getHealth(
  client: AxiosInstance = api,
): Promise<AxiosResponse<HealthResponse>> {
  return client.get<HealthResponse>('/health')
}
```

Store 和业务调用方继续显式从 `res.data` 读取裸 DTO。例如登录读取 `AuthContextDto` 中的 `user`、`session` 和 `permissions`，通知模块读取 `res.data.message`，不能假设 Client 已经返回 body。

## 3. 错误与 Blob

### 3.1 ApiClientError

最终 Axios error 统一收敛为可判别联合 `ApiClientError`：

```ts
type ApiClientError =
  | { kind: 'http'; status: number; body: ApiError }
  | {
    kind: 'http-unparseable'
    status: number
    requestId?: string
    message: '服务器返回了无法识别的错误响应'
  }
  | {
    kind: 'network'
    code: 'NETWORK_ERROR'
    message: '网络连接失败，请稍后重试'
  }
```

`ApiError` 类型来自 generated `types.gen.ts`，运行时仍由严格 guard 校验 `code`、`message`、`requestId` 和可选 `fieldErrors`。不得向 UI 复制 Axios `message`、`stack`、未知 body 或 hook exception。

### 3.2 Blob 错误

下载接口可能在失败时仍由 Axios 交付 Blob。只有同时满足以下条件才尝试解析 `ApiError`：

- body 是 Blob，且大小不超过 `1 MiB`；
- HTTP response 的 `Content-Type` 明确为 `application/json` 或 `application/*+json`；
- `Blob.text()`、JSON parse 和 `isApiError` 全部成功。

`Blob.type` 可能由浏览器或调用方推断，当前实现不读取或要求 `Blob.type`，只信任真实 HTTP response 的 `Content-Type`。也不能读取超过限制的大 body；任何 getter、解析或内容校验失败都收敛为 `http-unparseable`，并尽量保留安全的 `X-Request-Id`。

### 3.3 401 与 403

- 当前身份域中可识别的 `401 AUTHENTICATION_REQUIRED` 只调用统一 `handleSessionInvalid`，不额外 toast。
- 最终 `403` 只提示 `没有权限执行此操作`，不登出。
- 其他 HTTP 或 network 错误只显示契约文案或固定安全文案。
- side-effect hook 的同步 throw、Promise reject 或 thenable reject 不能替换已经规范化的错误，也不能写入日志。

## 4. 重试与取消

重试不是默认行为；只有请求显式配置 `retry: true` 时才参与判断。

| 条件 | 允许重试 |
| --- | --- |
| method | `GET`、`HEAD`、`OPTIONS`、`PUT` |
| network error | 允许 |
| HTTP status | `502`、`503`、`504` |
| 其他 method/status | 禁止 |
| 最大次数 | 最多重试 3 次，即 adapter 总调用最多 4 次 |

默认退避是 `500/1000/2000 ms`。只有 `503` 读取 `Retry-After`；它接受完整非负整数秒和 RFC 9110 的三种 HTTP-date，等待上限为 `5000 ms`，无效值回退到默认退避。

重试在 adapter wrapper 内复用同一 request config，不重复执行 transform 或公开 interceptor。每次尝试前重新读取语言并再次删除调用方可能注入的历史 `Token` Header；身份只由浏览器同源 Cookie 携带。

取消优先于重试和错误归一化：

- 发送前已经 aborted 时不读取 hooks、不调用 adapter；
- 等待期间 abort 时停止后续尝试；
- Axios `CanceledError` 保留对象身份；
- 取消不 toast、不登出，也不转换为 `ApiClientError`。

## 5. Fake 与网络前提

正式业务 app 当前保留 9 个 `fake: true` 调用，只服务动态路由、偏好、标签栏、收藏和通知等非认证框架能力。它们的成功 route 直接返回裸 DTO，不再使用 `{ status, error, data }` envelope；Store 仍从完整 Axios response 的 `res.data` 读取这些 DTO。

登录、当前身份、改密、退出、用户、角色、权限目录和审计均使用 Server OpenAPI 声明的真实接口。fake route 不提供账号、Token 或权限真相，也不能参与 `isLogin` 判定；真实认证失败使用 OpenAPI 中的 `ApiError`，确定的 Session 失效码为 `AUTHENTICATION_REQUIRED`。

生产 Client 默认 base URL 为 `/api`；开发代理启用时使用 `/proxy/`，fake 请求使用 `/fake/`。这些相对路径要求 Web 与 Server 位于同源部署或由网关/开发服务器配置反向代理。当前实现不声称支持跨域部署；若未来改为跨域，必须同步设计 CORS、Cookie、CSRF、可信 origin 和环境变量，并通过 `Access-Control-Expose-Headers: X-Request-Id, Retry-After` 向浏览器暴露契约依赖的响应头，不能只替换 URL。

## 6. 调用示例

```ts
const response = await getHealth()

if (response.status === 200) {
  const health = response.data
  // 业务只读取契约字段；X-Request-Id 可从 response.headers 获取并用于问题关联。
}
```

需要重试的幂等读取必须显式声明：

```ts
const response = await api.get<ResourceDto>('/resources/current', {
  retry: true,
})
```

不要为 `POST` 等非幂等写操作开启通用自动重试；需要幂等写入时应先设计 idempotency key 与 Server 契约。

## 7. 修改检查清单

1. 公共 API 或数据结构变更先取得用户确认。
2. 从根运行 `node --run contract:sync` 更新双方 snapshot 与 generated types。
3. 在 Web 中只导入 generated type，不导入 Server 源码。
4. 保持 Client 返回 `AxiosResponse<T>`，由调用方显式读取 `res.data`。
5. 为 error、Blob、重试、取消和 fake route 增加相应测试。
6. 运行 `node --run contract:check`、`pnpm -C web test:api`、`pnpm -C web check` 与 `pnpm -C web build`。
