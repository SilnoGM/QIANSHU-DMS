# 前端架构

## 1. 文档目的

本文定义千树 DMS 前端的物理边界、目录职责、依赖方向、技术栈和独立交付方式。适用范围是 `web/` 目录，不替代具体业务模块设计。

## 2. 架构结论

`web/` 是独立 pnpm workspace，拥有自己的 `package.json`、`pnpm-workspace.yaml` 和 `pnpm-lock.yaml`。它可以脱离仓库根目录和 `server/` 独立安装、构建、验证与发布。

根目录只负责无第三方依赖的前后端命令编排，不参与 Web 的依赖解析。Web 与 Server 之间不共享源码或依赖，通过 HTTP 与 OpenAPI 契约协作。

## 3. 目录模型

```text
web/
├── apps/
│   └── qsmds-arco/         # 唯一正式业务应用
├── examples/
│   ├── core/               # 初始框架基座参考
│   ├── core-arco-design-vue/
│   └── example/            # 示例参考
├── packages/               # 稳定共享能力
├── openapi/
│   └── openapi.json        # Web 自包含契约快照
├── scripts/                # 工程脚本和脚本测试
├── skills/                 # Web 项目级 Skill
├── package.json
├── pnpm-workspace.yaml
└── pnpm-lock.yaml
```

目录职责如下：

| 目录 | 职责 | 默认是否可写 |
| --- | --- | --- |
| `apps/qsmds-arco` | 正式业务页面、路由、API、Store、应用配置和业务文案 | 是 |
| `examples/*` | 保存初始基座和示例，供查阅与对照 | 否；只有用户明确点名具体参考应用并明确要求修改时才写入 |
| `packages/*` | 组件、组合式函数、主题、语言基础设施、设置等稳定共享能力 | 满足共享标准时可写 |
| `scripts/` | Web 工作区编排、约束检查和交互式 CLI | 工程需求下可写 |
| `skills/` | 项目内可复用的协作步骤与路径约束 | 维护 Skill 时可写 |
| `openapi/` | Web 独立移植时使用的已跟踪 OpenAPI snapshot | 只允许根 `contract:sync` 更新 |
| `apps/qsmds-arco/src/api/generated/` | 从 Web snapshot 重建的 types-only 产物 | ignored；不得手工修改或提交 |

## 4. 技术栈真相

当前版本以 `web/package.json`、`web/pnpm-workspace.yaml` 和 `web/pnpm-lock.yaml` 为真相源：

- Vue 3.5
- TypeScript 6
- Vite 8
- Arco Design Vue
- Pinia
- Vue Router
- UnoCSS
- pnpm 11.9

参考应用可能包含其他 UI 方案，但不能据此改变正式业务应用的技术栈描述。

版本字段承担不同职责：

- `web/package.json.version = 6.3.0` 是 Fantastic Admin 上游基座版本，不是千树 DMS 的产品 version。
- `apps/qsmds-arco/package.json.version` 是正式 Web app 的产品 version，正式发布前必须与仓库根产品 version 和 Server 产品 version 保持一致。
- Web 不提供 `release: bumpp` 或其他 `bumpp` 入口；产品版本准备和 Tag 创建由仓库根发布流程统一约束。

## 5. 依赖方向

核心方向是 `apps → packages`，具体规则为：

```text
apps/qsmds-arco ──────→ packages/*
examples/* ───────────→ packages/*

packages/*      ──X──→ apps/qsmds-arco
packages/*      ──X──→ examples/*
apps/qsmds-arco ──X──→ examples/*
examples/*      ──X──→ apps/qsmds-arco
web/            ──X──→ server/ source or dependencies
```

Web 内部只有 `packages/*` 等 workspace 成员之间可以按职责使用 `workspace:*`。禁止使用 `file:`、`link:`、绝对路径或越过 `web/` 的相对路径连接 Server 或仓库根目录源码。

共享包不得承载千树 DMS 领域规则、业务 API、业务页面或仅由一个业务场景使用的 Store。新增共享包或抽取共享能力遵循 YAGNI：必须已有至少两个真实调用方、职责稳定、接口可清晰测试，并且不含业务语义。未来可能复用和参考应用中存在相似代码都不能单独构成抽取理由。

## 6. 命令入口

默认入口始终面向正式业务应用：

| 命令 | 作用范围 |
| --- | --- |
| `pnpm dev` | 启动 `apps/qsmds-arco` |
| `pnpm api:generate` | 从 Web snapshot 重建正式 app 的 API types |
| `pnpm test:api` | 生成后运行正式 app API contract tests |
| `pnpm check` | 检查正式业务应用、必要共享包和工程脚本 |
| `pnpm build` | 构建 `apps/qsmds-arco` |

参考应用采用显式命令，避免日常业务开发误操作：

| 命令 | 用途 |
| --- | --- |
| `pnpm check:examples` | 检查全部参考应用 |
| `pnpm build:examples` | 构建全部参考应用 |
| `pnpm dev:select` | 交互式选择要启动的应用 |
| `pnpm build:select` | 交互式选择要构建的应用 |
| `pnpm serve:select` | 交互式选择要预览的应用 |

所有命令都在 `web/` 目录执行。`pnpm lint` 只检查；需要自动修复时显式使用 `pnpm lint:fix`，不能依赖 Git hook 或 `lint-staged` 自动执行。

## 7. 配置与安全

- 只提交 `.env.*.example` 模板，真实 `.env` 和 `.env.*` 必须保持忽略。
- 模板不得包含 token、密码、连接字符串、Cookie 或真实服务凭据。
- `VITE_` 变量会进入浏览器构建产物，必须按公开信息处理。
- 用户可见文案默认使用中文；代码、命令、路径、变量、API、字段和错误码等技术资产使用英文。
- 日志不得泄露敏感请求体或身份凭据。

## 8. 前后端契约

Web 通过 HTTP 调用 Server，并以 OpenAPI 作为接口结构真相源。`web/openapi/openapi.json` 是 Web 自包含 snapshot；`api:generate` 只读该文件，重建 ignored `apps/qsmds-arco/src/api/generated/`，且目录精确只含非空 `types.gen.ts`。

正式 app 的 `lint`、`typecheck`、`build`、`build:test` 与 Web `test:api` 都通过 lifecycle 先生成。跨端 snapshot 只通过根 `contract:sync` 更新，由 `contract:check` 只读验证；Web 不读取 Server 源码或依赖目录。

Axios 成功路径保留完整 `AxiosResponse<T>`，调用方显式读取 `res.data`；`ApiClientError`、Blob 限制、`401/403`、取消、受限重试和 fake 裸 DTO 的详细规则见[接口接入规范](./接口接入规范.md)。

当前相对 base URL 以同源或反向代理为前提，不声称支持跨域部署。任何新增或修改公共 API、请求响应数据结构的工作都必须先取得用户确认，并同步评估 Web 与 Server 影响。

## 9. 独立移植与发布

独立移植必须完整复制 `web/` 下的源码、`web/openapi/openapi.json`、workspace 配置、`pnpm-lock.yaml`、工程脚本和 `.env.*.example`，不得复制 `node_modules/`、`dist/`、真实 `.env`、generated types 或日志。

移植后从新的 `web/` 根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm check:examples
pnpm build:examples
```

上述流程不得访问原仓库根目录或 `server/node_modules/`。正式发布产物来自 `apps/qsmds-arco`；参考应用构建只用于验证基座没有失效，不进入正式产品发布物。

Web 仍可独立安装、检查、构建和移植，也可以按需独立生成和交付自身产物。仓库正式产品 Release 从同一个 Tag Commit 同时重新构建 Web 与 Server，以保证两端产物对应同一份已审查源码；该发布编排不改变依赖域，Web 与 Server 仍分别维护自己的依赖清单、lockfile 和安装目录，不产生跨目录依赖。

GitHub CI、Tag 与 Release 结论必须绑定对应 SHA、Run 和产物；历史验收参阅发布与版本管理文档，不以本地结果或历史成功替代当前平台验证。
