# 全局字体统一设计

## 文档状态

- 状态：已确认，分阶段实施
- 正式应用：`web/apps/qsmds-arco`
- 字体资源基线：Google Fonts CSS2 API 于 2026-07-22 的固定快照
- 本阶段：设计文档与本地 WOFF2 资源入库，尚未切换正式应用字体

## 背景与目标

正式应用当前同时存在 Arco Design 系统字体栈、首屏 Loading 独立字体栈、业务表格系统字体栈、SF Mono 数据字体和代码组件专用字体。不同设备会选中不同平台字体，导致字形、字宽、行高、换行位置和数字对齐不一致。

本设计的目标是：

1. 正文、表单、导航、表格和业务数据统一使用本地 `Noto Sans SC`。
2. 代码、用户名、单号和明确的等宽数据优先使用本地 `Noto Sans Mono`，其中文字形回到 `Noto Sans SC`。
3. 正常业务文本不再依赖系统正文或系统等宽字体。
4. 字体在项目中同源加载，生产构建不访问 Google Fonts 或其他字体 CDN。
5. 使用固定 `unicode-range` 分片按字符按需下载，不扫描 Vue 构建 HTML，不引入 `font-spider`。

本设计统一的是字形设计、排版指标和业务布局。操作系统和浏览器的抗锯齿、子像素渲染、缩放策略仍可能产生小幅差异，不把跨设备逐像素完全一致作为验收目标。

## 非目标

- 不引入第三个业务文本字体家族。
- 不在正常 `dev`、`check`或 `build` 过程中下载或重新裁剪字体。
- 不用当次源码出现的字符集合作为动态字体真相源。
- 不要求原生 Emoji 跨系统视觉一致。
- 不在本方案中改变业务 API、数据结构或数据库 schema。

## 字体家族与字重

### Noto Sans SC

- 用途：全局正文、导航、标题、表单、表格、按钮和中文等宽内容的字形回退。
- 样式：`normal`。
- Variable 字重范围：`300–700`。
- 不声明 `local()`，避免设备已安装的同名不同版本绕过项目 WOFF2。

### Noto Sans Mono

- 用途：代码、用户名、订单号、结算单号以及其他明确需要稳定字符宽度的数据。
- 样式：`normal`。
- 宽度轴：`wdth=100`。
- Variable 字重范围：`400–700`。
- `Noto Sans Mono` 不承担中文字形，等宽语义栈必须将 `Noto Sans SC` 放在其后。

正式应用当前使用 `300`、`400`、`500`、`600`、`700` 字重。字体切换时应设置 `font-synthesis: none`，避免浏览器伪造未声明字重。

## 全局字体 Token

目标 Token 将正文字体、等宽字体和原生 Emoji 例外分开声明：

```css
:root {
  --qs-font-text-sans: "Noto Sans SC";
  --qs-font-text-mono: "Noto Sans Mono", "Noto Sans SC";
  --qs-font-native-emoji:
    "Apple Color Emoji",
    "Segoe UI Emoji",
    "Noto Color Emoji";

  --qs-font-sans:
    var(--qs-font-text-sans),
    var(--qs-font-native-emoji);

  --qs-font-mono:
    var(--qs-font-text-mono),
    var(--qs-font-native-emoji);
}
```

全局栈不追加 `system-ui`、`sans-serif`、`ui-monospace` 或 `monospace`。设备原生 Emoji 字体是唯一允许的系统字体例外，只用于 Noto 不提供的 Emoji 字形。

## 原生 Emoji 策略

正式应用允许用户输入、备注和非关键装饰文案使用原生 Emoji，并接受 Apple、Windows、Android 和 Linux 之间的 Emoji 外观差异。

为避免功能语义受 Emoji 差异影响：

- 保存、删除、成功、失败、警告等功能图标仍使用 Iconify 或本地 SVG。
- 关键状态不能只用 Emoji 表达，必须同时具有文字或无障碍名称。
- 字符计数、截断和长度校验应按 grapheme cluster 处理，不直接用 UTF-16 `length` 或 `slice()` 截断 ZWJ、肤色或国旗序列。
- 不下载、分片或预加载 Emoji 字体。

## 固定 Unicode 分片

字体资源直接捕获 Google Fonts CSS2 API 为现代 Chromium User-Agent 返回的 Variable WOFF2 和 `unicode-range`。这些响应会被本地化、校验和提交，后续构建不再访问 Google。

固定请求：

```text
https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@300..700&display=block
https://fonts.googleapis.com/css2?family=Noto+Sans+Mono:wdth,wght@100,400..700&display=block
```

获取条件：

- 固定 CSS2 API URL。
- 固定支持 Variable WOFF2 的 Chromium User-Agent。
- 不传入 `text=`，避免生成依赖当次文字的临时子集。
- 本地 CSS 保留每个 `@font-face` 的原始 `unicode-range`，只将 `fonts.gstatic.com` URL 改为本地相对 URL。
- 每个 WOFF2 使用内容 SHA-256 生成本地文件名，便于不可变缓存和完整性审计。

2026-07-22 在固定 Chromium User-Agent 下的首次基线预期为：

| 字体 | 字重 / 宽度 | WOFF2 分片数 |
| --- | --- | ---: |
| Noto Sans SC | `wght=300..700` | 101 |
| Noto Sans Mono | `wdth=100, wght=400..700` | 7 |

分片数不是永久不变的上游契约。项目真相源是已提交的本地 CSS、`manifest.json` 和 `SHA256SUMS`；任何重新获取都是一次显式字体升级，必须审查分片数、字重、Unicode 范围、文件 Hash 和视觉回归。

## 资源存储与发布

字体快照存放于：

```text
web/apps/qsmds-arco/public/assets/fonts/noto/google-fonts-css2-2026-07-22/
├── manifest.json
├── SHA256SUMS
├── noto-sans-sc/
│   ├── fonts.css
│   ├── OFL.txt
│   └── *.woff2
└── noto-sans-mono/
    ├── fonts.css
    ├── OFL.txt
    └── *.woff2
```

选择 `public/assets/` 的原因：

1. 首屏 HTML 可以在 Vue 入口执行前直接引用字体 CSS。
2. Vite 只负责原样复制已固定资源，不在构建期联网。
3. 内容 Hash 文件名可配置 `Cache-Control: public, max-age=31536000, immutable`。
4. `index.html` 和字体 CSS 仍应支持重验证，避免长缓存指向被删除的旧分片。

OFL 许可文本必须随字体资源一起分发。`manifest.json` 至少记录请求 URL、User-Agent、获取日期、上源 URL、本地文件名、字节数、SHA-256 和 `unicode-range`。

## 加载与首屏策略

后续实施阶段在 `index.html` 的 `<head>` 中提前加载两份本地字体 CSS，使首屏 Loading 与正式应用共用同一字体声明。

预加载仅用于首屏真正需要的少量核心分片，不预加载全部 108 个 WOFF2。其他分片由浏览器按 `unicode-range` 和页面实际字符请求。

为避免正式应用在本地字体就绪前显示系统文本字体：

- `@font-face` 使用 `font-display: block`。
- 首屏退出路径在现有最短展示时间之外，显式等待核心 Sans 和 Mono 样本通过 `document.fonts.load()`。
- 字体加载失败时不无限阻塞，应进入可诊断的字体资源失败状态，不静默降级到系统正文字体。
- 原生 Emoji 字体不参与就绪等待。

## 构建与维护流程

正常开发与生产流程：

```text
已提交的 CSS / WOFF2 / OFL / manifest
  -> 本地完整性校验
  -> Vite 构建原样复制
  -> 构建产物校验
  -> 同源部署
```

字体升级流程：

```text
显式运行字体获取脚本
  -> 固定 CSS2 API 响应
  -> 下载并校验 WOFF2
  -> 改写为本地 URL
  -> 生成 manifest 与 SHA256SUMS
  -> 人工审查差异
  -> 浏览器回归
  -> 提交新快照
```

获取脚本不接入 `prebuild`、`build` 或 CI 的默认路径。CI 只验证已提交快照，保持无网络、可重复构建。

## 测试与验收

### 静态资源验证

- 字体目录和所有必需文件存在且不是符号链接。
- WOFF2 魔数为 `wOF2`。
- 字体家族、字重、宽度和分片数与 `manifest.json` 一致。
- 每个 WOFF2 的字节数和 SHA-256 与 manifest 一致。
- `SHA256SUMS` 覆盖除自身以外的全部快照文件。
- 本地 CSS 不存在 `fonts.googleapis.com`、`fonts.gstatic.com` 或其他外部字体 URL。
- CSS 中的每个本地 WOFF2 都存在，每个已提交 WOFF2 都被 CSS 引用。

### 构建产物验证

- `dist` 中存在本地字体 CSS、WOFF2、OFL 和 manifest。
- HTML 和 CSS 没有 Google Fonts 运行时请求。
- 字体资源使用 `font/woff2` MIME type，内容 Hash 文件使用 immutable 缓存。

### 浏览器验证

- `document.fonts.check()` 对 Sans 和 Mono 核心样本成功。
- `body`、表单控件、表格、金额、用户名和代码块的计算字体栈符合约定。
- 加载分属不同 `unicode-range` 的样本字符时，仅请求匹配分片。
- 不请求 Google Fonts、第三方字体 CDN 或已停用专用字体。
- Emoji 只验证可读性、不被错误截断和无障碍语义，不做跨操作系统像素一致断言。

## 后续实施分片

1. **字体资源基线**：提交本地分片、OFL、manifest、下载脚本和静态校验。
2. **全局 Token 与入口**：引入字体 CSS，配置全局 Sans/Mono/Emoji Token，同步 UnoCSS `font-sans` 和 `font-mono`。
3. **显式字体栈收敛**：修改 Loading、通用表格、金额、代码组件和控制台样式边界。
4. **首屏就绪控制**：将字体就绪条件纳入现有 Loading 退出路径，并增加失败传播和超时策略。
5. **构建与浏览器验收**：验证分片按需加载、缓存、断网构建、主要页面排版和 Emoji 例外。
6. **旧资源清理**：在获得单独删除确认后，再删除已无引用的代码组件专用 WOFF2 和未使用 Digital 7 字体资源。

## 风险与取舍

| 风险 | 影响 | 控制方式 |
| --- | --- | --- |
| CJK 分片数较多 | Git 与 Release 包含全部文件 | 网络按 `unicode-range` 懒加载；升级时审查总体积 |
| Google Fonts API 响应变化 | 重新运行可能得到不同分片 | 固定 URL/User-Agent，提交快照与 Hash，不在构建期重获取 |
| 首屏字体失败 | 文字不可见或产生系统字体回退 | 受控 Loading、明确超时与错误状态 |
| 罕见字符缺失 | 浏览器使用最终回退或缺字方框 | 用业务样本验证覆盖范围，明确支持字符契约 |
| 原生 Emoji 外观不一致 | 装饰文本跨系统有差异 | 已接受；功能图标仍用 SVG/Iconify |
| 共享组件字体改动 | 参考应用外观可能受影响 | 限定正式应用契约，改共享组件时补充 examples 构建校验 |

## 变更边界

字体资源与样式接入属于 Web 内部实现，不改变公共 API、数据结构或数据库 schema。

删除 `FontWithASyntaxHighlighter-Regular.woff2`、Digital 7 目录或其他旧资源仍属于文件删除，必须在实施到该分片前单独获得确认。
