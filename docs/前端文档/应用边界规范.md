# 应用边界规范

## 1. 目标

本规范用于判断一项 Web 改动应落在正式业务应用、参考应用还是共享包，并防止参考工程或共享层被业务代码污染。

## 2. 默认归属

| 区域 | 定位 | 允许内容 | 禁止内容 |
| --- | --- | --- | --- |
| `apps/qsmds-arco` | 唯一正式业务应用 | 业务页面、路由、API、Pinia Store、应用设置、业务文案 | 依赖参考应用源码 |
| `examples/*` | 只读参考 | 初始基座、框架示例、用于对照的实现 | 默认业务改动、与正式应用同步演进的副本 |
| `packages/*` | 稳定共享能力 | 无业务语义的组件、主题、设置、类型和基础设施 | 业务代码、业务 API、业务页面、单场景 Store、领域规则 |

未指定目标的正式需求直接落在 `apps/qsmds-arco`，不需要先询问应用。`examples/*` 默认只读，只有用户明确指定参考应用时才允许修改对应路径；仅仅为了查阅参考实现不构成修改授权。

## 3. 决策顺序

处理 Web 需求时按以下顺序判断：

1. 是否是正式业务功能？是则写入 `apps/qsmds-arco`。
2. 用户是否明确点名某个 `examples/<name>` 并要求修改？只有答案为是，才允许写入该参考应用。
3. 是否确有稳定共享能力需要维护？只有满足第 5 节的提取标准，才写入 `packages/*`。
4. 无法满足共享标准时，代码留在正式业务应用，不为潜在复用提前抽象。

## 4. 依赖规则

允许的方向：

- `apps/qsmds-arco` → `packages/*`
- `examples/*` → `packages/*`
- 职责清晰且无循环的 `packages/*` → `packages/*`

禁止的方向：

- `packages/*` → `apps/qsmds-arco`
- `packages/*` → `examples/*`
- `apps/qsmds-arco` → `examples/*`
- `examples/*` → `apps/qsmds-arco`
- `web/` → `server/` 源码或依赖

不得使用 `file:`、`link:`、跨目录 `workspace:*`、绝对路径或越界相对路径绕过这些规则。Web 与 Server 只通过 HTTP 和 OpenAPI 契约协作。

## 5. YAGNI 提取标准

新增共享包或把代码从 `apps/qsmds-arco` 提取到 `packages/*` 前，必须同时满足：

1. 已有至少两个真实调用方，而不是假设未来会出现第二个应用。
2. 职责与输入输出已经稳定，能够形成清晰、可测试的接口。
3. 实现不包含千树 DMS 的领域名词、业务权限、业务状态流或业务 API。
4. 提取能减少真实重复或统一稳定基础设施，而不是单纯缩短一个文件。

`examples/*` 是参考资产，不是产品需求方，因此参考应用出现相似实现不能单独作为共享提取依据。未满足全部条件时遵循 YAGNI，把实现留在 `apps/qsmds-arco`。

## 6. 参考应用保护

- 日常业务任务不得顺手修正、升级或格式化 `examples/*`。
- 从参考应用读取思路后，应按正式应用的 Fantastic-admin/Fa 技术栈和业务约束重新实现，不建立源码依赖；正式应用已移除 Arco，不能直接复制参考应用的 Arco 组件。
- 用户明确要求修改参考应用时，只修改点名的 `examples/<name>`，不得扩散到其他参考应用。
- 默认 `pnpm dev`、`pnpm check`、`pnpm build` 不操作参考应用；需要验证时显式使用 `pnpm check:examples`、`pnpm build:examples` 或 `*:select` 命令。
- 参考应用检查失败必须如实报告，但不得借此把参考应用纳入正式发布物。

## 7. 正式应用约定

- 页面：`apps/qsmds-arco/src/views/`
- 路由：`apps/qsmds-arco/src/router/`
- API：`apps/qsmds-arco/src/api/`
- Pinia Store：`apps/qsmds-arco/src/store/`
- 应用文案：`apps/qsmds-arco/src/locales/`
- 应用设置：`apps/qsmds-arco/src/settings.ts`

用户可见文案默认使用中文；组件名、变量名、路径、API、字段、错误码和日志使用英文。业务代码不得为了复用现有路径而放入 `packages/*`。

## 8. 变更检查清单

提交 Web 改动前检查：

- 改动是否默认落在 `apps/qsmds-arco`。
- `examples/*` 是否保持只读，或已有用户明确指定的修改授权。
- `packages/*` 新增内容是否通过全部 YAGNI 提取标准。
- 是否出现正式应用与参考应用之间的导入。
- 是否出现越过 `web/` 边界的源码或依赖引用。
- 默认命令是否仍只服务正式业务应用。
- 是否仅提交 `.env.*.example`，并确认 `VITE_` 变量不含密钥。
- 是否运行与改动匹配的 `pnpm check`、`pnpm build` 或显式参考应用命令。
