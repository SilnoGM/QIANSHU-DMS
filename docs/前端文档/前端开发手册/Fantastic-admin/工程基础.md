# Fantastic-admin 工程基础

## 准备工作

开始前以 `web/package.json` 为环境真相源：Node.js 需满足 `^22.22.2 || ^24.15.0 || >=26.0.0`，pnpm 使用 `11.9.0`。本仓库已包含 Fantastic-admin Pro `6.3.0` 源码，不需要另外 clone 上游仓库。

```bash
node --version
pnpm --version
pnpm -C web install --frozen-lockfile
```

安装前不要删除或重建 `web/pnpm-lock.yaml`，也不要在仓库根新建 pnpm workspace 文件。`web/` 是独立 workspace，其完整边界由 `web/package.json`、`web/pnpm-workspace.yaml` 和 `web/pnpm-lock.yaml` 定义。

IDE 建议启用 Vue、ESLint、Stylelint 和 UnoCSS 支持，但编辑器绿色提示不代表项目验证通过。格式和静态规则以 `web/.editorconfig`、`web/eslint.config.js` 和 `web/stylelint.config.js` 为准。

官方来源：[Fantastic-admin 准备工作](https://fantastic-admin.hurui.me/guide/ready.md)。

## 开始

日常业务开发从仓库根目录运行：

```bash
pnpm -C web run dev
```

`web/package.json` 会将该命令 filter 到 `qsmds-arco`，`web/apps/qsmds-arco/vite.config.ts` 将开发端口设为 `9000` 并自动打开浏览器。如果端口已被占用，先核对 listener 的 PID 和 cwd，不把其他工作区或旧进程的页面当作当前运行结果。

工作区职责为：

| 目录 | 职责 | 默认写入政策 |
| --- | --- | --- |
| `web/apps/qsmds-arco` | 唯一正式 Web 应用 | 业务页、API、Store、路由、文案和应用组件的默认落点 |
| `web/examples/*` | 上游写法和演示参考 | 只读；需用户点名精确目标并明确授权才可修改 |
| `web/packages/*` | 稳定、无业务语义的共享能力 | 至少两个真实调用方且边界稳定时才抽取 |
| `web/skills/*` | 项目级 Agent Skill | 按每个 `SKILL.md` 维护，不用聊天记忆替代 |
| `web/scripts/*` | workspace 脚本和治理测试 | 修改行为前先用测试锁定契约 |

官方多应用模板使用交互式命令，本项目已在 `web/package.json` 中把默认 `dev`、`build` 和 `serve` 绑定到正式应用；只有核对参考应用时才使用 `*:select` 命令。

官方来源：[Fantastic-admin 开始](https://fantastic-admin.hurui.me/guide/start.md)。

## 代码规范

本项目在官方 EditorConfig、ESLint 和 Stylelint 理念上，增加了仓库协作规则：

- Vue 业务页默认用 `<script setup lang="ts">`，不为相同代码同时保留 Options API 兼容层。
- 用户可见文案使用中文；代码标识符、命令、路径、API、字段、错误码和日志使用英文。
- 对进程生命周期、失败传播、权限与不直观的工程约束使用详细中文注释；不用注释重复显而易见的语句。
- 业务文件留在 `web/apps/qsmds-arco/src/`，不为未来假设过早下沉到 `web/packages/*`。
- 新功能、缺陷修复和复杂修改先写失败测试；前端小文案、颜色等低风险修改不强制 TDD。
- 命令报错与测试失败必须如实报告，不用其他检查的成功覆盖失败。

完整项目检查为：

```bash
pnpm -C web run check
```

该命令的具体顺序以 `web/package.json.scripts` 为准，当前包含 `test:scripts`、`typecheck` 和 `lint`。局部调试命令可帮助定位问题，但不自动替代完整检查。

官方来源：[Fantastic-admin 代码规范](https://fantastic-admin.hurui.me/guide/coding-standard.md)。

## 环境变量

正式应用提交的三套变量清单是：

- `web/apps/qsmds-arco/.env.development.example`
- `web/apps/qsmds-arco/.env.test.example`
- `web/apps/qsmds-arco/.env.production.example`

创建本地开发配置时，从示例文件复制，并只在本机填值：

```bash
cp web/apps/qsmds-arco/.env.development.example web/apps/qsmds-arco/.env.development
```

`web/.gitignore` 和仓库根 `.gitignore` 均忽略真实 `.env` 文件，只放行 `.env*.example`。不得使用强制添加绕过该边界。

### 5.1 安全政策

Vite 会将 `VITE_` 前缀变量暴露给浏览器代码，因此它们全部属于公开客户端数据，不是密钥存储方案。严禁放入 token、密码、数据库连接、私钥、Cookie 或其他服务端秘密。

当前示例文件中：

- 通用应用配置包括 `VITE_APP_SETTING`、`VITE_APP_TITLE`、`VITE_APP_API_BASEURL`、`VITE_APP_STORAGE_PREFIX` 和 `VITE_APP_DEBUG_TOOL`。
- 开发环境另有 `VITE_ENABLE_PROXY`、`VITE_ENABLE_VUE_DEVTOOLS`、`VITE_ENABLE_TURBO_CONSOLE` 和 `VITE_LAUNCH_EDITOR`。
- 测试/生产构建另有 `VITE_APP_DISABLE_DEVTOOL`、`VITE_BUILD_FAKE`、`VITE_BUILD_SOURCEMAP`、`VITE_BUILD_COMPRESS` 和 `VITE_BUILD_ARCHIVE`。

变量如何被使用以 `web/apps/qsmds-arco/vite.config.ts`、`web/apps/qsmds-arco/vite/plugins.ts`、`web/apps/qsmds-arco/src/api/index.ts` 和 `src/types/env.d.ts` 为准；不根据变量名猜测行为。

官方来源：[Fantastic-admin 环境变量](https://fantastic-admin.hurui.me/guide/env.md)。

## 资源

资源位置按“作用域”而不是文件类型单独决定：

| 场景 | 位置 | 选择规则 |
| --- | --- | --- |
| 应用级图片、字体、样式和自定义图标 | `web/apps/qsmds-arco/src/assets/` | 需要被 Vite 处理、参与 hash/依赖图或在 TypeScript/Vue 中 import 时使用 |
| 单个业务模块私有图片或组件 | 相应 `src/views/<module>/` 下的 `images/` 或 `components/` | 只服务一个模块时就近放置，避免污染全局目录 |
| 按原始文件名和稳定根路径直接服务的静态文件 | `web/apps/qsmds-arco/public/` | 文件不需 import 与构建转换时才使用；当前实例包括 `public/favicon.svg` 和 `public/browser_upgrade/` |
| 稳定的跨应用能力 | `web/packages/*` | 至少两个真实应用调用方且无业务语义时才使用 |

`web/apps/qsmds-arco/src/assets/styles/globals.css` 由 `src/main.ts` 显式引入。`src/assets/styles/resources/` 的 SCSS 变量、函数和 mixin 则由 `web/apps/qsmds-arco/vite.config.ts` 遍历并通过 `additionalData` 自动注入，无需每个组件重复 `@use`。这是本地实现，优先于官方通用示例。

局部样式优先使用 Vue SFC scoped style 或 UnoCSS；全局样式只写入 `src/assets/styles/` 并从明确入口引入。

官方来源：[Fantastic-admin 资源](https://fantastic-admin.hurui.me/guide/resources.md)。

## 图标

`FaIcon` 是项目的统一图标渲染入口，公开导出在 `web/packages/components/src/index.ts`，类型分流实现在 `web/packages/components/src/basic/icon/index.vue`。

| `name` 形式 | 本地处理 | 适用场景 |
| --- | --- | --- |
| `i-ri:search-line` | UnoCSS icon class | 已在源码中静态写明的常规图标，默认优先 |
| `ri:search-line` | `@iconify/vue` | 图标名需要在运行时动态传入时使用 |
| `app-toolbar-collapse` | 本地 SVG spritemap | 文件位于 `web/apps/qsmds-arco/src/assets/icons/app-toolbar-collapse.svg`，`name` 使用不带 `.svg` 的文件名 |
| `/favicon.svg` 或 import 后的资源 URL | 图片模式 | 已有稳定 URL 或非图标精灵的图像资源 |

最小用法：

```vue
<template>
  <AButton>
    <FaIcon name="i-ri:search-line" />
    搜索
  </AButton>
</template>
```

UnoCSS 会在构建时扫描静态 class，因此 `i-<collection>:<name>` 不使用字符串拼接，也不依赖异步接口才返回完整名称。必须动态渲染时，使用不带 `i-` 的 Iconify 名称，并复核离线策略。

本地 SVG 由 `web/apps/qsmds-arco/vite/plugins.ts` 中的 `VitePluginSvgSpritemap('./src/assets/icons/*.svg')` 处理。更新 SVG 或 Iconify 离线集时使用正式应用脚本：

```bash
pnpm -C web --filter qsmds-arco run svgo
pnpm -C web --filter qsmds-arco run generate:icons
```

Iconify 集合与离线开关记录在 `web/apps/qsmds-arco/src/iconify/index.json`，加载逻辑在 `src/iconify/index.ts` 和 `src/main.ts`。只生成已选集合不会自动覆盖未选动态图标；内网验收必须实际断网或限制外网后验证。

官方来源：[Fantastic-admin 图标](https://fantastic-admin.hurui.me/guide/icon.md)。

## 构建与预览

### 8.1 正式应用

| 目标 | 命令 | 结果 |
| --- | --- | --- |
| 开发 | `pnpm -C web run dev` | 启动 `qsmds-arco` Vite 开发服务，默认端口 `9000` |
| 完整检查 | `pnpm -C web run check` | 脚本/API 测试、TypeScript、ESLint 与 Stylelint |
| 生产构建 | `pnpm -C web run build` | 输出 `web/apps/qsmds-arco/dist/` |
| 生产预览 | `pnpm -C web run serve` | 用 `http-server` 打开 `dist/`，必须先构建 |
| 测试模式构建 | `pnpm -C web --filter qsmds-arco run build:test` | 输出 `web/apps/qsmds-arco/dist-test/` |
| 测试模式预览 | `pnpm -C web --filter qsmds-arco run serve:test` | 打开 `dist-test/` |

`build` 的完整行为以 `web/package.json`、`web/apps/qsmds-arco/package.json` 和 `web/apps/qsmds-arco/vite.config.ts` 为准：当前会先重建 API 类型，再运行 `vue-tsc -b` 与 Vite build。

部署到非域名根路径时，需根据真实部署路径在 `web/apps/qsmds-arco/vite.config.ts` 设置 Vite `base`，并在预览环境验证 HTML、JS、CSS、图片和路由刷新；不使用假定子路径直接写配置。

## Composition API

正式应用以 Vue SFC 和 `<script setup lang="ts">` 为默认开发方式。`web/apps/qsmds-arco/vite/plugins.ts` 的 `unplugin-auto-import` 已覆盖 Vue、Vue Router、Pinia、vue-i18n、Fantastic-admin 组件/composables，以及 `src/store/modules/**/*` 与 `src/composables/**/*`。自动导入声明生成到 `web/apps/qsmds-arco/src/types/auto-imports.d.ts`。

最小示例：

```vue
<script setup lang="ts">
defineOptions({
  name: 'SearchSummary',
})

const keyword = ref('')
const summary = computed(() => keyword.value
  ? `当前筛选：${keyword.value}`
  : '未设置筛选条件')
</script>

<template>
  <section>
    <AInput v-model="keyword" placeholder="请输入搜索内容" />
    <p>{{ summary }}</p>
  </section>
</template>
```

不要为了展示自动导入而删除必须的类型 import；例如仅用于类型的第三方导出仍应显式使用 `import type`。保活页面按项目路由约定声明稳定组件名，不依赖文件名猜测。

官方来源：[Fantastic-admin Composition API](https://fantastic-admin.hurui.me/guide/composition-api.md)。

## JSX

`web/apps/qsmds-arco/vite/plugins.ts` 已启用 `@vitejs/plugin-vue-jsx`，`web/apps/qsmds-arco/tsconfig.app.json` 也包含 `src/**/*.tsx`，所以构建链具备 JSX/TSX 能力。但截至 `2026-07-15`，`web/apps/qsmds-arco/src/` 中没有 `.jsx` 或 `.tsx` 业务文件，现有项目风格仍是 Vue SFC。

使用边界：

- 普通业务页、表单和布局继续使用 `.vue` 与 `<template>`，不为个人偏好混入 JSX。
- 只有渲染结构高度动态、使用 render function 可显著改善可读性时，才在局部使用 `.tsx` 或 `<script lang="tsx">`。
- `.vue` 中可继续使用 `<style scoped>`；独立 `.tsx` 需用 CSS Modules 或项目 UnoCSS 规则处理样式隔离。
- `setup()` 不使用 `this`；组件 props、emits 和子节点类型必须通过 TypeScript 和 Vue 类型检查。

最小局部组件可以写成：

```tsx
export default defineComponent({
  name: 'StatusText',
  props: {
    active: Boolean,
  },
  setup(props) {
    return () => <span>{props.active ? '已启用' : '已停用'}</span>
  },
})
```

引入 JSX 后仍要执行 `pnpm -C web run check` 和 `pnpm -C web run build`，并与等价 SFC 方案比较可读性；若无明确收益，保留 SFC。

官方来源：[Fantastic-admin JSX](https://fantastic-admin.hurui.me/guide/jsx.md)。
