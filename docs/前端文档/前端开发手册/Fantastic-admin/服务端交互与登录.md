# 服务端交互与登录

本文把 Fantastic-admin 的通用接入方式映射到千树 DMS 已实施的 Axios、OpenAPI types-only 和登录链路。环境变量、资源与构建准备请先阅读[工程基础](./工程基础.md)，完整 HTTP 契约以[前端接口接入规范](../../接口接入规范.md)为准。

## 与服务端交互

上游[《与服务端交互》](https://fantastic-admin.hurui.me/guide/axios.md)提供 Axios、代理、模块化、重试和 fake server 的通用做法；千树 DMS 已在此基础上建立了更严格的项目契约，不能直接照搬上游示例的响应 envelope 或重试范围。

### 当前项目请求链路

| 环节 | 当前项目事实 | 真相源 |
| --- | --- | --- |
| Client 装配 | `web/apps/qsmds-arco/src/api/index.ts` 调用 `createApiClient()`，生产默认 `baseURL` 为 `/api`，开发代理启用时为 `/proxy/`，fake 请求为 `/fake/` | `web/apps/qsmds-arco/src/api/index.ts`、`web/apps/qsmds-arco/vite.config.ts` |
| 动态 Header | 每次 adapter 尝试前重新读取语言和登录状态，设置 `Accept-Language` 与 `Token`；Token 缺失时删除旧 Header | `web/apps/qsmds-arco/src/api/client.ts` |
| 成功响应 | response interceptor 原样返回 `AxiosResponse<T>`；调用方显式读取 `res.data` | `web/apps/qsmds-arco/src/api/client.ts` |
| 模块组织 | 框架接口在 `web/apps/qsmds-arco/src/api/modules/`，fake route 在 `web/apps/qsmds-arco/src/api/fake_modules/` | `web/apps/qsmds-arco/src/api/modules/app.ts`、`web/apps/qsmds-arco/src/api/fake_modules/app.fake.ts` |
| 契约类型 | `web/apps/qsmds-arco/src/api/generated/types.gen.ts` 由 `web/openapi/openapi.json` 生成且被 ignore；业务只导入生成类型，不导入 Server 源码 | `web/apps/qsmds-arco/src/api/api-error.ts`、`web/apps/qsmds-arco/src/api/modules/health.ts` |

成功路径必须保留 HTTP 信息。例如健康检查的 DTO 来自生成类型，调用方仍从完整 response 中读取 body：

```ts
import { getHealth } from '@/api/modules/health'

const response = await getHealth()

if (response.status === 200) {
  const health = response.data
  // 业务逻辑只读取 OpenAPI 契约字段。
}
```

生成类型的标准入口是：

```bash
pnpm -C web api:generate
```

不要手写一份与 OpenAPI 重复的 DTO，也不要把 Client 改成自动返回 `response.data`；两种做法都会让类型、状态码/Header 读取和当前调用方约定发生漂移。

### 错误、Blob 与安全展示

最终失败会收敛为 `ApiClientError`：

- `kind: 'http'`：body 通过 `isApiError()` 严格校验，包含 `code`、`message`、`requestId`，可选 `fieldErrors`。
- `kind: 'http-unparseable'`：保留安全的 HTTP `status` 和可选 `X-Request-Id`，展示固定文案，不复制未知 body。
- `kind: 'network'`：使用固定的 `NETWORK_ERROR` 与中文安全文案，不向 UI 透传 Axios `message`、`stack` 或 hook 异常。

下载失败的 body 只有在以下条件同时成立时才按 `ApiError` 解析：值确为 `Blob`、HTTP `Content-Type` 为 `application/json` 或 `application/*+json`、大小不超过 `1 MiB`，并且文本、JSON 与结构校验全部成功。实现位于 `web/apps/qsmds-arco/src/api/blob-error.ts`；`Blob.type` 不是可信 HTTP Header 的替代品。

最终 `401` 触发 `requestLogout()` 且不重复 toast；`403` 只提示“没有权限执行此操作”，不会登出。副作用 hook 即使抛错也不能替换已经规范化的错误。排障时用 `requestId` 关联服务端日志，不要把 token、密码、Cookie、连接字符串或完整敏感请求体写入控制台。

### 重试与取消

上游文档展示了通用 `retry: true`；本项目的实际规则以 `web/apps/qsmds-arco/src/api/retry.ts` 为准：

| 项目 | 当前规则 |
| --- | --- |
| 开启方式 | 单次请求显式设置 `retry: true`，默认不重试 |
| 允许方法 | `GET`、`HEAD`、`OPTIONS`、`PUT` |
| 允许失败 | network error 或 HTTP `502`、`503`、`504` |
| 次数 | 最多重试 3 次，因此 adapter 总调用最多 4 次 |
| 默认等待 | `500`、`1000`、`2000 ms` |
| `Retry-After` | 仅 `503` 读取，解析后最多等待 `5000 ms` |

幂等读取可显式开启：

```ts
import type { HealthResponse } from '@/api/modules/health'

const response = await api.get<HealthResponse>('/health', {
  retry: true,
})
```

不要给 `POST` 等非幂等写操作套通用自动重试。请求在发送前或等待期间被 abort 时会保留 Axios `CanceledError` 语义，不重试、不 toast、不登出，也不转换成 `ApiClientError`。

### Fake route 的项目规则

`web/apps/qsmds-arco/src/api/modules/app.ts` 当前的框架演示调用使用 `fake: true`，对应 `web/apps/qsmds-arco/src/api/fake_modules/app.fake.ts`。成功 route 直接返回裸 DTO，Store 读取 `res.data.account`、`res.data.permissions` 等字段；禁止重新引入上游旧示例中的 `{ status, error, data }` envelope。

fake route 是 Web 基座能力，不属于 Server OpenAPI。把某个 fake 调用替换为真实业务接口时，需要先确认公共 API 契约并按[接口接入规范](../../接口接入规范.md)同步 snapshot、生成类型和测试，不能只删除 `fake: true` 后猜测字段。

### Base URL、代理与部署边界

安全示例文件 `web/apps/qsmds-arco/.env.*.example` 当前都使用相对 `VITE_APP_API_BASEURL=/api`；开发代理由 `VITE_ENABLE_PROXY` 与 `web/apps/qsmds-arco/vite.config.ts` 的 `/proxy` 规则共同控制。相对路径表示当前设计依赖同源部署，或由网关/Vite dev server 反向代理。

上游文档允许覆盖 `baseURL` 或创建第二个 Axios 实例，但这只是可选方案，不是本项目现状。若要改成跨域或多数据源，必须先设计 CORS、可信 origin、Token/Cookie 策略和 `X-Request-Id`、`Retry-After` 的暴露方式，并单独确认公共契约；不能把真实地址、凭据或密钥写进 `VITE_*` 变量。

## 登录相关

上游[《登录相关》](https://fantastic-admin.hurui.me/guide/login.md)提示开发者同时核对环境、interceptor、登录模块和 `isLogin`；当前千树 DMS 的真实登录链路如下。

### 已实施链路

1. `web/apps/qsmds-arco/src/components/AppAccountForm/login.vue` 校验账号、密码和记住账号选项，然后调用 `useAppAccountStore().login()`。
2. `web/apps/qsmds-arco/src/api/modules/app.ts` 当前通过 `POST app/account/login` 且 `fake: true` 发起请求；这不是已声明的 Server 登录端点。
3. `web/apps/qsmds-arco/src/store/modules/app/account.ts` 从 `res.data` 读取 `account`、`token`、`avatar`，写入带项目前缀的 `localStorage`，并更新响应式状态。
4. 登录表单触发 `onLogin` 后，`web/apps/qsmds-arco/src/views/login.vue` 跳转到 query 中的 `redirect`，缺省目标为 `settings.app.home.fullPath`。
5. 下一次导航进入 `web/apps/qsmds-arco/src/router/guards.ts`：若动态路由尚未生成，守卫按配置获取权限/偏好、生成并注册路由、恢复标签页，然后以 `replace: true` 重新进入当前路径。

当前 `isLogin` 只判断 Store 中的 `token` 是否为非空字符串；项目没有可据此声称的 `/auth/me`、refresh token 或启动时服务端会话校验。注册、重置密码等组件存在于 `web/apps/qsmds-arco/src/components/AppAccountForm/`，但 `web/apps/qsmds-arco/src/api/modules/app.ts` 没有注册/找回密码公共端点，不能把演示表单写成已接通业务能力。

### 失效、登出与跳转

- 未登录访问非 `meta.whiteList` 路由时，守卫跳到命名路由 `login`，并在非首页场景保存 `redirect`。
- 已登录访问 `login` 时，守卫跳回 `settings.app.home.fullPath`。
- 手动 `logout()` 清除 token，跳转后再清理账号、头像、权限、偏好覆盖、标签页、动态路由和主菜单状态。
- 请求最终返回 `401` 时，Client 调用 `requestLogout()`；当前默认 `app.account.expiredMode` 为 `redirect`。`popup` 的重新登录组件属于上游可配置能力，但正式应用当前没有开启。

### 登录安全边界

浏览器中的 `isLogin`、路由守卫、菜单过滤与按钮隐藏都只是客户端体验控制，不能替代 Server 对每个请求的身份与权限校验。当前 token 存在 `localStorage` 并通过 `Token` Header 发送，因此尤其要避免 XSS、日志泄露和把 token 复制到 URL；Storage 前缀只防同源 key 冲突，不提供加密或访问隔离。

接入真实登录服务前，应先获得公共 API/数据结构确认，并用测试固定以下边界：成功 DTO、`401 ApiError`、登录后 redirect、刷新后的会话判定、登出清理和无权限响应。不要在文档或测试 fixture 中写真实账号、密码或 token。
