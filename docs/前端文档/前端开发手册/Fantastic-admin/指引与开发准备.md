## 文档说明

官方指南用专业版标记区分授权范围，并假定读者会在本地源码上运行和修改。千树 DMS 不使用这一标记推测能力是否存在：是否可用必须回到 `web/packages/*`、`web/apps/qsmds-arco` 和 `web/skills/*`。

本分册只保留开发任务需要的上游结论，再转换成项目路径、命令和审查边界。任何示例都不能包含真实 `.env`、密钥、Cookie 或专业版授权信息，也不能为了让示例“看起来完整”而伪造业务 API、路由或字段。

官方来源：[Fantastic-admin 文档说明](https://fantastic-admin.hurui.me/guide/intro.md)。

## 为什么选择 Fantastic-admin

官方将 Fantastic-admin 定位为适合长期维护、持续扩展与 AI 协作的后台工程底座。对千树 DMS 而言，选型价值落在以下已验证事实，而不是上游宣传文案：

- **应用与共享能力分层**：`web/apps/qsmds-arco` 承载业务，`web/packages/*` 承载稳定、无业务语义的共享能力，依赖方向以 `web/pnpm-workspace.yaml` 和源码 import 为准。
- **框架壳与业务 UI 可组合**：`web/packages/components` 提供 Fantastic-admin 内置组件，正式应用已移除 Arco，框架交互与标准业务 UI 都由 Fa 组件承担；Arco 只保留在 `web/examples/` 参考应用。
- **路由、导航、权限和保活共用同一元数据体系**：实际入口位于 `web/apps/qsmds-arco/src/router/`、`src/layouts/` 和 `src/store/modules/app/`。
- **项目级 Skills 可追溯**：九个本分册覆盖的 Skill 均在 `web/skills/<name>/SKILL.md` 维护，生成路径和修改边界可直接审查。
- **主题与布局有本地扩展点**：`web/packages/themes/index.ts`、`web/apps/qsmds-arco/src/settings.ts` 和 `src/slots/` 分别承载主题 token、应用覆盖和布局注入。

这一选型不意味着所有业务都应下沉到共享包。页面、业务 API、业务 Store 和领域规则默认留在 `web/apps/qsmds-arco/src/`，只有存在至少两个真实调用方且边界已稳定时才评估共享。

官方来源：[Fantastic-admin 选型说明](https://fantastic-admin.hurui.me/guide/why.md)。

## 更新日志的阅读方法

官方日志只聚合 feature、fix 和 breaking change，不是每次提交的清单。当前本地基座为 `6.3.0`，对应公开基线是 [`fantastic-admin/basic@v6.3.0`](https://github.com/fantastic-admin/basic/tree/v6.3.0)；上游 `main` 或在线文档后续出现的内容不是本项目当前能力。

评估升级时按以下顺序阅读：

1. 从 `web/package.json.version` 确定起点，从待升级 tag 确定终点。
2. 在官方日志中只阅读起点到终点之间的 feature、fix 和 breaking change。
3. 用公开 tag 核对 `apps/`、`packages/`、配置和脚本结构，再用本地 `web/packages/*` 核对专业版差异。
4. 逐项评估 `web/apps/qsmds-arco`、`web/skills/*` 和 `web/pnpm-lock.yaml` 的影响，不覆盖千树 DMS 定制。
5. 修改公共 API、数据结构或数据库 schema 前单独获得确认；升级不构成默认授权。

官方来源：[Fantastic-admin 更新日志](https://fantastic-admin.hurui.me/guide/changelog.md)。

## 开发前提

从仓库根目录开始时，先确认本地工具符合 `web/package.json`：

```bash
node --version
pnpm --version
pnpm -C web install --frozen-lockfile
```

`web/` 已经包含完整源码、workspace 配置和 lockfile，无需另外下载 Fantastic-admin。官方“优先使用 Release、谨慎直接 clone 未发布分支”的建议用于获取上游源码；本项目开发应当使用当前 Git commit 中的 `web/`。

IDE 应能读取 `web/.editorconfig`、`web/eslint.config.js` 和 `web/stylelint.config.js`。Vue、ESLint、Stylelint 与 UnoCSS 的编辑器支持会改善反馈速度，但最终判定仍以仓库命令为准。

官方来源：[Fantastic-admin 准备工作](https://fantastic-admin.hurui.me/guide/ready.md)。

## 工作区启动与检查

`web/package.json` 已将默认命令绑定到唯一正式应用 `qsmds-arco`，因此日常开发不需要交互式选择 app：

```bash
pnpm -C web run dev
pnpm -C web run check
pnpm -C web run build
pnpm -C web run serve
```

- `dev` 运行 `web/apps/qsmds-arco` 的 Vite 服务，默认端口是 `9000`。
- `check` 串行执行脚本测试、API 契约测试、TypeScript 检查、ESLint 和 Stylelint，组合真相源是 `web/package.json.scripts`。
- `build` 会先由 `web/apps/qsmds-arco/package.json` 的 `prebuild` 重建 API 类型，再执行 `vue-tsc -b` 与 Vite build。
- `serve` 预览 `web/apps/qsmds-arco/dist/`，应在生产构建成功后执行。

参考应用不会被默认命令带入；需要核对时显式使用：

```bash
pnpm -C web run check:examples
pnpm -C web run build:examples
pnpm -C web run dev:select
```

官方来源：[Fantastic-admin 开始](https://fantastic-admin.hurui.me/guide/start.md)。官方命令是多应用通用说明，上述项目命令以 `web/package.json` 为准。

## 目录与依赖边界

```text
web/
├── apps/qsmds-arco/       # 唯一正式 Web 应用
├── examples/             # 只读参考，需精确授权才允许修改
├── packages/             # 稳定、无业务语义的共享能力
├── skills/               # 项目级 AI Skill 真相源
├── scripts/              # workspace 脚本与测试
├── openapi/openapi.json  # Web 自包含 OpenAPI snapshot
├── package.json
├── pnpm-workspace.yaml
└── pnpm-lock.yaml
```

- 正式业务页面、API、Store、路由、插槽和应用文案默认写入 `web/apps/qsmds-arco/src/`。
- `web/examples/*` 可以查阅；只有用户精确点名某个参考应用并明确要求修改时，才能写入该目录。
- `web/packages/*` 不存放业务页面、业务 API、业务 Store 或领域规则；正式应用不反向被共享包依赖。
- `web/` 和 `server/` 是独立依赖域，通过 HTTP 与 OpenAPI 契约协作，不使用 `file:`、`link:`、`workspace:*` 或跨目录源码引用建立前后端依赖。

## 两个 version 的含义

`web/package.json.version = 6.3.0` 表示 Fantastic-admin 上游基座版本，用于选择对应文档、tag 和升级范围，不是千树 DMS 产品版本。

`web/apps/qsmds-arco/package.json.version = 0.1.2` 是核对日当前正式 Web app 的产品版本。产品发布时，它由仓库根发布流程与根产品版本、Server 产品版本一致管理；不应因为升级 Fantastic-admin 就直接把产品版本改成 `6.3.0`。

这两个字段的职责来自 `web/README.md`、`web/package.json` 和 `web/apps/qsmds-arco/package.json`。

## 代码规范

官方指南建议使用 EditorConfig、ESLint 和 Stylelint 维持一致性。本项目的实际配置是 `web/.editorconfig`、`web/eslint.config.js` 和 `web/stylelint.config.js`，不照抄官方文档中可能已变化的 hook 或 script 假设。

项目约定：

- Vue 业务页默认使用 `<script setup lang="ts">`，组件名、变量、API、字段、路径和日志使用英文。
- 用户可见文案默认使用中文；全局或路由文案按 `web/apps/qsmds-arco/src/locales/` 的结构管理。
- 为进程生命周期、失败传播、权限边界和不直观的工程约束编写必要且详细的中文注释，不用注释重复显然代码。
- 小文案或颜色修改可按风险直接验证；新功能、缺陷修复和复杂修改先写失败测试，再实现最小修复。
- 提交前至少执行与改动风险匹配的 `pnpm -C web run check`，需要产物保证时再执行 `pnpm -C web run build`。
- Commit Message 类型使用英文，描述使用中文，例如 `feat: 添加用户列表`。

官方来源：[Fantastic-admin 代码规范](https://fantastic-admin.hurui.me/guide/coding-standard.md)。

## 项目术语

| 术语 | 项目含义 | 本地入口 |
| --- | --- | --- |
| 头部导航栏 | 顶部的导航容器，不等于整个顶栏 | `web/apps/qsmds-arco/src/layouts/components/Header/` |
| 主导航栏 | 承载主导航菜单的侧边区域 | `web/apps/qsmds-arco/src/layouts/components/MainSidebar/` |
| 次导航栏 | 承载当前主菜单下级导航的区域 | `web/apps/qsmds-arco/src/layouts/components/SubSidebar/` |
| 导航菜单 | 由路由及其 `meta` 驱动的菜单节点 | `web/apps/qsmds-arco/src/router/` 与 `src/layouts/components/Menu/` |
| 顶栏 | 标签栏与工具栏的组合 | `web/apps/qsmds-arco/src/layouts/components/Topbar/` |
| 标签栏 | 管理已打开页面标签与快捷操作 | `web/apps/qsmds-arco/src/layouts/components/Topbar/Tabbar/` |
| 工具栏 | 承载面包屑、搜索、通知、国际化和全屏等工具 | `web/apps/qsmds-arco/src/layouts/components/Topbar/Toolbar/` |
| 正式应用 | 千树 DMS 真实业务与产品构建目标 | `web/apps/qsmds-arco` |
| 参考应用 | 用于学习上游写法的非产品目录 | `web/examples/*` |

沟通时应使用上表精确术语，例如“在工具栏末尾增加入口”，而不是模糊地说“在顶部加东西”。官方术语中“顶栏 = 标签栏 + 工具栏”与本地目录结构一致。

官方来源：[Fantastic-admin 术语](https://fantastic-admin.hurui.me/guide/term.md)。
