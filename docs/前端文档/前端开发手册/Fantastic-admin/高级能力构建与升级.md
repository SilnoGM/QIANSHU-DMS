# 高级能力、构建与升级

本册采用三个标签区分信息：**当前项目事实**来自正式应用和 `web/packages/*`；**上游选项**来自官方当前指南；**项目建议**用于在不改变现有契约的前提下落地。不要把上游示例或建议写成已经启用的产品能力。

## 内置 API

**上游选项：** 官方[《内置 API》](https://fantastic-admin.hurui.me/guide/api.md)整理了主导航、主页面、标签栏、事件总线和日期入口。

**当前项目事实：** `web/apps/qsmds-arco/vite/plugins.ts` 自动导入 `web/apps/qsmds-arco/src/composables/**/*` 与 `@fantastic-admin/composables` 的公开函数，实际可用入口如下：

| 来源 | API | 当前职责 |
| --- | --- | --- |
| `web/apps/qsmds-arco/src/composables/app/auth.ts` | `useAppAuth()` | `auth()` 任一权限、`authAll()` 全部权限 |
| `web/apps/qsmds-arco/src/composables/app/localeAuth.ts` | `useAppLocaleAuth()` | 按当前语言判断 route/menu 可见性 |
| `web/apps/qsmds-arco/src/composables/app/menu.ts` | `useAppMenu()` | 生成国际化标题、切换/跳转主菜单 |
| `web/apps/qsmds-arco/src/composables/app/page.ts` | `useAppPage()` | `reload()`、自定义/重置标题、最大化 |
| `web/apps/qsmds-arco/src/composables/app/tabbar.ts` | `useAppTabbar()` | tabId、关闭/批量关闭和可关闭性判断 |
| `web/packages/composables` | `useConfetti()` | confetti 调用，并支持 reduced-motion 选项 |
| `web/packages/composables` | `usePagination()` | 当前页、页大小、排序与两种分页参数 |
| `web/packages/composables` | `useTiks()` | 浏览器支持时初始化交互音效并控制静音/音量/主题 |

官网“主导航切换”示例使用 `useMenu()`，本地正式应用导出的是 `useAppMenu()`；必须以本地函数名为准。`router.close(to)` 与带可选目标的 `router.back(to?)` 是 `web/apps/qsmds-arco/src/router/extensions.ts` 声明的框架扩展，不是 Vue Router 原生 API；`push/replace/go` 也被包装以同步标签页。

事件总线和日期工具不是自动导入：

```ts
import dayjs from '@/utils/dayjs'
import eventBus from '@/utils/eventBus'
```

`eventBus` 是带宽泛事件表的 `mitt` 实例。新增跨组件事件时应定义清晰名称、payload 和对称 `off()`，优先使用 props/emits、Store 或 composable 处理有明确所有权的状态，避免把 event bus 变成不可追踪的业务总线。

## 预留插槽

**上游选项：** 官方[《预留插槽》](https://fantastic-admin.hurui.me/guide/slots.md)建议用 slot 扩展布局，减少直接修改框架壳。

**当前项目事实：** `web/apps/qsmds-arco/src/slots/index.ts` 通过 `import.meta.glob('./*/index.vue', { eager: true })` 加载 PascalCase 目录；当前 `web/apps/qsmds-arco/src/slots/` 没有任何具体 slot 组件。类型精确允许 19 个位置：

| 区域 | 目录名 |
| --- | --- |
| 布局 | `LayoutTop`、`LayoutBottom` |
| Header | `HeaderStart`、`HeaderAfterLogo`、`HeaderAfterMenu`、`HeaderEnd` |
| 主侧栏 | `MainSidebarTop`、`MainSidebarAfterLogo`、`MainSidebarAfterMenu`、`MainSidebarBottom` |
| 次侧栏 | `SubSidebarTop`、`SubSidebarAfterLogo`、`SubSidebarAfterMenu`、`SubSidebarBottom` |
| 顶栏 | `TabbarStart`、`TabbarEnd`、`ToolbarStart`、`ToolbarEnd` |
| 自由位置 | `FreePosition` |

**项目建议：** 一个位置一个目录且文件固定为 `index.vue`，例如 `web/apps/qsmds-arco/src/slots/ToolbarEnd/index.vue`。保持 slot 只负责布局插入，复杂状态下沉到业务组件/Store。`FreePosition` 需要自行定位并检查 stacking context；顶部/底部 slot 的实际高度会参与布局 CSS 变量，应在窄屏、滚动和页面最大化状态下验证。

需要新增 slot 时，先参考[AI 技能的 `fa-slot-creator`](./AI技能.md#fa-slot-creator)，再核对上述本地 type；不要创建未被 `Slots` 联合类型声明的目录后假设它会加载。

快捷键有独立所有权，统一见[《权限、保活与国际化 / 快捷键》](./权限保活与国际化.md#快捷键)，本节不重复定义 registry 或键位。

## 开发者工具

**上游选项：** 官方[《开发工具》](https://fantastic-admin.hurui.me/guide/devtools.md)介绍 Vue DevTools、Turbo Console 和编辑器定位。

**当前项目事实：** `web/apps/qsmds-arco/vite/plugins.ts` 按解析后的环境变量装配工具：

| 开关 | 实现 | 当前安全示例值 |
| --- | --- | --- |
| `VITE_ENABLE_VUE_DEVTOOLS` | `vite-plugin-vue-devtools` | development 为 `true` |
| `VITE_ENABLE_TURBO_CONSOLE` | `unplugin-turbo-console` | development 为 `false` |
| `VITE_LAUNCH_EDITOR` | 两个工具共用的 editor 标识 | development 为空 |
| `VITE_APP_DEBUG_TOOL` | 可注入 `eruda` 或 `vconsole` | 三套示例均为空 |
| `VITE_APP_DISABLE_DEVTOOL` | build 时注入 `disable-devtool` | production 为 `true`，test 为 `false` |

**项目建议：** 个人 editor 设置写入未提交的 `.env.development.local`，不要改团队示例来绑定个人 IDE。调试截图、Pinia 导出和 console 不能包含 token、密码、Cookie 或连接字符串。`disable-devtool` 只提高浏览器调试门槛，不会隐藏已下发的 JavaScript、接口或密钥，因此不能作为安全边界。

开发工具依赖真实 dev server；默认正式应用端口来自 `web/apps/qsmds-arco/vite.config.ts` 的 `9000`。如果页面行为与源码不一致，先用 `lsof`/`ps` 核对监听进程属于当前 worktree，再相信浏览器结果。

## 自定义字体

**上游选项：** 官方[《自定义字体》](https://fantastic-admin.hurui.me/guide/font.md)建议在 `src/assets/fonts/` 中按字体家族建立子目录，放入浏览器字体及 `stylesheet.css` 后按需导入。

**当前项目事实：** 正式应用已有两套 Digital 7 资源：

- `web/apps/qsmds-arco/src/assets/fonts/digital-7/stylesheet.css` 声明 `digital-7regular`。
- `web/apps/qsmds-arco/src/assets/fonts/digital-7_mono/stylesheet.css` 声明 `digital-7_monomono`。

仓库当前没有在页面或全局样式导入这两个 CSS，因此字体文件“存在”不等于界面“正在使用”。

**项目建议：** 优先在确实使用的页面样式中局部 `@import`，避免所有用户下载无关字体；为数字仪表等场景提供系统 fallback，并检查 WOFF2 请求、缓存、首屏抖动和中文 fallback。不要仅凭文件名推断字形覆盖范围。

## 首屏 Loading

**上游选项：** 官方[《首屏 Loading》](https://fantastic-admin.hurui.me/guide/loading.md)说明 `vite-plugin-app-loading` 会把独立 HTML 注入应用入口。

**当前项目事实：** `web/apps/qsmds-arco/vite/plugins.ts` 注册 `AppLoading('loading.html')`，`web/apps/qsmds-arco/loading.html` 提供纯 CSS 四方块动画、`%VITE_APP_TITLE%` 和中文“载入中”；`web/apps/qsmds-arco/src/router/index.ts` 在 `router.isReady()` 后调用 `loadingFadeOut()`。Loading 覆盖的是应用初始化到 Router ready 的空白期，不代表 API 数据已经完成加载。

**项目建议：** 自定义只改 `loading.html` 的独立结构和样式，不依赖 Vue/Pinia，也不请求业务 API。保留清晰中文提示，控制动画强度与层级，并在冷缓存、慢网络、Router 初始化失败和 reduced-motion 场景检查是否可退出；不要在 Loading 中嵌入敏感配置。

## 搭配 UI 组件库

**上游选项：** 官方[《搭配 UI 组件库》](https://fantastic-admin.hurui.me/guide/with-ui-libraries.md)把 `src/ui/provider/index.ts` 与 `index.vue` 定义为组件库统一接入点。

**当前项目事实：** 千树 DMS 的正式应用已移除第三方 UI 组件库，只使用 Fantastic-admin 内置组件与 Fa 组件；`web/apps/qsmds-arco/src/main.ts` 与 `App.vue` 不再安装或包裹 Arco Provider。上游的 provider 接入方式仅保留在 `web/examples/core-arco-design-vue` 参考应用中，可作为未来重新接入时的结构参考。

**项目建议：** Fantastic-admin 内置 `Fa*` 组件是框架壳和标准业务 UI 的第一优先级；本地 Fa 能力无法满足已确认契约时，优先扩展 `web/packages/components`，不要直接恢复 Arco。确需重新接入 Arco，必须先完成依赖与 provider 接入评审，并重写 `rules/field/model/validate()` 和 slot 语义，不能只把组件名替换为 `A*`。详细契约见[AI 技能](./AI技能.md#共同安全与执行规则)。

参考应用修改 Provider 后运行 `pnpm -C web typecheck` 和 `pnpm -C web build`，再验证亮暗主题、三种 locale、弹层挂载、消息/通知与窄屏；正式应用的主题验证只需覆盖 Fantastic-admin 壳与 Fa 组件。

## 框架更新

**上游选项：** 官方[《框架更新》](https://fantastic-admin.hurui.me/guide/upgrade.md)明确 Fantastic-admin 是可二次开发的模板，不是可以无差异升级的 npm 插件，推荐记录定制、选择性移植并完整回归。

**当前项目事实：** `web/package.json` 固定 Fantastic-admin Pro `6.3.0`；本手册用公开 `fantastic-admin/basic@v6.3.0` 辅助核对概念，但真正产品基线是本仓库 `web/packages/*` 与 `web/apps/qsmds-arco`。产品 Git remote 是千树 DMS 仓库，不能把它当作 Fantastic-admin 上游 remote 直接拉取覆盖。

**项目建议：** 更新采用“候选源码差异迁移”，不执行目录覆盖：

1. 从干净提交创建独立 upgrade worktree/branch，记录当前 `web/package.json.version`、lockfile 与验证结果。
2. 阅读官方 changelog 和涉及主题的直接 `.md` 页面；只引入有明确价值的修复或能力。
3. 将候选变更放入工作树后，先检查范围：

```bash
git diff --name-status -- web/package.json web/pnpm-lock.yaml web/packages web/apps/qsmds-arco
git diff --check
```

4. 对 `web/apps/qsmds-arco/src/api/`、router、Store、settings、locales、hotkeys 和 slots 做逐文件三方判断：保留项目契约、移植上游修复、拒绝无关 demo。
5. 依赖、公共 API/数据结构、数据库 schema 或文件删除仍需单独确认，不能借“框架升级”绕过安全红线。
6. 按风险运行 `pnpm -C web check`、`pnpm -C web check:examples`、`pnpm -C web build`、`pnpm -C web build:examples`，并做登录、路由、权限、Storage、主题、i18n、窄屏和部署预览回归。

一次只迁移可验证的小块并提交，便于 `git show`、`git revert` 和问题归因。公开 basic 只能帮助理解同版本结构，不能覆盖本地专业版或千树 DMS 定制。

## 常见问题

官方[《常见问题》](https://fantastic-admin.hurui.me/guide/q-a.md)提供通用排查方向；以下答案按当前仓库修正。

### 安装出现 warning，是否可以忽略

先看命令退出码和可运行性，不因官网某个历史 warning 可忽略就跳过失败。当前 `web/` 是独立 pnpm workspace，使用仓库固定 pnpm 与 lockfile；验证依赖至少运行实际命令，例如 `pnpm -C web exec vite --version` 和目标检查/构建。

### 切换页面后空白

`web/apps/qsmds-arco/src/layouts/index.vue` 的 RouterView 外仍有 `<Transition>`，页面模板应保持可过渡的单根结构。除此之外检查控制台、动态 import、route component/name、`appKeepAlive.list` 与当前 dev server cwd；不要把所有空白页都归因于 Transition。

### 构建内存不足

先保留完整 `Reached heap limit` 等错误、Node 版本和复现命令，确认是内存而非 TypeScript/OpenAPI 生成失败。不要未经确认新增 `cross-env` 或修改依赖；如确需调整 `NODE_OPTIONS`，应在有测量数据后作为独立工程变更评审。

### 是否直接修改构建产物的 API 地址

不要修改 `dist`。当前 Client 以相对 `/api` 和同源/反向代理为部署前提，环境与跨域方案见[服务端交互与登录](./服务端交互与登录.md#base-url代理与部署边界)。多环境需求应回到可审计配置和网关设计，不在产物中注入未知全局对象。

### generated types 缺失

`web/apps/qsmds-arco/src/api/generated/` 被 ignore 是设计行为。运行 `pnpm -C web api:generate`；正式 app 的 lint/typecheck/build 也有生成 lifecycle。不要手工提交或编辑 `types.gen.ts`。

### 如何全局关闭动效

当前 `page.transitionMode` 默认为空，但组件仍可能自带动画，设置类型中不存在“全局关闭所有动效”的键。无障碍需求应逐层处理并验证 `prefers-reduced-motion`，不要杜撰配置项或用不可审计的全局覆盖掩盖交互问题。

### fake 请求为什么没有到 Server

`web/apps/qsmds-arco/src/api/modules/app.ts` 当前只有路由、偏好、标签栏、收藏和通知等非认证框架请求使用 `fake: true`，Client 会把它们路由到 `/fake/`。登录、当前身份、改密、退出、用户、角色、权限和审计均使用真实 Server API；剩余 fake 请求没有到 Server 属于预期行为。替换前先确认真实公共 API、裸 DTO 和错误契约；详细见[服务端交互与登录](./服务端交互与登录.md#fake-route-的项目规则)。

## 从 v5 迁移

**上游参考：** 官方[《从 v5 迁移》](https://fantastic-admin.hurui.me/guide/migration-from-v5.md)记录配置分层、route meta、Store 与 mock 目录等迁移点。

**当前项目事实：** 本仓库已经是 `6.3.0`，正式应用 `web/apps/qsmds-arco/src/settings.ts` 使用 `setSettings()`，route meta 使用当前 `RouteMetaRaw`，fake route 位于 `web/apps/qsmds-arco/src/api/fake_modules/`。虽然 `@fantastic-admin/settings` 仍导出 `setSettingsLegacy()`，正式应用没有使用它。

**项目建议：** v5 页面只作为外部旧代码迁入时的核对表，不在当前应用加入运行时兼容层，也不把 `setSettings()` 换回 `setSettingsLegacy()`。先在隔离分支把旧配置、route meta、Store/mock 路径和组件名翻译成当前 v6 结构，再以正常 v6 代码落库；每一块都通过 typecheck/build 和真实回归后再提交。对公共 API、数据结构、依赖或删除文件的迁移仍需单独确认。
