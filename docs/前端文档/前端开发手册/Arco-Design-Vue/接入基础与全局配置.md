# Arco Design Vue 接入基础与全局配置

本文只描述 `web/apps/qsmds-arco` 在 `@arco-design/web-vue@2.58.0` 下的真实接入。当前官网用于理解推荐意图，固定 API 以 [2.58.0 tag](https://github.com/arco-design/arco-design-vue/tree/2.58.0)和本地安装包为准。

## 当前安装与启动链路

正式应用把 Arco 封装为 Vue plugin：`src/ui/provider/index.ts` 引入默认导出的 `ArcoVue`、三份 locale 和整包样式，`install(app)` 内执行 `app.use(ArcoVue)`；`src/main.ts` 再执行 `app.use(uiProvider)`。这是一条**全局注册 + 整包 CSS**链路：模板可以直接写 `AButton`、`AForm` 等 `A*` 标签，但不能把它描述为 tree-shaking 的按需组件导入。

```ts
import type { App } from 'vue'
import ArcoVue from '@arco-design/web-vue'
import en from '@arco-design/web-vue/es/locale/lang/en-us'
import zhCN from '@arco-design/web-vue/es/locale/lang/zh-cn'
import zhTW from '@arco-design/web-vue/es/locale/lang/zh-tw'
import '@arco-design/web-vue/dist/arco.css'

function install(app: App) {
  app.use(ArcoVue)
}

export default { install }
export const locales = {
  'zh-cn': zhCN,
  'zh-tw': zhTW,
  en,
}
```

```ts
import uiProvider from './ui/provider'

const app = createApp(App)
app.use(uiProvider)
```

Vite 的 `components()` 当前只配置 `FantasticAdminComponentsResolver()` 与 Fantastic-admin 类型清单，未配置 `ArcoResolver`；`autoImport()` 也只收录 Vue、Router、Pinia、i18n 和 Fantastic-admin resolver。因此当前 `A*` 可用性来自 `app.use(ArcoVue)`，不是 Arco 按需自动导入。若未来切换接入模式，必须同时调整样式导入、生成类型和本文档，不能叠加两套机制后声称已经按需。

模板里的全局组件名不需要 import；以下情况仍要显式 `import type` 或显式值导入：

- `import type { ButtonProps, FormInstance } from '@arco-design/web-vue'` 等 TypeScript 类型；
- `Message`、`Notification`、`Modal` 等命令式 API；
- 测试、渲染函数、动态组件表或脚本中直接持有组件值。

## 全局配置、语言与主题

`src/ui/provider/index.vue` 是应用级 Provider。当前实际启用的 Arco ConfigProvider 能力只有 locale：

```vue
<script setup lang="ts">
import { locales } from './index'

const appSettingsStore = useAppSettingsStore()
</script>

<template>
  <AConfigProvider :locale="locales[appSettingsStore.lang]">
    <slot />
  </AConfigProvider>
</template>
```

语言键与项目 i18n 保持一致：`zh-cn` 映射 Arco `zh-cn`，`zh-tw` 映射 `zh-tw`，`en` 映射包内 `en-us`。值来自 `locales[appSettingsStore.lang]`；新增语言时不能只改 Vue I18n，也要补齐 Arco locale 映射并验证组件内置文案。

2.58.0 的 `AConfigProvider` 还支持 `size`、`rtl`、`update-at-scroll`、`scroll-to-close`、`exchange-time`、`global` 等配置，但当前项目没有启用这些项。不要把“库支持”写成“项目已启用”，也不要伪造全局 empty renderer 或统一 size。

主题不是由 `AConfigProvider` 切换。Provider 在客户端通过 `window.matchMedia('(prefers-color-scheme: dark)')` 监听系统方案；当项目设置跟随 system 时保留监听，否则移除监听。最终由 `currentColorScheme` 控制 `body`：

```ts
function updateTheme() {
  if (appSettingsStore.currentColorScheme === 'dark') {
    document.body.setAttribute('arco-theme', 'dark')
  }
  else {
    document.body.removeAttribute('arco-theme')
  }
}
```

Arco 暗色选择器因此依赖 `body[arco-theme="dark"]`。自定义主题变量应覆盖 Arco CSS variables，并同时验证 light、dark 与 system 三种路径；不能另建一套脱离现有 store 的主题状态。

## 命令式反馈 API

模板组件已全局注册，但脚本调用必须从包入口显式导入。最小示例只使用静态中文文案，不代表项目已有业务封装：

```ts
import { Message, Modal, Notification } from '@arco-design/web-vue'

export function showLocalExample() {
  Message.success('保存成功')
  Notification.info({
    title: '处理提示',
    content: '任务已进入本地示例队列',
  })
  Modal.warning({
    title: '操作确认',
    content: '这是静态演示，不会发送业务请求。',
  })
}
```

2.58.0 的 `Message`、`Notification` 与 `Modal` 静态方法会创建独立渲染节点，并接受可选 `AppContext`；它们与写在当前组件树中的 `AMessage` / `ANotification` / `AModal` 不是同一种调用路径。最近的 `AConfigProvider` 上下文不能被无条件视为静态节点的上下文。若业务需要统一 locale、容器、层级、关闭策略或错误记录，应先核对 `app.use(ArcoVue)` 设置的 context，再由项目明确建立封装；当前仓库没有可据此声称存在的项目封装。

选择原则：短暂、非阻塞结果用 `Message`；需要标题和较长说明用 `Notification`；必须让用户确认或处理中断性内容用 `Modal`。服务端错误不得把完整请求体、token、Cookie 或连接字符串直接展示或写日志。

## 工程边界、验证与升级

- **SSR 与浏览器边界**：当前正式应用是客户端应用，Provider 顶层直接访问 `window`，主题函数访问 `document`。若未来引入 SSR，必须把 `matchMedia`、事件监听和 DOM 属性更新放到 client-only 生命周期，并在卸载时移除监听；不能在服务端求值这些全局对象。
- **样式顺序**：Arco 的 `arco.css` 在 ui plugin 中引入，UnoCSS 与项目 `globals.css` 在应用入口引入。调整导入位置后要检查级联顺序、弹层和暗色覆盖，不能用无边界的 `!important` 修补。
- **主题变量**：优先覆写有明确语义的 Arco CSS variable；改动应同时观察组件默认、hover、focus、disabled、error 与 dark 状态。
- **TypeScript**：模板全局注册不会自动替代脚本类型；类型使用 `import type`，实例 ref 使用包导出的 `*Instance`，不要手写宽泛 `any` 模拟公开契约。
- **测试**：组件行为测试应挂载真实 Provider，并覆盖当前语言和主题；命令式 API 要在每个用例后 clear / close，避免跨用例残留 DOM。
- **升级**：先修改依赖并确认 `pnpm-lock.yaml` resolved version，再对照新 tag 检查 breaking change、locale、CSS 与 `.d.ts`，运行治理测试、类型检查、构建和实际页面检查。本文档固定 2.58.0，不以当前官网页面替代版本化核对。
