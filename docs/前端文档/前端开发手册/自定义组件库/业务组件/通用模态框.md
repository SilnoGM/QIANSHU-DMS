# 通用模态框

[返回自定义组件库](../README.md)

## 1. 组件定位

`QsGenericModal` 是千树 DMS 的聚焦任务业务模态框，源码位于：

```text
web/apps/qsmds-arco/src/components/business/QsGenericModal/
```

组件以加固后的 `FaModal` 为底层内核，统一标题区、可滚动正文、稳定状态、Footer、关闭守卫和响应式尺寸。它不调用业务 API、不读取 Store、不判断权限，也不内置确认、保存、编辑或删除动作。

本次选型没有采用 Arco `Modal`。当前需求需要的模态语义、单一遮罩、焦点约束、关闭焦点恢复、异步关闭守卫与保留挂载能力已经由加固后的 `FaModal` 提供；继续复用 Fa 内核可以保持项目主题、按钮、图标和生命周期一致。只有真实调用方提出 `FaModal` 无法覆盖且已验证的 Arco 独有契约时，才重新评估回退。

## 2. 最小用法

```vue
<script setup lang="ts">
import type { QsGenericModalCloseReason } from '@/components/business/QsGenericModal/logic'
import QsGenericModal from '@/components/business/QsGenericModal/index.vue'
import { ref } from 'vue'

const visible = ref(false)
const submitting = ref(false)
const hasUnsavedChanges = ref(false)

function beforeClose(reason: QsGenericModalCloseReason) {
  if (hasUnsavedChanges.value) {
    return false
  }

  console.info('modal close reason', reason)
  return true
}

async function submit() {
  submitting.value = true
  try {
    // 由业务页面调用真实保存逻辑。
    hasUnsavedChanges.value = false
    visible.value = false
  }
  finally {
    submitting.value = false
  }
}
</script>

<template>
  <FaButton @click="visible = true">
    打开模态框
  </FaButton>

  <QsGenericModal
    v-model="visible"
    title="复核应收费用"
    description="QS-202607-0042"
    :submitting="submitting"
    :before-close="beforeClose"
  >
    <p>业务表单或详情内容</p>

    <template #footer>
      <FaButton
        variant="outline"
        class="w-full sm:w-auto"
        @click="visible = false"
      >
        取消
      </FaButton>
      <FaButton
        class="w-full sm:w-auto"
        :loading="submitting"
        @click="submit"
      >
        保存
      </FaButton>
    </template>
  </QsGenericModal>
</template>
```

Footer 中的按钮、权限、校验、确认和请求全部由调用方负责。组件只在 `submitting=true` 时统一阻止误关闭并禁用 Footer 交互。

## 3. Props

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `modelValue` | `boolean` | `false` | 模态框受控可见状态，通过 `v-model` 使用。 |
| `title` | `string` | 必填 | 可见标题及模态框的可访问名称。 |
| `description` | `string` | `undefined` | 标题下方的辅助说明。 |
| `size` | `"sm" \| "md" \| "lg" \| "xl"` | `"md"` | 桌面最大宽度档位。 |
| `loading` | `boolean` | `false` | 使用 Loading 插槽或默认骨架替换正文。 |
| `submitting` | `boolean` | `false` | 保留正文，阻止所有关闭方式，并使 Footer 不可交互。 |
| `error` | `string \| null` | `null` | 在正文顶部显示内联错误。 |
| `closable` | `boolean` | `true` | 是否显示标题区关闭按钮。 |
| `destroyOnClose` | `boolean` | `true` | 关闭后是否销毁内容。 |
| `dismissOnOverlay` | `boolean` | `true` | 是否允许点击遮罩发起关闭。 |
| `dismissOnEscape` | `boolean` | `true` | 是否允许按 `Escape` 发起关闭。 |
| `beforeClose` | `(reason) => boolean \| Promise<boolean>` | `undefined` | 所有关闭来源共用的同步或异步守卫。 |

四档桌面最大宽度分别为 `480px`、`560px`、`720px`、`896px`。窄屏始终保留左右各 `12px` 视口边距，最大高度为 `calc(100dvh - 24px)`。

## 4. Events

| Event | 参数 | 触发时机 |
| --- | --- | --- |
| `update:modelValue` | `boolean` | 组件接受打开或关闭状态时。 |
| `opened` | 无 | 打开动画结束后。 |
| `closed` | 无 | 关闭动画结束后。 |

组件不提供 `confirm`、`cancel`、`save` 或 `delete` 事件。业务动作属于 Footer 调用方。

## 5. Slots

| Slot | 用途 |
| --- | --- |
| `default` | 表单、详情或其他业务正文。 |
| `header-leading` | 标题左侧图标或紧凑标识。 |
| `header-extra` | 标题右侧状态标签等辅助信息。 |
| `loading` | 覆盖默认骨架；内容应保留可理解的状态文案。 |
| `error-actions` | 错误信息后的重试或恢复操作。 |
| `footer` | 调用方控制的状态说明和业务按钮。 |

未提供 Footer 时组件不会保留空操作区。移动端按钮需要调用方使用 `w-full sm:w-auto` 等布局类明确声明，组件不猜测哪个按钮是主操作。

## 6. 关闭语义

`beforeClose` 的 `reason` 为以下四种之一：

| Reason | 来源 |
| --- | --- |
| `close-button` | 点击组件标题区的关闭按钮。 |
| `overlay` | 点击底层遮罩。 |
| `escape` | 按下 `Escape`。 |
| `programmatic` | 父组件把 `v-model` 改为 `false`，包括 Footer 按钮执行的受控关闭。 |

守卫返回 `true` 才继续关闭；返回 `false`、异步拒绝或抛出异常时保持打开。业务错误提示应由调用方在守卫内部写入自己的状态，组件不会把未知异常转换成固定用户文案。

同一时刻只执行一个关闭守卫。`submitting=true` 时组件在调用守卫前直接拒绝关闭，调用方必须通过 `finally` 等路径可靠释放提交状态，避免用户被永久困在模态框中。

## 7. Loading、Error 与 Submitting

- `loading`：正文显示稳定骨架，错误和默认内容暂不显示；不使用覆盖整个模态框的大型旋转图标。
- `error`：Loading 结束后在正文顶部使用主题化内联 Alert，并允许通过 `error-actions` 提供重试。
- `submitting`：已有正文继续可见，标题关闭、遮罩、`Escape`、程序关闭和 Footer 交互均被暂时阻止。
- 空内容：由调用方决定，不内置虚构业务空状态。

如果页面已有旧数据，建议由页面保留数据并只切换 `submitting` 或自己的刷新状态，不要每次后台刷新都把正文替换为首屏骨架。

## 8. 响应式与可访问性

- 模态框水平、垂直居中，窄屏保留 `12px` 视口边距。
- 内容最大高度使用 `100dvh` 计算，Header 与 Footer 保持稳定，正文独立滚动。
- Footer 使用 `env(safe-area-inset-bottom)` 保护移动设备底部安全区。
- 可见标题与说明同时传入 `FaModal`，由隐藏的 `DialogTitle` 和 `DialogDescription` 提供真实可访问名称。
- 底层保持 `role="dialog"`、`aria-modal="true"`、焦点约束、背景滚动锁与关闭焦点恢复。
- 默认关闭按钮在移动端为 `44px` 触摸目标，桌面为 `36px`。
- 动画只使用透明度与缩放，并在 `prefers-reduced-motion` 下缩短为近零时长。

真实移动设备安全区、焦点循环、关闭焦点恢复、遮罩、`Escape` 和动画行为必须在浏览器中验收，源码字符串测试不能替代运行时证明。

## 9. `destroyOnClose`

- `true`：关闭后销毁正文，适合每次打开都重新初始化的表单或详情。
- `false`：关闭后保留正文状态，但底层内容退出焦点范围和模态交互；再次打开时重新进入焦点约束。

保留挂载不等于缓存业务请求。请求生命周期、脏数据处理和身份切换后的失效策略仍由调用方负责。

## 10. 第一版不支持

- 命令式 Modal Service、全局队列或跨路由弹窗管理。
- 多层嵌套模态框栈和自动 z-index 编排。
- 拖拽、最大化、全屏或任意 class 逃生口。
- 内置表单提交、权限判断、API 请求和固定业务动作。
- 自动未保存确认文案；需要时由调用方的 `beforeClose` 状态实现。

新增这些能力前必须由至少两个真实调用方证明稳定需求，并重新评估底层内核是否仍适合使用 `FaModal`。

## 11. Showcase 与验证

独立展示路由：

```text

```

选择“长内容滚动”状态后再打开模态框，可使用十条本地费用数据直接验收高度边界。滚动期间 Header 与 Footer 应保持可见，只有正文内容移动；无需连接业务 API。
