# 通用表格：QsGenericTable

[返回自定义组件库](../README.md)

## 1. 组件定位

`QsGenericTable` 是 `web/apps/qsmds-arco` 内的业务通用表格。其内核关系为：

```text
QsGenericTable
├── FaTable
│   └── TanStack Table
└── FaPagination
```

组件统一搜索、筛选、排序、分页、列设置、复制、汇总、加载、错误、空状态和移动卡片的交互骨架，但不请求 API、不读取 Store，也不内置具体业务按钮、权限或数据写入。

| 项目 | 当前值 |
| --- | --- |
| 主组件 | `web/apps/qsmds-arco/src/components/business/QsGenericTable/index.vue` |
| 类型与纯逻辑 | `web/apps/qsmds-arco/src/components/business/QsGenericTable/logic.ts` |
| Showcase | `web/apps/qsmds-arco/src/views/component_library/business/components/GenericTableShowcase.vue` |
| 路由 | `/component-library/business/generic-table` |
| 测试 | `web/apps/qsmds-arco/test/views/generic-table.test.ts`、`generic-table-showcase.test.ts` |

组件位于嵌套业务组件目录，不在当前自动组件扫描范围内，必须显式导入。

## 2. 核心边界

调用方负责：

- 根据搜索、筛选、排序和分页状态请求或计算数据。
- 把已经处理好的当前页记录传入 `data`，服务端分页时同时传入 `total`。
- 处理新增、重试和行操作中的跳转、权限、确认、写入及错误反馈。
- 决定单号、金额、日期、状态等字段的业务语义和排版角色。

组件不会：

- 自动搜索、过滤、排序或分页切片。
- 调用领域 API、访问业务 Store 或持久化列设置。
- 提供固定的“查看”“编辑”“删除”等业务动作。
- 根据列名、内容或对齐方式推断数据类型。

## 3. 可运行的本地数据示例

```vue
<script setup lang="ts">
import type {
  QsGenericTableColumn,
  QsGenericTableFilterDefinition,
  QsGenericTableFilterValues,
} from '@/components/business/QsGenericTable/logic'

import AmountDisplay from '@/components/base/AmountDisplay/index.vue'
import DateTimeDisplay from '@/components/base/DateTimeDisplay/index.vue'
import QsGenericTable from '@/components/business/QsGenericTable/index.vue'

interface SettlementRow {
  amount: string
  id: string
  settlementNo: string
  status: '待复核' | '已完成'
  updatedAt: string
}

const sourceRows: SettlementRow[] = [
  {
    amount: '12800.00',
    id: '1',
    settlementNo: 'QS-202607-0001',
    status: '待复核',
    updatedAt: '2026-07-24T02:30:00.000Z',
  },
  {
    amount: '9600.00',
    id: '2',
    settlementNo: 'QS-202607-0002',
    status: '已完成',
    updatedAt: '2026-07-24T03:30:00.000Z',
  },
]

const page = ref(1)
const pageSize = ref(20)
const search = ref('')
const filters = ref<QsGenericTableFilterValues>({})
const selectedRow = shallowRef<SettlementRow>()

const filterDefinitions: QsGenericTableFilterDefinition[] = [
  {
    key: 'status',
    label: '结算状态',
    options: [
      { label: '待复核', value: '待复核' },
      { label: '已完成', value: '已完成' },
    ],
  },
]

const columns: QsGenericTableColumn<SettlementRow>[] = [
  {
    accessorKey: 'settlementNo',
    cellClass: 'qs-type-data-emphasis',
    copyable: true,
    fixed: 'left',
    id: 'settlementNo',
    title: '结算单号',
    width: 180,
  },
  {
    accessorKey: 'amount',
    align: 'right',
    cellClass: 'qs-type-data-emphasis',
    id: 'amount',
    summary: {
      component: AmountDisplay,
      componentProps: { currency: 'CNY' },
      type: 'sum',
    },
    title: '结算金额',
    width: 160,
  },
  {
    accessorKey: 'updatedAt',
    cellClass: 'qs-type-data',
    id: 'updatedAt',
    title: '更新时间',
    width: 180,
  },
]

const filteredRows = computed(() => sourceRows.filter((row) => {
  const keywordMatched = !search.value
    || row.settlementNo.includes(search.value)
  const statusMatched = !filters.value.status
    || row.status === filters.value.status

  return keywordMatched && statusMatched
}))

const pageRows = computed(() => {
  const start = (page.value - 1) * pageSize.value
  return filteredRows.value.slice(start, start + pageSize.value)
})

function openDetail(row: SettlementRow) {
  selectedRow.value = row
}
</script>

<template>
  <QsGenericTable
    v-model:page="page"
    v-model:page-size="pageSize"
    v-model:search="search"
    v-model:filters="filters"
    row-key="id"
    :columns="columns"
    :data="pageRows"
    :total="filteredRows.length"
    :filter-definitions="filterDefinitions"
    :action-column="{ width: 120 }"
    :addable="false"
  >
    <template #cell-amount="{ row }">
      <AmountDisplay :value="row.original.amount" currency="CNY" />
    </template>

    <template #cell-updatedAt="{ row }">
      <DateTimeDisplay :value="row.original.updatedAt" />
    </template>

    <template #mobile-row="{ row, rowNumber }">
      <div class="gap-3 grid">
        <div class="flex gap-3 items-center justify-between">
          <span class="qs-type-meta">#{{ rowNumber }}</span>
          <span class="qs-type-data-emphasis">{{ row.settlementNo }}</span>
        </div>
        <div class="flex gap-3 items-center justify-between">
          <span class="qs-type-meta">结算金额</span>
          <AmountDisplay :value="row.amount" currency="CNY" />
        </div>
        <div class="flex gap-3 items-center justify-between">
          <span class="qs-type-meta">更新时间</span>
          <DateTimeDisplay :value="row.updatedAt" />
        </div>
      </div>
    </template>

    <template #actions="{ row, rowNumber }">
      <FaButton
        variant="ghost"
        size="sm"
        :aria-label="`查看第 ${rowNumber} 行`"
        @click="openDetail(row)"
      >
        查看
      </FaButton>
    </template>
  </QsGenericTable>

  <p v-if="selectedRow" class="qs-type-meta">
    当前选择：<span class="qs-type-data-emphasis">{{ selectedRow.settlementNo }}</span>
  </p>
</template>
```

示例使用本地静态数据说明状态归属，不代表仓库存在对应业务 API。真实页面应在组件事件中调用项目已经存在的 API client，并把结果重新传给组件。

## 4. Props

### 4.1 数据与列

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `columns` | `QsGenericTableColumn<TData>[]` | 必填 | 业务列定义 |
| `data` | `TData[]` | 必填 | 已搜索、筛选、排序并分页后的当前页数据 |
| `rowKey` | `TableProps<TData>['rowKey']` | `undefined` | 桌面行 ID 和移动卡片 key；动态数据应始终提供稳定业务键 |
| `total` | `number` | `data.length` | 总数据量；服务端分页必须显式传入 |
| `summaryValues` | `Record<string, number \| string \| null>` | `{}` | 按列 ID 覆盖组件计算的汇总值 |
| `tableClass` | `string` | `undefined` | 传给底层 `<table>`，常用于设置最小宽度 |

### 4.2 工具栏与分页

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `addable` | `boolean` | `true` | 是否显示新增按钮；页面不支持新增时必须显式关闭 |
| `addLabel` | `string` | `'新增数据'` | 新增按钮文案 |
| `searchable` | `boolean` | `true` | 是否显示搜索框 |
| `searchPlaceholder` | `string` | `'搜索当前业务数据'` | 搜索框提示文案 |
| `filterDefinitions` | `QsGenericTableFilterDefinition[]` | `[]` | 下拉筛选定义；空数组隐藏筛选入口 |
| `showColumnSettings` | `boolean` | `true` | 是否显示列设置；所有工具关闭时不保留空工具栏间距 |
| `showPagination` | `boolean` | `true` | 是否显示分页；总数为 `0` 时仍隐藏 |
| `pageSizeOptions` | `number[]` | `[20, 50, 100, 200]` | 每页数量选项 |

### 4.3 状态与外观

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `loading` | `boolean` | `false` | 首屏空数据时显示骨架；有旧数据时保留内容并降低透明度 |
| `error` | `string` | `undefined` | 错误提示；提供“重试”入口 |
| `emptyTitle` | `string` | `'暂无数据'` | 无查询条件时的空状态标题 |
| `emptyDescription` | `string` | `'当前没有可展示的数据。'` | 无查询条件时的空状态说明 |
| `border` | `boolean` | `false` | 是否启用桌面表格边框 |
| `stripe` | `boolean` | `false` | 是否启用桌面斑马纹 |
| `actionColumn` | `QsGenericTableActionColumn` | `{}` | 仅在存在 `actions` 插槽时生效 |

已有页面复用自己的页头查询或操作区时，可以关闭 `searchable`、`addable` 和 `showColumnSettings`；筛选定义同时为空时，组件会移除整个工具栏。

## 5. `v-model`

| Model | 类型 | 默认值 | 行为 |
| --- | --- | --- | --- |
| `v-model:page` | `number` | `1` | 当前页，从 `1` 开始 |
| `v-model:page-size` | `number` | `20` | 每页数量；修改后把页码重置为 `1` |
| `v-model:search` | `string` | `''` | 已提交并去除首尾空白的搜索词 |
| `v-model:filters` | `QsGenericTableFilterValues` | `{}` | 已应用的筛选条件 |
| `v-model:sorting` | `TableSortingState` | `[]` | TanStack Table 排序状态 |

组件内交互会产生对应的 `update:*` 事件。搜索、筛选和排序会把 `page` 更新为 `1`，但不会额外触发 `paginationChange`；调用方需要监听对应业务事件或模型更新，而不能只监听分页事件。

调用方直接修改 `search`、`filters` 或 `sorting` 模型时，组件只同步内部展示状态，不会反向触发 `search`、`filterChange` 或 `sortingChange`，也不会替调用方重置页码或重新加载数据。外部状态变更的页码归一和数据刷新由调用方负责。

## 6. Events

| Event | 参数 | 触发时机 |
| --- | --- | --- |
| `add` | 无 | 点击新增按钮 |
| `columnSettingsChange` | `QsGenericTableColumnSettings` | 调整列显隐、固定、对齐或恢复默认 |
| `filterChange` | `QsGenericTableFilterValues` | 应用、重置、移除筛选或清除全部查询 |
| `paginationChange` | `{ page: number, pageSize: number }` | 分页器修改页码或每页数量 |
| `retry` | 无 | 点击错误提示中的“重试” |
| `rowClick` | `{ row: TData, index: number, event: MouseEvent }` | 点击表格行；不监听该事件的页面行为不变 |
| `search` | `string` | 回车、点击查询、清空搜索或清除全部查询 |
| `sortingChange` | `TableSortingState` | 用户修改排序 |

Vue 模板中使用 kebab-case。以下事件连接片段依赖第 3 节已经声明的 `columns`、`pageRows` 和业务页面自行实现的 `reload`：

```vue
<template>
  <QsGenericTable
    :columns="columns"
    :data="pageRows"
    @search="reload"
    @filter-change="reload"
    @sorting-change="reload"
    @pagination-change="reload"
    @retry="reload"
  />
</template>
```

上例中的 `reload` 由业务页面实现；组件不会替调用方发起请求。

## 7. Slots

| Slot | Scope | 说明 |
| --- | --- | --- |
| `cell-{columnId}` | `cell`、`column`、`index`、`row`、`table`、`value` | 桌面单元格；原始业务数据为 `row.original` |
| `header-{columnId}` | `column`、`header`、`table` | 桌面自定义表头 |
| `summary-{columnId}` | `column`、`label`、`value` | 汇总列内容；同一插槽用于桌面表尾和移动汇总区 |
| `actions` | `row`、`index`、`rowNumber` | 行操作；`row` 为原始业务对象，`index` 为当前页索引 |
| `mobile-row` | `columns`、`row`、`index`、`rowNumber` | 完全替换默认移动卡片主体 |

组件没有普通默认插槽。`mobile-row` 只替换卡片主体，操作区和汇总区仍由组件统一追加。

## 8. 列定义

`QsGenericTableColumn<TData>` 继承底层 `TableColumn<TData>`，增加以下业务字段：

| 字段 | 类型 | 默认行为 |
| --- | --- | --- |
| `id` | `string` | 必填且必须唯一 |
| `title` | `string` | 必填；用于列设置、移动字段名和复制按钮标签 |
| `copyable` | `boolean` | 默认关闭 |
| `defaultVisible` | `boolean` | 默认 `true` |
| `sortable` | `boolean` | 优先于继承的 `enableSorting`，最终默认 `false` |
| `summary` | `QsGenericTableSummaryDefinition<TData>` | 配置 `count`、`average` 或 `sum` |

常用继承字段包括 `accessorKey`、`accessorFn`、`cellClass`、`header`、`footer`、`align`、`fixed`、`width`、`minWidth` 和 `maxWidth`。

业务列不得使用以下保留 ID：

```text
__qs_generic_table_row_number__
__qs_generic_table_actions__
```

行号列由组件生成，始终固定在左侧，不参与排序和列显隐。连续行号按以下公式计算：

```text
(page - 1) * pageSize + rowIndex + 1
```

## 9. 搜索、筛选、排序与分页

### 9.1 搜索

搜索框维护未提交草稿。点击“查询”、按 Enter 或清空输入后，组件才会：

1. 去除首尾空白。
2. 更新 `v-model:search`。
3. 把页码重置为 `1`。
4. 触发 `search`。

组件不会根据搜索词修改 `data`。

### 9.2 筛选

筛选定义：

```ts
type QsGenericTableFilterValue = number | string | undefined

interface QsGenericTableFilterOption {
  label: string
  value: number | string
}

interface QsGenericTableFilterDefinition {
  key: string
  label: string
  options: readonly QsGenericTableFilterOption[]
  placeholder?: string
}

type QsGenericTableFilterValues =
  Record<string, QsGenericTableFilterValue>
```

面板选择先写入内部草稿，只有点击“应用筛选”才更新 `v-model:filters` 并触发 `filterChange`。关闭面板不会提交草稿。

### 9.3 排序

列只有在 `sortable: true` 或继承的 `enableSorting: true` 时允许排序。组件更新 TanStack `TableSortingState`、重置页码并触发 `sortingChange`，不重排 `data`。

### 9.4 分页

分页器只更新 `page` 和 `pageSize`。服务端分页必须传入当前页 `data` 与全量 `total`；本地数据必须由调用方按相同状态完成切片。

## 10. 操作列

只有提供 `actions` 插槽时，组件才在业务列之后追加操作列。没有该插槽时不会产生空操作列。

`actionColumn`：

| 字段 | 类型 | 默认值 |
| --- | --- | --- |
| `title` | `string` | `'操作'` |
| `width` | `number \| string` | `160` |
| `minWidth` | `number \| string` | `undefined` |
| `maxWidth` | `number \| string` | `undefined` |
| `align` | `'left' \| 'center' \| 'right'` | `'left'` |
| `fixed` | `false \| 'left' \| 'right'` | `'right'` |

操作列不可隐藏、不可排序，也不进入列设置和汇总。`fixed: false` 可以取消默认右侧固定。

`actions` 插槽提供：

- `row`：原始业务对象。
- `index`：当前页内从 `0` 开始的索引。
- `rowNumber`：跨分页连续行号。

按钮、权限判断、禁用条件、确认弹窗和写入副作用全部由调用方负责。桌面端操作列使用同一插槽渲染；小于 `768px` 时，操作区自动放到移动卡片底部。

## 11. 汇总

列的 `summary` 类型：

```ts
interface QsGenericTableSummaryDefinition<TData> {
  type: 'average' | 'count' | 'sum'
  getValue?: (row: TData, index: number) => unknown
  component?: Component
  componentProps?:
    | Record<string, unknown>
    | ((value: number | string | null) => Record<string, unknown>)
}
```

| `type` | 规则 |
| --- | --- |
| `count` | 统计不为 `undefined`、`null` 和空字符串的值，文本也可计数 |
| `sum` | 对有限数字及普通十进制数字字符串求和 |
| `average` | 对有效数值求平均 |
| 无有效数值 | 返回 `null`，默认显示 `—` |

默认汇总传入的 `data`。若 `data` 是当前页数据，结果就是当前页汇总；服务端分页需要全量结果时，可通过 `summaryValues[columnId]` 覆盖。

内置 `sum/average` 是通用数值汇总，当前会把值转换为 JavaScript `number`，不承担数据库 `DECIMAL` 金额的精确计算，也不会替业务页面验证严格金额字符串。金额列应使用
[金额输入](../基础组件/金额输入.md)提供的 `sumMoneyValues` 在调用方精确求和，再通过已有
`summaryValues` 注入：

```ts
import { sumMoneyValues } from '@/components/base/MoneyInput/logic'

const summaryValues = computed(() => ({
  amount: sumMoneyValues(
    pageRows.value.map(row => row.amount),
    { precision: 2 },
  ),
}))
```

```vue
<QsGenericTable
  :columns="columns"
  :data="pageRows"
  :summary-values="summaryValues"
/>
```

`sumMoneyValues` 忽略 `null`，但遇到非法非空金额会抛出 `MoneyValidationError`。业务页面必须把该错误收敛为字段或数据质量错误，不能静默跳过后继续显示错误总额。汇总结果是十进制字符串，可以继续交给 `AmountDisplay`。

`summary-{columnId}` 可以覆盖默认内容，且必须同时兼容桌面表尾和移动汇总区。当前即使 `summaryValues` 来自全量数据，移动端汇总区标题仍固定为“当前页汇总”，调用方不能通过 Prop 修改该标题。

未提供自定义组件或插槽时，默认汇总按以下方式展示：

- `number` 使用 `Intl.NumberFormat('zh-CN', { maximumFractionDigits: 2 })`。
- `string` 原样显示。
- `null` 或空字符串显示 `—`。
- 配置 `summary.component` 时，组件始终把最终汇总结果作为 `value` Prop 传入，并合并 `componentProps`。

## 12. 列设置

列设置支持：

- 显示或隐藏业务列。
- 固定到左侧、右侧或取消固定。
- 左、中、右内容对齐。
- 恢复 `columns` 声明的默认状态。

`columnSettingsChange` 会输出每列的 `visible`、`fixed` 和 `align`，业务页面可以保存该事件结果。但组件当前没有 `columnSettings` Prop 或 `v-model`，因此无法把已保存的设置直接回灌到组件。若业务需求包含跨会话恢复，必须先扩展受控接口，不能把事件输出误认为完整持久化能力。

`columns` 动态变化时，新列使用自身默认设置，删除的列会从内部设置移除；相同 `id` 的已有列保留用户当前设置，因此后续只修改该列的 `defaultVisible`、`fixed` 或 `align` 不会覆盖已存在的内部状态。

## 13. 复制与复合单元格

### 13.1 复制

`copyable: true` 会在桌面单元格追加复制按钮，按钮在悬停或键盘聚焦时显示；默认移动卡片始终显示复制入口。

复制原始值来自列的 `accessorKey` 或 `accessorFn`，再经过统一展示转换：`undefined`、`null` 和空字符串会变成 `—`，复制按钮也会复制该文本。自定义 `cell-*` 只改变可见内容，不改变默认复制文本。复制成功、失败均有状态反馈。自定义 `mobile-row` 后，调用方需要显式组合：

```ts
import CopyCellButton from '@/components/business/QsGenericTable/CopyCellButton.vue'
```

### 13.2 复合单元格

一列需要展示主值、辅助说明、多个金额或状态时，可显式导入：

```ts
import QsTableStackedCell from '@/components/business/QsGenericTable/QsTableStackedCell.vue'
import QsTableStackedLine from '@/components/business/QsGenericTable/QsTableStackedLine.vue'
```

这两个组件只管理纵向节奏和逐行样式，不内置订单、金额等业务语义。排序和默认复制仍由原列的 `accessorKey` 或 `accessorFn` 决定。

配套组件的最小接口：

| 组件 | Props | Slots |
| --- | --- | --- |
| `CopyCellButton` | `label: string`、`text: string`、`alwaysVisible?: boolean`，默认 `false` | 无 |
| `QsTableStackedCell` | 无专用 Prop，根节点接收普通 attribute | 默认插槽 |
| `QsTableStackedLine` | `label?`、`tone?`、`weight?`、`nowrap?`、`labelClass?`、`contentClass?`、`suffixClass?` | 默认插槽、`suffix` |

## 14. 响应式行为

| 视口 | 行为 |
| --- | --- |
| `>= 768px` | 使用 `FaTable`；筛选和列设置使用 Popover；分页包含 jumper |
| `< 768px` | 使用卡片列表；筛选和列设置使用底部 Drawer；分页不包含 jumper |

默认移动卡片通过 `accessorKey` 或 `accessorFn` 读取原始值，不执行桌面 `cell-{columnId}` 插槽。金额、日期、复合内容或业务化布局必须通过 `mobile-row` 单独定义。

即使使用 `mobile-row`，组件仍会追加：

- `actions` 操作区。
- 配置了 `summary` 的移动汇总区。

## 15. 加载、错误与空状态

| 状态 | 表现 |
| --- | --- |
| `loading=true` 且 `data` 为空 | 显示骨架 |
| `loading=true` 且已有 `data` | 保留旧数据；数据展示区域降低透明度并阻止指针交互 |
| `error` 非空 | 在现有内容上方增加错误 Alert 和“重试”按钮 |
| 无数据且无查询条件 | 显示 `emptyTitle`、`emptyDescription` |
| 无数据且有搜索或筛选 | 显示“没有匹配结果”，允许清除查询条件 |

组件只呈现状态。加载时工具栏和分页不会自动禁用，键盘交互也不能只靠 `pointer-events` 完整阻止，调用方仍需防止重复请求或业务动作。`error` 不会隐藏已有表格或卡片，也不会自动停止 `loading`。何时清除旧数据、如何重试以及错误信息来源由业务页面决定。

## 16. 排版语义

组件遵循[全局排版规范](../../../全局排版规范.md)：

| 数据角色 | 使用方式 |
| --- | --- |
| 表头 | 组件自动使用 Sans `13/18/600` 和主题 `muted-foreground` |
| 普通正文 | 默认 `qs-type-body`，Sans `14/20/400` |
| 行号、来源、辅助说明 | `qs-type-meta`，Sans `12/16/400` |
| 数量、百分比、日期时间 | `qs-type-data`，Mono `14/20/400`、`tabular-nums` |
| 单号、编码、金额、汇总 | `qs-type-data-emphasis`，Mono `14/20/500` |
| 状态标签 | 调用方显式使用 `qs-type-status-tag` |
| 操作按钮 | `FaButton` 自动使用 `action`，禁用态统一 `opacity: 0.5` |

桌面单值优先通过 `cellClass` 声明语义，复杂内容使用 `cell-*` 插槽，移动卡片使用 `mobile-row`。日期时间和金额优先复用[日期显示](../基础组件/日期显示.md)与[金额显示](../基础组件/金额显示.md)。

`align: 'right'` 只表达布局，不会自动应用 Mono、数字等宽或金额字重。`cellClass` 只作用于桌面 `<td>`，不会自动进入移动卡片。

## 17. 已知限制

- 没有 API、Store、权限、确认弹窗或数据写入副作用。
- 没有内部搜索、过滤、排序和分页切片。
- 没有行选择公共契约。
- 行号列不能关闭。
- 列设置只有输出事件，没有受控输入或恢复已持久化状态的接口。
- 默认移动卡片不执行桌面 `cell-*` 插槽。
- `summary-{columnId}` 必须同时兼容桌面和移动端。
- `summaryValues` 即使提供全量汇总，移动端标题仍显示“当前页汇总”。
- `columns` 的 `id` 必须唯一，且不能与保留 ID 冲突。
- 生产环境默认不注册组件库路由。
