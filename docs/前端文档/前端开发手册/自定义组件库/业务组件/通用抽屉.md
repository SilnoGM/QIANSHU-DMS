# 通用抽屉

## 1. 组件定位

`QsGenericDrawer` 是千树 DMS 的任务型业务抽屉，源码位于：

```text
web/apps/qsmds-arco/src/components/business/QsGenericDrawer/
```

组件以 `FaDrawer` 为底层内核，统一标题区、可滚动正文、状态反馈、Footer、关闭守卫、响应式尺寸和焦点恢复。它不调用业务 API、不读取 Store、不判断权限，也不内置编辑、删除或保存动作。

页面需要完整 Arco Drawer 特性且已经确认 `FaDrawer` 内核无法满足时，才单独评估回退；不得仅为局部视觉差异在同一业务中混用两套 Drawer。

## 2. 最小用法

```vue
<script setup lang="ts">
import type { QsGenericDrawerCloseReason } from '@/components/business/QsGenericDrawer/logic'
import QsGenericDrawer from '@/components/business/QsGenericDrawer/index.vue'
import { ref } from 'vue'

const visible = ref(false)
const submitting = ref(false)
const hasUnsavedChanges = ref(false)

function beforeClose(reason: QsGenericDrawerCloseReason) {
  if (hasUnsavedChanges.value) {
    return false
  }

  console.info('drawer close reason', reason)
  return true
}

async function submit() {
  submitting.value = true
  try {
    // 由业务页面调用真实保存逻辑。
    visible.value = false
  }
  finally {
    submitting.value = false
  }
}
</script>

<template>
  <FaButton @click="visible = true">
    打开抽屉
  </FaButton>

  <QsGenericDrawer
    v-model="visible"
    title="复核运输委托"
    description="QS-202607-0042"
    :submitting="submitting"
    :before-close="beforeClose"
  >
    <p>业务表单或详情内容</p>

    <template #footer>
      <FaButton
        variant="outline"
        class="w-full md:w-auto"
        @click="visible = false"
      >
        取消
      </FaButton>
      <FaButton
        class="w-full md:w-auto"
        :loading="submitting"
        @click="submit"
      >
        保存
      </FaButton>
    </template>
  </QsGenericDrawer>
</template>
```

Footer 中的按钮、权限、校验、确认和请求全部由调用方负责。组件只在 `submitting=true` 时统一阻止误关闭并禁用 Footer 交互。

## 3. Props

| Prop | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `modelValue` | `boolean` | `false` | 抽屉受控可见状态，通过 `v-model` 使用。 |
| `title` | `string` | 必填 | 可见标题及抽屉的可访问名称。 |
| `description` | `string` | `undefined` | 标题下方的辅助说明。 |
| `size` | `"sm" \| "md" \| "lg" \| "xl"` | `"md"` | 右侧抽屉桌面宽度；底部模式不使用宽度档位。 |
| `placement` | `"right" \| "bottom"` | `"right"` | 抽屉出现方向。 |
| `loading` | `boolean` | `false` | 使用 Loading 插槽或默认骨架替换正文。 |
| `submitting` | `boolean` | `false` | 保留正文，阻止所有关闭方式，并使 Footer 不可交互。 |
| `error` | `string \| null` | `null` | 在正文顶部显示内联错误。 |
| `closable` | `boolean` | `true` | 是否显示标题区关闭按钮。 |
| `destroyOnClose` | `boolean` | `true` | 关闭后是否销毁内容。 |
| `dismissOnOverlay` | `boolean` | `true` | 是否允许点击遮罩发起关闭。 |
| `dismissOnEscape` | `boolean` | `true` | 是否允许按 `Escape` 发起关闭。 |
| `beforeClose` | `(reason) => boolean \| Promise<boolean>` | `undefined` | 所有关闭来源共用的同步或异步守卫。 |

桌面右侧尺寸分别为 `384px`、`480px`、`640px`、`768px`，并且不超过 `calc(100vw - 48px)`。小于 `768px` 时右侧抽屉使用视口全宽。

## 4. Events

| Event | 参数 | 触发时机 |
| --- | --- | --- |
| `update:modelValue` | `boolean` | 组件接受打开或关闭状态时。 |
| `opened` | 无 | 打开动画结束后。 |
| `closed` | 无 | 关闭动画结束且准备恢复焦点时。 |

组件不额外提供 `confirm`、`cancel`、`save` 或 `delete` 事件。业务动作属于 Footer 调用方。

## 5. Slots

| Slot | 用途 |
| --- | --- |
| `default` | 表单、详情或其他业务正文。 |
| `header-leading` | 标题左侧图标或紧凑标识。 |
| `header-extra` | 标题右侧状态标签等辅助信息。 |
| `loading` | 覆盖默认骨架；内容应保留 `role="status"` 对应的可理解文案。 |
| `error-actions` | 错误信息后的重试或恢复操作。 |
| `footer` | 调用方控制的状态说明和业务按钮。 |

未提供 Footer 时组件不会保留空操作区。移动端按钮需要调用方使用 `w-full md:w-auto` 等布局类明确声明，组件不猜测哪个按钮是主操作。

## 6. 关闭语义

`beforeClose` 的 `reason` 为以下四种之一：

| Reason | 来源 |
| --- | --- |
| `close-button` | 点击组件标题区的关闭按钮。 |
| `overlay` | 点击底层遮罩。 |
| `escape` | 按下 `Escape`。 |
| `programmatic` | 父组件把 `v-model` 改为 `false`，包括 Footer 按钮执行的受控关闭。 |

守卫返回 `true` 才继续关闭；返回 `false`、异步拒绝或抛出异常时保持打开。业务错误提示应由调用方在守卫内部写入自己的状态，组件不会把未知异常转换成用户文案。

同一时刻只执行一个关闭守卫。`submitting=true` 时组件在调用守卫前直接拒绝关闭，调用方必须通过 `finally` 等路径可靠释放提交状态，避免用户被永久困在抽屉中。

## 7. Loading、Error 与 Submitting

- `loading`：正文显示骨架，错误和默认内容暂不显示；不使用覆盖整个抽屉的大型旋转图标。
- `error`：Loading 结束后在正文顶部使用主题化的内联 Alert，并允许通过 `error-actions` 提供重试。
- `submitting`：已有正文继续可见，标题关闭、遮罩、`Escape`、程序关闭和 Footer 交互均被暂时阻止。
- 空内容：由调用方决定，不内置虚构业务空状态。

如果页面已有旧数据，建议由页面保留数据并只切换 `submitting` 或自己的刷新状态，不要每次后台刷新都把正文替换为首屏骨架。

## 8. 响应式与可访问性

- 右侧模式在窄屏全宽显示，从 `768px` 开始应用尺寸档位。
- 底部模式高度不超过 `calc(100dvh - 16px)`，顶部保留圆角。
- Footer 使用 `env(safe-area-inset-bottom)` 保护移动设备底部安全区。
- 标题和说明同时写入 `FaDrawer` 的 `SheetTitle` 与 `SheetDescription` 语义。
- 默认关闭按钮在移动端为 `44px` 触摸目标，桌面为 `36px`。
- 打开后沿用 `FaDrawer` 的面板聚焦；关闭动画完成后恢复到仍存在的打开触发器。
- 开关动画只使用位移和透明度，并在 `prefers-reduced-motion` 下关闭持续时间。

真实 iOS 安全区、焦点恢复、遮罩、`Escape` 和动画行为必须在浏览器中验收，源码字符串测试不能替代运行时证明。

## 9. 第一版不支持

- 命令式 Drawer Service 或全局队列。
- 多层嵌套抽屉栈、焦点栈和自动 z-index 编排。
- 拖拽关闭或无手势支持的装饰性把手。
- 桌面全屏模式、左右任意方向或高度拖拽。
- 内置表单提交、权限判断、API 请求和固定业务动作。
- 自动离开确认文案；需要时由调用方的 `beforeClose` 状态实现。

新增这些能力前必须由至少两个真实调用方证明稳定需求，并重新评估底层内核是否仍适合使用 `FaDrawer`。
