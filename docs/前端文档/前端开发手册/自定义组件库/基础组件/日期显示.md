# 日期显示：DateTimeDisplay

[返回自定义组件库](../README.md)

## 1. 组件定位

`DateTimeDisplay` 是 `web/apps/qsmds-arco` 内的只读日期时间显示组件。它把明确的时刻按指定 IANA 时区输出为稳定的现代业务日期结构，避免浏览器默认语言、本地时区或字段顺序造成显示漂移。

组件只解析和格式化调用方传入的值，不读取业务 Store、不请求 API，也不推断业务时区。当前属于应用内可复用基础组件，尚未从 `web/packages/*` 导出，也没有注册为全局组件。

| 项目 | 当前值 |
| --- | --- |
| 组件源码 | `web/apps/qsmds-arco/src/components/base/DateTimeDisplay/index.vue` |
| 格式化内核 | `web/apps/qsmds-arco/src/components/base/DateTimeDisplay/format.ts` |
| Showcase | `web/apps/qsmds-arco/src/views/component_library/basic/components/DateTimeDisplayShowcase.vue` |
| 路由 | `/component-library/basic/date-time-display` |
| 测试 | `web/apps/qsmds-arco/test/views/date-time-display.test.ts` |

## 2. 快速使用

组件必须显式导入：

```vue
<script setup lang="ts">
import DateTimeDisplay from '@/components/base/DateTimeDisplay/index.vue'

const occurredAt = '2026-07-20T08:16:35.000Z'
</script>

<template>
  <DateTimeDisplay :value="occurredAt" />
  <DateTimeDisplay
    :value="occurredAt"
    format="date"
    time-zone="America/New_York"
  />
</template>
```

默认使用 `Asia/Shanghai` 和 `datetime`，上述第一个组件输出：

```text
2026-07-20 16:16:35
```

## 3. Props

| Prop | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `value` | `Date \| number \| string \| null \| undefined` | 是 | 无 | 待显示时刻；空值或非法值显示 `—` |
| `format` | `'date' \| 'datetime' \| 'time'` | 否 | `'datetime'` | 控制固定输出结构 |
| `timeZone` | `string` | 否 | `'Asia/Shanghai'` | 传给 `Intl.DateTimeFormat` 的 IANA 时区标识 |

`value` 是必填 Prop，但类型允许调用方显式传入 `undefined`，用于把缺失字段统一显示为 `—`。

组件没有 Slots、Events、`v-model`、`locale`、`emptyText` 或自定义格式模板。

## 4. 输出格式

常规现代业务年份 `1000–9999` 的输出结构如下：

| `format` | 输出结构 | 示例 |
| --- | --- | --- |
| `date` | `YYYY-MM-DD` | `2026-07-20` |
| `datetime` | `YYYY-MM-DD HH:mm:ss` | `2026-07-20 16:16:35` |
| `time` | `HH:mm:ss` | `16:16:35` |

实现固定使用：

```text
en-CA-u-ca-gregory-nu-latn
```

并通过 `Intl.DateTimeFormat.formatToParts()` 重新组合结果，所以常规业务年份使用公历、拉丁数字、两位月日与时分秒和 24 小时制，不受浏览器默认 locale 影响。

当前实现直接使用 `Intl` 返回的 `numeric` 年份，不补足四位，也没有输出 era。解析器仍会接收 `0000–0999` 的四位年份字符串，因此这一区间可能输出 `1-01-01`、`99-12-31` 等非 `YYYY` 结构，`0000` 还会丢失 BCE era。历史年份不属于当前适用范围；若业务出现该需求，应先扩展并测试年份与 era 契约。

## 5. 输入解析边界

字符串只接受带显式时区的 ISO 8601 日期时间子集：

```text
YYYY-MM-DDTHH:mm[:ss[.1-9 位小数]]Z
YYYY-MM-DDTHH:mm[:ss[.1-9 位小数]]±HH:mm
```

具体规则：

- 必须使用 `T` 分隔日期和时间。
- 必须包含大写 `Z` 或显式 `±HH:mm`。
- 校验闰年、每月天数、时、分、秒和 offset，不接受 JavaScript `Date` 的自动进位结果。
- UTC offset 最大为 `±14:00`；达到 `14` 小时时分钟必须为 `00`。
- `number` 始终表示 Unix 毫秒，不猜测 Unix 秒。
- `Date` 必须有效；组件会复制实例后再格式化。
- 小数秒只参与时刻解析；三种格式都只显示到整秒，并直接省略小数部分。
- 空 `timeZone`、非法 IANA 时区或当前运行环境不支持的时区统一显示 `—`。

以下字符串不会被接受：

```text
2026-07-20
2026-07-20 08:16:35Z
2026-07-20T08:16:35
2026-02-30T08:16:35Z
2026-07-20T24:00:00Z
```

组件不新增日期库依赖，只使用原生 `Date` 和 `Intl.DateTimeFormat`。

## 6. 公开类型与格式化函数

```ts
import type {
  DateTimeDisplayFormat,
  DateTimeDisplayValue,
} from '@/components/base/DateTimeDisplay/format'
import {
  DEFAULT_TIME_ZONE,
  EMPTY_DATE_TIME_TEXT,
  formatDateTime,
} from '@/components/base/DateTimeDisplay/format'

const occurredAt = formatDateTime(
  '2026-07-20T08:16:35.000Z',
  'datetime',
  'America/New_York',
)
// 2026-07-20 04:16:35
```

| Export | 契约 |
| --- | --- |
| `DateTimeDisplayFormat` | `'date' \| 'datetime' \| 'time'` |
| `DateTimeDisplayValue` | `Date \| number \| string \| null \| undefined` |
| `DEFAULT_TIME_ZONE` | `'Asia/Shanghai'` |
| `EMPTY_DATE_TIME_TEXT` | `'—'` |
| `formatDateTime(value, format = 'datetime', timeZone = 'Asia/Shanghai')` | 只有 `value` 必须传入；返回日期时间文本，输入无效时返回 `—` |

## 7. DOM、无障碍与排版

组件根节点为单个 `<time>`，默认类为：

```text
qs-type-data inline-flex whitespace-nowrap items-baseline
```

默认排版遵循[全局排版规范](../../../全局排版规范.md)的 `data` 角色：

| 项目 | 当前规则 |
| --- | --- |
| 字体 | `Noto Sans Mono`，中文回退 `Noto Sans SC` |
| 字号 / 行高 | `14px / 20px` |
| 字重 | `400` |
| 数字特性 | `tabular-nums` |
| 颜色 | 主题 `foreground`；浅色主题当前为 `#09090B` |
| 布局 | 行内 Flex、不换行、基线对齐 |

调用方可把普通 `class`、`style` 和原生 attribute 传到根节点，但不应覆盖组件生成的语义属性：

- 有效值的 `aria-label` 为 `${timeZone} ${formattedValue}`。
- 空值或非法值的 `aria-label` 为 `${timeZone} 时间不可用`。
- `data-empty` 标记空值或非法输入形成的占位状态。
- `data-format` 和 `data-time-zone` 记录当前格式化参数。

## 8. 时区选择原则

- API 返回的时间字符串应包含 `Z` 或明确 offset，禁止依赖浏览器本地时区解释无时区字符串。
- `timeZone` 应由业务语义决定。例如“平台统一运营时间”和“门店所在地时间”是不同产品口径，组件不会替调用方选择。
- Unix 时间戳必须明确单位为毫秒。若上游使用秒，应在数据适配层显式转换后再传入。
- 只需要处理日期而没有明确时刻的业务字段，不应伪造午夜时刻后交给本组件。

## 9. 适用与不适用场景

适合：

- 表格、详情、卡片中的创建时间、更新时间和业务发生时刻。
- 需要在多个 IANA 时区稳定展示同一时刻的场景。
- 需要稳定日期、日期时间或时间输出结构的现代业务年份只读场景。

不适合：

- 日期时间输入、日历选择或时区选择。
- 相对时间、持续时长、自然语言日期或任意自定义模板。
- 不带时区且业务语义不明确的字符串。
- 需要正确显示 `0000–0999` 年份或 BCE era 的历史日期。
