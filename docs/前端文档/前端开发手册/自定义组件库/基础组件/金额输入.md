# 金额输入：MoneyInput

[返回自定义组件库](../README.md)

## 1. 组件定位

`MoneyInput` 是 `web/apps/qsmds-arco` 内的精确金额输入基础组件。它以
`FaInput` 为输入内核，负责十进制字符串录入、严格格式校验、固定精度规范化和
无障碍错误状态，不读取业务 Store、不请求 API，也不决定会计科目、币种换算或
税费规则。

| 项目 | 当前值 |
| --- | --- |
| 组件源码 | `web/apps/qsmds-arco/src/components/base/MoneyInput/index.vue` |
| 校验与计算内核 | `web/apps/qsmds-arco/src/components/base/MoneyInput/logic.ts` |
| 组件目录说明 | `web/apps/qsmds-arco/src/components/base/MoneyInput/README.md` |
| Showcase | `web/apps/qsmds-arco/src/views/component_library/basic/components/MoneyInputShowcase.vue` |
| 路由 | `/component-library/basic/money-input` |
| 测试 | `web/apps/qsmds-arco/test/views/money-input.test.ts` |

组件属于应用内可复用基础组件，尚未从 `web/packages/*` 导出，也没有注册为全局
组件。调用方必须显式导入。

## 2. 数据存储协议

数据库、API 和前端表单使用以下边界：

```text
Database DECIMAL / NUMERIC
        ↓
API JSON string，例如 "1234.50"
        ↓
MoneyInput string | null
        ↓
AmountDisplay / sumMoneyValues

币种字段 currency: "CNY"
        ↓
MoneyInput v-model:currency
        ↓
AmountDisplay currency
```

固定规则：

- 数据库使用业务确认精度的 `DECIMAL/NUMERIC`。
- API 金额字段使用 JSON string，不使用 JSON number。
- 前端持久化金额类型为 `string | null`。
- 币种使用独立字段或业务上下文，例如 `currency: "CNY"`。
- 金额字段不存储 `¥`、`CNY`、千分位或本地化展示文本；币种代码只保存到
  独立 `currency` 字段。
- 空值使用 `null`，不能用空字符串代替，也不能把空值自动改为零。

数据库使用 `DECIMAL` 不代表前端必须把所有金额包装为 `Decimal` 实例。组件、表单
与 API 继续传递字符串；只有比较、规范化、求和等计算边界临时使用 `decimal.js`。

## 3. 快速使用

```vue
<script setup lang="ts">
import type { CurrencyCode } from '@/components/base/AmountDisplay/format'
import AmountDisplay from '@/components/base/AmountDisplay/index.vue'
import MoneyInput from '@/components/base/MoneyInput/index.vue'

const amount = ref<string | null>(null)
const currency = ref<CurrencyCode>('CNY')
</script>

<template>
  <MoneyInput
    v-model="amount"
    v-model:currency="currency"
    min="0.00"
    max="9999999999999999.99"
  />
  <AmountDisplay :value="amount" :currency="currency" />
</template>
```

输入 `1234.5` 并失焦后，`amount` 规范化为：

```text
1234.50
```

金额展示组件输出：

```text
¥1,234.50 CNY
```

未传入币种模型时，金额输入默认使用 `CNY`。需要保存用户选择时，应始终初始化并
绑定独立的 `currency` ref；切换币种只改变该字段，不会换算金额。

## 4. Props

| Prop | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `modelValue` | `string \| null` | 否 | `null` | 无分组符和币种符号的金额文本 |
| `currency` | `'CNY' \| 'TWD' \| 'MYR' \| 'USD'` | 否 | `CNY` | 通过 `v-model:currency` 双向绑定的独立币种 |
| `precision` | `number` | 否 | `2` | 小数位，必须是 `0..100` 的整数 |
| `allowNegative` | `boolean` | 否 | `false` | 是否允许负数 |
| `min` | `string` | 否 | 无 | 精确最小值 |
| `max` | `string` | 否 | 无 | 精确最大值 |
| `clearable` | `boolean` | 否 | `true` | 是否允许清空为 `null` |
| `disabled` | `boolean` | 否 | `false` | 禁用输入 |
| `readonly` | `boolean` | 否 | `false` | 只读输入；同时移除清空按钮 |
| `placeholder` | `string` | 否 | 根据 `precision` 生成 | 输入占位文本 |
| `inputClass` | `HTMLAttributes['class']` | 否 | 无 | 追加到底层输入节点的类 |

组件继续向 `FaInput` 转发原生 `name`、`autocomplete`、`aria-*`、`input` 和
`change` 等属性或事件。这些内容只落到真实 `<input>`，不会复制到输入组外层，
可以作为 `FaFormItem` 的第一个控件使用。

右侧币种下拉从 `CURRENCY_SYMBOLS` 派生 `CNY/TWD/MYR/USD` 四个选项；左侧货币
符号、`data-currency` 与配套 `AmountDisplay` 均应消费同一个币种模型。
`disabled` 或 `readonly` 时下拉不可切换。

## 5. 严格金额字符串

合法持久化金额示例：

```text
0
0.50
1234.50
-12.30
```

以下内容不是合法持久化金额：

```text
""
.50
123.
01.20
1,234.50
¥12.00
+12
1e3
" 12.00 "
```

输入过程可能暂时产生不完整草稿。调用方不能仅凭字段非空就提交，必须在业务提交
前调用 `validateMoneyString` 或配置等价的 `FaForm` 校验规则。失焦时，合法值会
按 `precision` 补齐；非法值原样保留以便用户修正，并通过无障碍状态和
`validation` 事件报告错误。`readonly` 状态只校验并发出 `blur`，不会补零或写回
`v-model`。

币种切换不会触发金额换算，也不会改写当前金额字符串。例如
`{ amount: "1234.50", currency: "CNY" }` 切换后成为
`{ amount: "1234.50", currency: "USD" }`。真实换汇必须由业务层使用明确汇率
完成，基础组件不会猜测汇率。

## 6. 校验结果与错误码

```ts
import { validateMoneyString } from '@/components/base/MoneyInput/logic'

const result = validateMoneyString(amount.value, {
  allowNegative: false,
  min: '0.00',
  max: '9999999999999999.99',
  precision: 2,
})
```

成功结果：

```ts
{
  valid: true,
  normalizedValue: '1234.50',
}
```

失败结果包含中文消息与稳定英文错误码：

| 错误码 | 含义 |
| --- | --- |
| `INVALID_FORMAT` | 包含非法语法、空白、展示符号或非规范结构 |
| `PRECISION_EXCEEDED` | 小数位超过 `precision` |
| `NEGATIVE_NOT_ALLOWED` | 当前字段不允许负数 |
| `BELOW_MIN` | 小于精确下限 |
| `ABOVE_MAX` | 大于精确上限 |

校验顺序固定为：

```text
严格字符串语法
→ 小数位
→ 负数策略
→ Decimal 精确上下限
→ 固定精度规范化
```

`decimal.js` 不是字符串语法校验器。组件不会直接把 `1e3`、`+12` 或带空白文本
交给 `Decimal` 后视为合法金额。

## 7. Events 与公开方法

| Event | 参数 | 说明 |
| --- | --- | --- |
| `update:modelValue` | `string \| null` | 输入或失焦规范化后更新表单值 |
| `update:currency` | `CurrencyCode` | 右侧下拉选择币种后更新独立币种字段 |
| `validation` | `MoneyValidationResult` | 失焦、显式校验或已触碰后的继续输入触发 |
| `blur` | `Event` | 完成规范化与校验后触发 |

组件公开：

| 方法 | 返回值 | 说明 |
| --- | --- | --- |
| `validate()` | `MoneyValidationResult` | 标记已触碰并返回当前严格校验结果 |
| `resetValidation()` | `void` | 清除组件内部已触碰状态 |

业务提交仍应以业务表单的完整校验结果为准；组件公开方法不替代服务端金额校验。

## 8. 精确列汇总

金额求和必须使用 `sumMoneyValues`：

```ts
import { sumMoneyValues } from '@/components/base/MoneyInput/logic'

const total = sumMoneyValues(
  ['0.10', '0.20', '9007199254740993.21'],
  { precision: 2 },
)
// "9007199254740993.51"
```

行为边界：

- `null` 不参与计算。
- 空数组返回当前精度的零，例如 `0.00`。
- 所有非空项先执行严格金额校验。
- 非法金额抛出 `MoneyValidationError`，不能静默跳过或按零处理。
- 计算精度按最大整数位、`precision` 和行数可能产生的进位动态扩展，不使用
  `decimal.js` 默认的 20 位有效数字。
- 每次汇总使用隔离的 `Decimal.clone` 构造器，不修改全局 Decimal 配置。
- 汇总结果仍是字符串，不暴露 `Decimal` 实例。
- `sumMoneyValues` 不执行币种识别或汇率换算；调用前必须保证所有金额属于同一币种。
- 不同币种必须拒绝汇总、按币种分组，或在业务层完成明确换算，不能直接相加。

`QsGenericTable` 的内置 `sum/average` 是通用数值汇总，目前仍使用 JavaScript
`number`，不能承担精确金额计算。金额列应先在业务调用方计算，再通过已有
`summaryValues` 注入：

```vue
<script setup lang="ts">
import { sumMoneyValues } from '@/components/base/MoneyInput/logic'

const summaryValues = computed(() => ({
  amount: sumMoneyValues(
    pageRows.value.map(row => row.amount),
    { precision: 2 },
  ),
}))
</script>

<template>
  <QsGenericTable
    :columns="columns"
    :data="pageRows"
    :summary-values="summaryValues"
  />
</template>
```

汇总列可以继续使用 `AmountDisplay` 作为 `summary.component`，或者通过
`summary-{columnId}` 插槽显示。

`AmountDisplay` 当前按货币展示规则固定保留两位小数。因此直接组成
`MoneyInput → AmountDisplay` 时使用默认 `precision=2`；若业务金额不是两位小数，
`MoneyInput` 与 `sumMoneyValues` 仍可按指定精度工作，但必须选择相同精度契约的
展示方式，不能依赖 `AmountDisplay` 保留额外小数位。

## 9. 无障碍与排版

- 底层使用 `type="text"` 和 `inputmode="decimal"`，不使用会转换为
  JavaScript `number` 的数字输入组件。
- 币种符号位于开头，币种代码位于末尾。
- 币种代码通过右侧 `FaSelect` 选择，默认 `CNY`，支持完整键盘操作。
- 金额输入使用全局 `Noto Sans Mono`、`tabular-nums` 和右对齐。
- 控件尺寸、焦点、禁用和错误边框继续由 `FaInput` 与主题 token 管理。
- 失焦后的非法值设置 `aria-invalid=true` 和 `data-validation-code`。
- `aria-describedby` 可由 `FaFormItem` 或业务调用方关联帮助与错误文本。
