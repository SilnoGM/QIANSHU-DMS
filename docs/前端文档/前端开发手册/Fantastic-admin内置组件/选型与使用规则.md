# Fantastic-admin 内置组件选型与使用规则

本规则用于决定正式应用中一个界面能力应落到 Fantastic-admin、Arco Design Vue 参考实现、应用领域组件还是 Web 共享包。组件名字相似不代表契约相同；选型必须先看职责，再看本地源码和真实调用方。

## 1. 总原则

- Fantastic-admin 内置组件是框架壳和标准业务 UI 的第一优先级；先核对本地公开导出与真实 API，只有无法满足已确认契约时才考虑扩展或回退。
- Arco Design Vue 已从正式应用移除，只保留在 `web/examples/core-arco-design-vue` 参考应用中，因此不是正式应用可直接使用的第二级回退。确需在正式应用使用，必须先完成依赖与 provider 接入评审，不能直接引用示例源码。
- Fantastic-admin Pro `6.3.0` 已在当前仓库中，基础版和专业版公开能力都必须进入首轮选型。
- 同一语义层保留一套组件契约。优先组合 `FaPageMain`、`FaForm`、`FaTable` 等真实 Fa 能力；确需引入 Arco 时，对应表单、表格或操作区应整体迁移，不混写状态与事件契约。
- 可用性以 `web/packages/components/src/index.ts` 为准，API 以本地源码/类型为准；官网示例不能越过本地公开边界。

## 2. 组件职责矩阵

| 优先级 | 实现落点 | 进入条件 |
| --- | --- | --- |
| 1 | Fantastic-admin 内置组件 | 本地公开能力能满足已确认的功能、交互、无障碍和性能契约 |
| 2 | Arco Design Vue 组件 | 已核对 Fantastic-admin 真实 API 并确认其无法满足需求 |
| 3 | 基于 Arco Design Vue 的应用级自定义组件 | Arco 单个组件不足，且需要在正式应用内组合领域语义与交互 |
| 4 | 基于原生 Vue 的自定义组件 | 前三级均无法满足需求，并已记录不适用原因 |

| 需求职责 | 默认落点 | 采用条件 | 不应采用 |
| --- | --- | --- | --- |
| 框架壳、导航、页面容器、框架内部交互 | Fantastic-admin 内置组件 | 能力直接服务布局壳、顶栏/侧栏适配、页面容器或框架全局交互 | 为普通业务表单或列表仅追求不同外观而使用 `Fa*` |
| 标准业务交互：表单、数据录入、数据展示、反馈、企业后台交互 | Fantastic-admin 内置组件 | 本地 Fa 公开能力满足已确认契约；不足时再按上表逐级回退 | 未核对 Fa API 就直接把 Arco 或原生 Vue 作为默认实现 |
| 专业版特有视觉、动画、日期和框架封装 | Fantastic-admin Pro | 本地专业版公开导出存在，效果或封装是需求本身，且已核对响应式与无障碍 | 未验证窄屏、减少动态或可访问性就用展示效果承载关键业务交互 |
| 领域组件 | `web/apps/qsmds-arco/src/components/` | 包含千树 DMS 业务语义、业务字段、流程组合或仅由正式应用消费 | 过早放入共享包，或让参考应用承担正式业务实现 |
| 跨应用基础能力 | `web/packages/*` | 至少两个真实调用方、接口稳定、无业务语义，并通过依赖边界评审 | 为“以后可能复用”预建抽象 |

这里的“标准业务交互”以用户完成业务任务为中心；“框架内部交互”以维持框架布局、导航和全局容器行为为中心。组件位于 `basic/` 或 `pro/` 只表示源码导航，不改变上述职责判断。

## 3. 领域组件与共享边界

具有业务语义的组合优先放在 `web/apps/qsmds-arco/src/components/`。例如一个组件如果知道千树 DMS 的单据状态、业务字段、审批动作或权限文案，它就是领域组件，而不是通用 UI 基础设施。

只有同时满足以下条件，才评估迁入 `web/packages/*`：

1. 已有至少两个真实、独立的调用方，而非计划中的调用方。
2. Props、Events、Slots 或函数接口已在实际使用中稳定。
3. 名称、字段和行为不携带业务语义，也不依赖正式应用的路由、Store 或 API。
4. 提取后不会产生反向依赖、跨目录源码引用或额外的应用构建假设。
5. 迁移收益明确大于新增维护成本。

遵循 YAGNI：没有真实复用证据就留在正式应用，出现第二个调用方后再从实际差异中提炼最小接口，不为假想未来设计兼容层。

## 4. 与 Arco 重叠能力的选择

| 能力 | Fantastic-admin 对应能力 | Arco 对应能力 | 项目决策 |
| --- | --- | --- | --- |
| Button | `FaButton`、`FaButtonGroup` | `AButton`、`AButtonGroup` | 标准业务操作优先 Fantastic-admin；`FaButton` 无法满足已确认交互时才回退 Arco，单一操作区不混用组件族。 |
| Card | `FaCard` | `ACard`、`ACardMeta`、`ACardGrid` | 标准业务内容卡片优先 Fantastic-admin；`FaCard` 缺少已确认结构能力时才回退 Arco，不为局部外观混用组件族。 |
| Form | `FaForm`、`FaFormItem` | `AForm`、`AFormItem` | 标准业务表单优先 Fantastic-admin；无法满足校验或字段契约时才回退 Arco，并完整迁移校验、提交、disabled 与 slot 语义。 |
| Input | `FaInput`、`FaTextarea` | `AInput`、`ATextarea` | 业务录入优先 Fantastic-admin；Fa 输入能力无法满足已确认交互时才回退 Arco，同一表单只保留一套值、错误、焦点和尺寸契约。 |
| Select | `FaSelect`、`FaCombobox`、`FaCascader`、`FaCheckboxGroup`、`FaRadioGroup` | `ASelect`、`ACascader`、`ATreeSelect`、`ACheckboxGroup`、`ARadioGroup` | 业务选择优先 Fantastic-admin；搜索单选先核对 `FaCombobox`，层级单选先核对 `FaCascader`；Fa 选择能力仍无法满足多选、树选择或大数据契约时才按需求回退 Arco。 |
| Table | `FaTable`、`FaDescriptions` | `ATable`、`ADescriptions` | 标准业务数据展示优先 Fantastic-admin；`FaTable` 无法满足已确认表格能力时才回退 Arco，TanStack columns 与 Arco 声明式列契约不得混写。 |
| Pagination | `FaPagination` | `APagination` | 业务列表优先 Fantastic-admin；`FaPagination` 无法满足已确认分页能力时才回退 Arco，并与查询的 page、pageSize、total 保持单一受控状态。 |
| Modal/Drawer | `FaModal`、`FaDrawer`、`useFaModal`、`useFaDrawer` | `AModal`、`ADrawer`、`$modal`、`$drawer` | 业务编辑与确认优先 Fantastic-admin；Fa 浮层无法满足已确认交互时才回退 Arco，并统一异步关闭、错误反馈和焦点恢复。 |
| Toast/Message | `FaToast`、`useFaToast` | `Message`、`Notification`、`$message`、`$notification` | 业务反馈优先 Fantastic-admin；Fa 反馈无法满足已确认上下文或交互时才回退 Arco，静态方法与实例注入的 context 不跨层冒充。 |
| Tooltip/Popover | `FaTooltip`、`FaPopover` | `ATooltip`、`APopover`、`ATrigger` | 业务说明浮层优先 Fantastic-admin；Fa 浮层无法满足触发、碰撞或内容契约时才回退 Arco，并验证键盘与触屏。 |
| Tabs | `FaTabs` | `ATabs` | 业务内容切换优先 Fantastic-admin；`FaTabs` 无法满足已确认切换契约时才回退 Arco，二者都不能替代 Fantastic-admin 的路由 Tabbar。 |
| Tag/Badge | `FaTag`、`FaBadge` | `ATag`、`ABadge` | 业务状态与计数优先 Fantastic-admin；Fa 变体无法满足已确认语义时才回退 Arco，颜色之外必须保留文字、数值或可读状态。 |
| Upload | `FaFileUpload`、`FaImageUpload` | `AUpload` | 标准业务上传优先 Fantastic-admin；Fa request 或进度契约无法满足需求时才回退 Arco，二者都必须接入受控 HTTP client。 |
| ImagePreview | `FaImagePreview`、`useFaImagePreview` | `AImage`、`AImagePreview`、`AImagePreviewGroup` | 标准业务图片预览优先 Fantastic-admin；需要 `alt` 等 Fa 未提供的契约时才回退 Arco 或原生语义元素，不伪造不存在的 prop。 |
| Tree | 专业版 `FaTree` | `ATree`、`ATreeSelect` | 标准业务树优先 Fantastic-admin；`FaTree` 无法满足选择、搜索或无障碍契约时才回退 Arco，并按真实层级数据建模。 |
| Steps | 专业版 `FaSteps` | `ASteps` | 标准业务流程优先 Fantastic-admin；`FaSteps` 无法满足交互或无障碍契约时才回退 Arco，不能把只读展示冒充可操作步骤。 |
| PageHeader | `FaPageHeader`、`FaPageMain` | `APageHeader` | 框架页面标题默认 Fantastic-admin，使用 `FaPageHeader` 与 `FaPageMain` 维持壳层布局；业务区域内部需要 Arco 返回/面包屑语义时才局部使用 `APageHeader`。 |

同页组合的正确粒度是“框架容器 + 一套业务控件”。默认优先组合 `FaPageHeader`、`FaPageMain`、`FaForm`、`FaTable` 和相应 Fa 操作控件；回退 Arco 时以完整语义区域为单位迁移。同一表单中混用 `FaInput` 与 `AInput`，或同一操作区混用 `FaButton` 和 `AButton`，会带来焦点、禁用、校验、尺寸和主题语义不一致，默认禁止。

## 5. 决策流程

1. **确认契约**：明确功能、交互、响应式、无障碍和性能要求，不用个人习惯代替需求。
2. **先查 Fantastic-admin**：从 `web/packages/components/src/index.ts` 及对应本地源码、类型与 README 确认真实能力。
3. **无法满足才查 Arco**：记录 Fa 不满足的具体契约，再在固定版本 Arco 中选择回退能力。
4. **仍不足才组合**：先在 `web/apps/qsmds-arco/src/components/` 基于 Arco 组合应用级组件，不提前下沉共享包。
5. **原生 Vue 最后**：前三级均不满足时，才实现基于原生 Vue 的自定义组件。
6. **最后评估共享**：满足两个真实调用方、接口稳定、无业务语义后，才讨论 `web/packages/*`。
7. **验证组合一致性**：检查当前主题 token、焦点、键盘、窄屏、错误态、加载态和同类控件是否只保留一套。

只有能具体指出 `Fa*` 缺失的已确认契约，才能进入 Arco 回退；无法证明共享收益时，选择应用内实现。

## 6. 自动导入与显式导入

正式应用的 `web/apps/qsmds-arco/vite/plugins.ts` 已配置两条不同链路：

- `FantasticAdminComponentsResolver()` 供 `unplugin-vue-components` 解析 Vue template 中的 `Fa*` 组件，并生成 `src/types/components.d.ts`。
- `FantasticAdminComponentsAutoImports` 供 `unplugin-auto-import` 引入 `useFaDrawer`、`useFaImagePreview`、`useFaModal`、`useFaToast` 等 composable，并生成 `src/types/auto-imports.d.ts`。

在 `web/apps/qsmds-arco/src/**/*.vue` 中使用已生成声明覆盖的组件和 composable 时可以依赖自动导入。以下场景必须显式导入：

- `import type`：例如从 `@fantastic-admin/components` 导入 `FormExpose`、`TableColumn` 或上传 request option type。
- `web/packages/*` 中的共享源码；共享包不能依赖某个应用的 Vite transform。
- Node 脚本、测试、Vite 配置、构建插件以及不会经过正式应用 transform 的文件。
- 需要向审阅者明确运行时依赖来源，或存在同名符号歧义的 TypeScript 模块。

不要手改生成的 `components.d.ts` 或 `auto-imports.d.ts` 来“增加能力”；应先确认根公开导出和 resolver，再由构建工具重新生成。

## 7. FaForm 与 AForm 不是名称替换

`FaForm`/`FaFormItem` 基于 `vee-validate`，是标准业务表单的第一优先级；`AForm`/`AFormItem` 使用 Arco 自己的表单契约。只有 Fantastic-admin 无法满足表单契约时才使用 Arco，回退时不得只替换组件名：

| 语义 | Fantastic-admin | Arco |
| --- | --- | --- |
| 整体校验 | `validation-schema`，支持 typed/Yup schema 与 vee-validate rule | `rules` 或 `AFormItem` 字段级 `rules`；自定义规则写 `validator` |
| 字段身份 | `FaFormItem name="account"` | `AFormItem field="account"` |
| 值绑定 | `model`/`initialValues`，默认插槽首控件可由 `componentField` 自动注入 | `:model="model"`，控件显式 `v-model="model.account"` |
| 命令式调用 | `FormExpose.submit()`、`validate()`、`resetFields()` 等 | form ref 的 `validate()`；校验通过返回 `undefined` 后再调用业务逻辑 |
| 原生提交 | `@submit`、`@invalid-submit` | `html-type="submit"` 配合 `@submit-success`、`@submit-failed`；通用 `@submit` 不是仅成功事件 |
| 插槽 | `componentField` 及 `label`、`description`、`message` | 按 Arco 的 `default`、`label`、`help`、`extra` 重写，不沿用 Fa slot props |

回退迁移时还要重写 disabled 传播、错误展示、焦点/滚动到错误字段和提交失败传播。不要把 vee-validate schema 直接传给 Arco，也不要假设 `rules`、`validate()`、`model`、`field` 或 slots 在两套组件间同名同义。

## 8. API 与源码查找路径

按以下顺序定位一个内置组件：

1. 在 `web/packages/components/src/index.ts` 的基础版或专业版区段确认公开名。
2. 在 `web/packages/components/src/basic/<component>/index.ts` 确认组件、composable 和 type 的目录出口。
3. 阅读同目录 `README.md`，再用 `*.vue`、`use*.ts`、`types` 校正 Props、Events、Slots、Expose 和默认值。
4. 在 `web/packages/components/resolver.ts` 核对运行时名称是否参与自动导入。
5. 在 `web/apps/qsmds-arco/src/types/*.d.ts` 核对正式应用当前生成声明；生成文件不是手工修改点。
6. 最后查[Fantastic-admin 组件官网](https://fantastic-admin.hurui.me/components/)的具体组件页理解上游示例。官网与本地不一致时记录差异，并以本地源码/类型为准。

## 9. 样式、无障碍与响应式

- 页面样式优先使用当前主题 token；真相源是 `web/packages/themes/index.ts` 与 `web/uno.config.ts`，不在业务页面另建配色体系。
- 优先使用 `bg-background`、`text-foreground`、`text-muted-foreground`、`border-border` 等语义类；组件或原子类确实无法表达时，再直接引用 `oklch(var(--...))` 形式的当前 token。
- 不得默认硬编码颜色；只有颜色本身是已确认业务数据或外部品牌契约时才例外，并必须同时验证亮色与暗色主题下的对比度和状态可读性。
- 只有源码真实声明并通过 `cn()` 合并的 `class`、`contentClass`、`headerClass`、`itemClass` 等入口，才可用 UnoCSS 原子类覆盖；不要向未声明的 prop 传样式字符串。
- 不能通过深层 DOM selector 绑定 Reka UI 或 shadcn-vue 的内部结构。
- 表单控件必须有可感知 label，图标按钮必须提供可访问名称；状态不能只靠颜色。弹层必须验证键盘关闭、焦点回收、遮罩关闭策略和危险操作确认。
- `FaImagePreview` 当前本地 props 没有 `alt`。需要业务图片替代文本时，使用能满足无障碍契约的 Arco Image 或原生 `img`，不要伪造不存在的 prop。
- `FaPageHeader` 等框架容器需要在窄屏验证换行；固定栏要验证内容不被遮挡。业务表格在窄屏应按信息层级改为紧凑卡片、抽屉或响应式布局，不把横向滚动当作唯一方案。
- Modal、Drawer、Popover、Dropdown 和 Tooltip 需要在小视口验证碰撞、最大尺寸、滚动区与触控目标；不要复制仅适合桌面的固定宽度。

## 10. 安全规则

- 示例只使用静态中文数据和明显占位符，例如 `https://api.example.invalid/upload`；不得写入真实 token、密码、Cookie、连接字符串或 `.env` 内容。
- 上传组件的 `httpRequest` 必须接入项目受控 HTTP client；鉴权由统一拦截器处理，不把 token 硬编码进 `headers`。客户端的 `beforeUpload` 不能替代服务端文件类型、大小、内容和权限校验。
- 外部图片、图标和下载地址必须来自受信来源并经过服务端授权；不要把用户输入直接拼成可执行 URL 或 HTML。
- Modal、Drawer、Toast、菜单项 handler 和 slot 不得吞掉业务失败；异步错误必须进入项目统一错误链路，并保证 loading 状态最终释放。
- 不伪造业务 API、路由、权限、字段或返回结构。领域示例需要真实契约时，先查正式应用源码和 OpenAPI types。
