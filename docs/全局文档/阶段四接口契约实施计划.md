# 阶段四接口契约 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不新增业务 API、不修改 Prisma schema 的前提下，建立 Server Request ID、`ApiError`、OpenAPI 离线快照、根级契约同步/检查、Web types-only 生成与单一 Axios 运行时契约。

**Architecture:** NestJS Controller、DTO 与 OpenAPI decorators 是 HTTP 契约定义真相源，Server 使用 preview mode 离线生成可提交快照；无第三方依赖的根脚本以临时目录校验、同步 Server/Web 双快照并调用 Web 稳定生成入口。Web 仅使用 `@hey-api/openapi-ts` 的 TypeScript plugin 生成类型，所有请求继续复用唯一 Axios Client，成功返回完整 `AxiosResponse<T>`，错误、Blob、取消和重试由可注入的纯函数与 Client factory 统一约束。

**Tech Stack:** Node.js 24、pnpm 11.9、NestJS 11.1、`@nestjs/swagger` 11.4.5、Prisma 7.8、PostgreSQL 16、OpenAPI 3.0.3、TypeScript 5.9/6.0、Jest 29、`node:test`、Vue 3、Axios 1.18、`@hey-api/openapi-ts` 0.99.0。

## 执行边界

- 设计真相源是 `docs/全局文档/阶段四接口契约设计.md`；实施中不得用本计划的代码片段反向改写已确认需求。
- 根目录不是 pnpm workspace，不新增根 `pnpm-workspace.yaml`、`pnpm-lock.yaml`、`node_modules/`或任何依赖字段。
- `server/` 与 `web/` 继续使用各自 manifest 和 lockfile；禁止 `file:`、`link:`、跨目录 `workspace:*` 和跨端源码 import。
- 本阶段只有契约基础设施；不新增 User/Auth/Role 等业务 API，不修改 `server/prisma/schema.prisma` 或 `server/prisma/migrations/`。
- 正式 Server 路由始终只有 `GET /api/health`；响应矩阵 Controller 只能存在 `server/test/fixtures/`，不得被 `AppModule`、`HTTP_MODULES` 或 `OpenApiModule` 引用。
- health 的 `200/503` body 保持 Terminus 原样，仅增加 `X-Request-Id`；其他应用级 JSON 错误使用 `ApiError`。
- Request ID 始终由 Server 使用 `crypto.randomUUID()` 生成，忽略客户端传入值。
- Web 生成目录 ignored 且不提交；`server/openapi/openapi.json` 和 `web/openapi/openapi.json` 必须提交且字节一致。
- `web/examples/*` 只做参考应用，不修改其源码、manifest 或运行时行为。
- 不提交 `.env`、密钥、连接串、生成类型、`dist/`、日志或测试数据库信息；不 push。
- 同一 checkout 中所有包含 `prisma generate` 的 Server 命令串行执行。

- [x] **Step 3：实现公共错误模型和纯映射**

```ts
export type ApiFieldErrors = Record<string, string[]>

export class ApiError {
  code!: string
  message!: string
  fieldErrors?: ApiFieldErrors
  requestId!: string
}

export class ApiException extends HttpException {
  constructor(
    status: number,
    readonly code: string,
    readonly publicMessage: string,
    readonly fieldErrors?: ApiFieldErrors,
  ) {
    super(publicMessage, status)
  }
}

export function mapExceptionToApiError(
  exception: unknown,
  requestId: string,
): { status: number; body: ApiError; unexpected: boolean }

export function flattenValidationErrors(
  errors: readonly ValidationError[],
): ApiFieldErrors

export function createValidationException(
  errors: ValidationError[],
): ApiException

export interface HealthFailureRequest {
  method?: string
  path?: string
  originalUrl?: string
  url?: string
}

export function isTerminusHealthFailureExemption(
  request: HealthFailureRequest,
  status: number,
  body: unknown,
): boolean
```

`mapExceptionToApiError()` 先保留 `ApiException` 的公开 `code/message/fieldErrors`，再按上述 status table 映射标准 `HttpException`，其他异常统一为 `500/INTERNAL_ERROR`；只有最后一支返回 `unexpected: true`，不读取原始 message。`flattenValidationErrors()` 递归 children，使用点路径，合并并去重 message；只保留 decorator 中已提供的中文，`whitelistValidation`、`isString`、`isNotEmpty` 使用固定中文，其他英文/未知文本统一为“字段校验失败”。`createValidationException()` 固定返回 `422/VALIDATION_FAILED/请求参数校验失败`。health guard 必须同时命中 `GET`、规范化路径 `/api/health`、`503` 与 Terminus failure shape，其他情况均返回 `false`。

- [x] **Step 6：实现 Filter 并完成全局装配**

`ApiExceptionFilter` 稳定签名为：

```ts
@Catch()
export class ApiExceptionFilter implements ExceptionFilter {
  constructor(
    private readonly logger: Pick<Logger, 'error'> =
      new Logger(ApiExceptionFilter.name),
  ) {}

  catch(exception: unknown, host: ArgumentsHost): void
}
```

同时将 Task 1 的最小 `ApplicationSetupTarget` 精确扩展为可注册 Filter，避免把 `INestApplication` 扩散到纯装配测试：

```ts
interface ApplicationSetupTarget {
  use(...handlers: unknown[]): unknown
  setGlobalPrefix(prefix: string): unknown
  useGlobalPipes(...pipes: PipeTransform[]): unknown
  useGlobalFilters(...filters: ExceptionFilter[]): unknown
  enableShutdownHooks(): unknown
}
```

`catch()` 严格按“health 豁免 -> `ApiException` -> 标准 `HttpException` -> 未知异常”处理；日志仅包含固定文本和 Request ID，不传入 exception、stack、headers 或 body。`configureApplication()` 使用：

```ts
application.use(requestIdMiddleware)
application.setGlobalPrefix(API_PREFIX)
application.useGlobalPipes(
  new ValidationPipe({
    whitelist: true,
    forbidNonWhitelisted: true,
    transform: true,
    errorHttpStatusCode: HttpStatus.UNPROCESSABLE_ENTITY,
    exceptionFactory: createValidationException,
  }),
)
application.useGlobalFilters(new ApiExceptionFilter())
application.enableShutdownHooks()
```

- [x] **Step 6：实现可注入时钟/等待的重试纯规则**

```ts
import {
  CanceledError,
  type AxiosError,
  type AxiosRequestConfig,
  type GenericAbortSignal,
} from 'axios'

export type Sleep = (
  delayMs: number,
  signal?: GenericAbortSignal,
) => Promise<void>
export type Now = () => number

const RETRY_DELAYS_MS = [500, 1000, 2000] as const

export function fallbackRetryDelayMs(retryIndex: number): number {
  const boundedIndex = Math.min(
    Math.max(Math.trunc(retryIndex), 0),
    RETRY_DELAYS_MS.length - 1,
  )
  return RETRY_DELAYS_MS[boundedIndex] ?? 2000
}

export function abortableSleep(
  delayMs: number,
  signal?: GenericAbortSignal,
): Promise<void>

export function normalizeRetryCount(value: unknown): number {
  if (typeof value !== 'number' || !Number.isFinite(value)) {
    return 0
  }
  return Math.max(Math.trunc(value), 0)
}

export function shouldRetry(
  config: AxiosRequestConfig,
  error: AxiosError,
): boolean

export function resolveRetryDelayMs(
  error: AxiosError,
  retryIndex: number,
  now: Now,
): number
```

`normalizeRetryCount()` 的规则唯一且无隐式 coercion：有限 number 使用 `Math.trunc()` 并以 `0` 为下界，非 number、`NaN` 与正负 `Infinity` 均归为 `0`，不对大于 `3` 的整数向下 clamp。`shouldRetry()` 先要求 `config.retry === true`，再将 method 小写化并只允许 `get/head/options/put`；取消错误、已 aborted signal 与 `normalizeRetryCount(config.retryCount) >= 3` 均返回 `false`，否则仅 `error.response === undefined` 或 status 为 `502/503/504` 返回 `true`。`resolveRetryDelayMs()` 仅对 `503` 解析大小写不敏感的 `Retry-After`：合法秒数转毫秒，合法 HTTP 日期计算 `date - now()`，过去日期取 `0`，两者都用 `Math.min(value, 5000)` 限制；缺失/无效及其他可重试状态调用 `fallbackRetryDelayMs()`。
