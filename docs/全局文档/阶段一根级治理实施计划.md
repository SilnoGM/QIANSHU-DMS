# 阶段一根级治理实施计划

> **供智能代理执行：** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**目标：** 建立不参与 pnpm workspace 的根级治理层，并用 Node.js 内置测试验证无依赖编排脚本的命令顺序、失败传播和进程清理行为。

**架构：** 根目录只保存 Git 治理、中文文档和命令门面，不安装第三方依赖，也不生成根 lockfile。根 package scripts 统一通过 `node --run` 执行，避免 pnpm 11 在执行 script 前自动 install 并生成根状态；`server/` 与 `web/` 始终通过 `pnpm -C` 在各自依赖域内运行。阶段一使用依赖注入的 fake runner/fake child 完成 TDD，真实跨端集成在对应消费者完成后验证。

**技术栈：** Node.js 24、pnpm 11.9、ECMAScript Modules、`node:test`、`node:assert`、Git。

---

## 阶段边界

阶段一结束时，`server/` 仍为空，`web/` 仍没有最终 `check` 脚本，OpenAPI 检查也尚未建立。因此：

- 本阶段必须验证根脚本本身，不把 `node --run bootstrap`、`node --run dev`、`node --run check` 的真实全链路成功作为验收条件。
- `scripts/sync-openapi.mjs`、`scripts/check-openapi.mjs` 和根 `contract:*` scripts 延后到阶段四，不创建无功能空实现。
- `check.mjs` 在阶段一运行根测试、Server 检查和 Web 检查；阶段四再追加 Contract 检查。
- 不创建空的后端文档、前端文档或 `.gitkeep`。
- 配置文件和中文说明文档属于项目规则允许的简单修改，不要求人为制造失败测试；所有可执行 JavaScript 行为必须遵循 RED → GREEN → REFACTOR。

### Task 3：实现开发进程生命周期编排

**Files:**

- Create: `scripts/dev.test.mjs`

- [ ] **Step 1：先写失败测试**

使用 `EventEmitter` 构造 fake child 和 fake process，测试期望接口 `runDevelopment({ spawnImpl, processRef })`：

```js
test('同时启动 Server 与 Web 开发进程', async () => {
  const calls = []
  const harness = createHarness(calls)
  const completion = runDevelopment(harness)

  assert.deepEqual(calls.map(({ command, args }) => [command, args]), [
    ['pnpm', ['-C', 'server', 'dev']],
    ['pnpm', ['-C', 'web', 'dev']],
  ])

  harness.children.forEach(child => child.emit('exit', 0, null))
  assert.equal(await completion, 0)
})
```

补充测试必须覆盖：

- 根进程收到 `SIGINT` 时，两个运行中的子进程都收到 `SIGINT`，最终码为 `130`。
- 根进程收到 `SIGTERM` 时，最终码为 `143`。
- 第一条非零退出码获胜，另一个进程收到 `SIGTERM`。
- 子进程触发 spawn error 时按退出码 `1` 清理另一进程。
- 一个子进程正常退出时等待另一个，不把正常退出误判为失败。

- [ ] **Step 3：实现最小进程协调器**

`dev.mjs` 必须：

```js
export function runDevelopment({ spawnImpl = spawn, processRef = process } = {}) {
  // 并行 spawn 两条 pnpm -C 命令，stdio 使用 inherit。
  // 注册 SIGINT/SIGTERM，原样转发给仍在运行的子进程。
  // 首个非零 exit 或 spawn error 终止另一进程，并保留第一条失败码。
  // 两个进程都以 0 退出才 resolve 0；信号退出使用 128 + signal number。
  // finally 中移除根进程 signal listeners，避免测试和热重载泄漏。
}
```

实际入口等待 `runDevelopment()`，把结果写入 `process.exitCode`。实现不得读取、复制、打印环境变量，不硬编码端口、数据库地址或密钥。
